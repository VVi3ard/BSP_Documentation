5.35 Обмен данными (Синхронизация данных с другими Приложениями и РИБ)

Примечание для технического писателя: В зависимости от способа внедрения подсистемы в приложении может быть предусмотрена синхронизация данных с различными приложениями, а также возможность создания территориально распределенных систем с помощью механизма распределенных информационных баз (РИБ). Поэтому далее по тексту приведены примечания, к какому варианту внедрения подсистемы относится тот или иной фрагмент документации. При компоновке документации необходимо оставить только те фрагменты этой главы, которые относятся к конкретному варианту внедрения подсистемы Синхронизация данных.

Предусмотрена возможность настроить синхронизацию данных со следующими приложениями:

■ Библиотека стандартных подсистем;

■ … (в реальной документации здесь будет список реальных приложений).

В зависимости от конкретной задачи синхронизация может:

■ быть односторонней или двухсторонней с точки зрения направления синхронизации данных;

■ настраиваться для всех данных в приложении или только для определенной части данных (с определенной даты, по конкретным организациям, складам, подразделениям);

■ выполняться автоматически в фоне по заданному расписанию или вручную, при необходимости.

Для передачи данных между приложениями могут быть использованы различные каналы связи: сетевой каталог, электронная почта, FTP или Интернет (веб-сервисы). При работе в одной сети синхронизацию данных можно также настроить через прямое подключение с помощью COM-соединения.

Таким образом, с помощью регулярной синхронизации данных между приложениями можно организовать работу всех пользователей в едином информационном пространстве, как это показано на рисунке:

Например, склады крупной организации работают в приложении Управление торговлей, а бухгалтерский учет в офисах ведется в приложении Бухгалтерия предприятия.

В этом случае необходима синхронизация данных между двумя приложениями.

Для территориально удаленных подразделений крупной компании при наличии стабильных каналов связи через интернет при работе в одном приложении ничего не меняется, работа удаленных подразделений в этом приложении (например, в приложении Управление торговлей) ведется в режиме реального времени. Однако это идеальный вариант, который работает далеко не везде.

Для РИБ:

Если работа через интернет в реальном времени в удаленных подразделениях невозможна (доступ к интернету нестабилен или невозможно его обеспечить всем работникам, которые вводят данные в приложение), то в приложении имеется возможность создать территориально распределенную систему, узлы которой образуют иерархическую структуру («главный» – «подчиненный»). Такая система позволяет работать с данными в любом узле, синхронизируя их между узлами по различным каналам связи.

Главный узел, верхний в иерархии и у которого нет вышестоящего узла, называется также корневым узлом. При этом узлам территориально распределенной системы должны соответствовать структурные единицы, главный или корневой узел будет расположен в центральном офисе, подчиненные узлы будут находиться в филиалах. Например, крупное турагентство, которое со временем расширилось и создало отделения в других городах, связь с которыми не очень устойчивая, может использовать такую возможность для синхронизации данных в приложении Управление торговлей, все пользователи при этом будут работать в едином информационном пространстве, и можно будет вести единый учет. Данные мигрируют только по вертикали.

Иерархия территориально распределенной системы может быть более сложной. Например, крупный ритейлер состоит из предприятий розничной сети и оптовой торговли, те в свою очередь состоят из магазинов и оптовых складов, но необходимо вести общий учет в одном офисе. Тогда структура территориально распределенной системы будет строиться по аналогии с производственной структурой данного ритейлера.

Загрузка данных EnterpriseData

Приложение позволяет производить выгрузку и загрузку данных с использованием универсального формата EnterpriseData.

Для загрузки в приложение данных в формате EnterpriseData без необходимости настройки регулярной синхронизации данных предусмотрена ссылка Загрузка данных EnterpriseData.

Информационные базы должны поддерживать синхронизацию данных через универсальный формат EnterpriseData.

С помощью кнопки  укажите Путь к файлу загрузки на устройстве. Нажмите кнопку Выполнить операцию. После этого будет выполнена загрузка данных.

Приложение выводит сообщение о завершении загрузки данных.

Выгрузка данных производится по команде Функции для технического специалиста главного меню  или с помощью внешней обработки.

Права на использование есть у ролей Полные права и Выполнение синхронизации данных.

В поле Операция с помощью кнопок выберите, какая операция будет выполняться, например, Выгрузка.

Выберите формат EnterpriseData, в котором должны быть выгружены данные, например, 1.8.

В таблице в нижней части окна с помощью флажков определите состав выгружаемых данных.

С помощью кнопки  можно определить Период отбора всех документов и ограничить объем выгрузки.

С помощью кнопки  выполненные настройки можно сохранить в файл и использовать в следующих сеансах работы (с помощью кнопки ).

Выгрузка данных происходит в файл формата XML. Укажите файл в поле Файл выгрузки с помощью кнопки . Напишите имя файла, нажмите Сохранить. После этого путь заполнится автоматически.

При необходимости можно указать Расширение формата, выбрав его из списка с помощью кнопки . По умолчанию выбрано значение <без расширения>.

Нажмите кнопку Выполнить операцию. Через некоторое время приложение выводит сообщение об успешной выгрузке.

Для загрузки данных в этом окне нажмите кнопку Загрузка в поле Операция. Загрузка данных производится, как описано в начале раздела.

Состояния синхронизации данных могут быть, например, такими:

■ Прошлый запуск – синхронизация успешно настроена и работает, при этом указывается дата запуска синхронизации данных;

■ Не запускалась – синхронизация успешно настроена, но обмен данными еще не производился. В этом случае можно Синхронизировать данные с помощью кнопки панели навигации. Проверить и изменить настройку можно с помощью кнопки Настроить. Подробнее см. раздел Изменение настройки синхронизации данных.

■ Настройка не завершена – настройка синхронизации была прервана (например, появилась срочная работа, и настройка была прервана, или произошла некорректная настройка, в этом случае строка выделена красным). В этом случае можно продолжить настройку, нажав кнопку Настроить.

■ Настройка не завершена, получены данные для сопоставления – в таком состоянии настройка синхронизации данных между разными приложениями отражается в приложении-приемнике в случае прямого подключения (см. раздел Прямое подключение к приложению на этом устройстве или в локальной сети) и тогда необходимо продолжать настройку, подробнее см. раздел Настройка в приложении-приемнике.

■ Получены данные для сопоставления – для анализа и сопоставления полученных данных нажмите кнопку  Синхронизировать данные, задав дополнительные отборы. Подробнее см. раздел Выполнение синхронизации данных при необходимости (интерактивно).

Назначение

На примере синхронизации с Библиотекой стандартных подсистем (полная синхронизация) разбирается синхронизация данных между разными приложениями.

Одновременное использование двух приложений, например Управления торговлей и Бухгалтерии предприятия, предоставляет:

■ Повышение эффективности управления торговым предприятием;

■ Консолидацию данных управленческого и бухгалтерского учета;

■ Наличие в приложении Управление торговлей всех данных, необходимых для управления торговым предприятием;

■ Наличие в приложении Бухгалтерия предприятия КОРП всех данных, необходимых для регламентированного учета и сдачи отчетности;

■ Возможность работы сотрудников в привычной для себя среде:

■ бухгалтеры работают в приложении Бухгалтерия предприятия КОРП;

■ менеджеры по продажам работают в приложении Управление торговлей.

Выбор приложения-источника и приложения-приемника

Рассмотрим настройку синхронизации данных между двумя приложениями на примере приложения Библиотека стандартных подсистем. Необходимо провести синхронизацию данных между двумя приложениями, находящимися на одном устройстве.

При настройке синхронизации данных между двумя приложениями очень важно правильно определить приложение-источник и приложение-приемник.

Решение нужно принимать в зависимости от наполненности двух приложений данными:

1. Если в двух приложениях на момент создания синхронизации уже имеются данные, в этом случае в качестве приложения-источника лучше выбрать то приложение, в которой данные заполнены качественнее, более подробно.

■ При выборе необходимо учитывать, что если в двух приложениях часть из имеющихся данных является общей (например, списки Демо: Организации, Демо: Контрагенты и т. п.), то от того, какое приложение выбрана в качестве источника, будет зависеть и то, к какому виду будет приведена эта часть общих данных.

■ Например, если при настройке синхронизации данных между двумя приложениями Бухгалтерия предприятия и Управление торговлей в приложении Управление торговлей информация об организациях описана более полно (заполнено больше реквизитов, заполнена контактная информация и т. д.), и по остальным видам данных ситуация такая же, то целесообразнее в качестве источника данных выбрать приложение Управление торговлей и изначально производить отправку данных именно из нее. В этом случае общие данные будут приведены к состоянию приложения Управление торговлей.

■ Если не все общие данные нужно принять в том виде, в каком они содержатся в приложении-источнике, то рекомендуется воспользоваться возможностью интерактивного получения данных. Подробнее см. раздел Выполнение синхронизации данных при необходимости (интерактивно).

■ При первой синхронизации данных необходимо получить из приложения-источника только те данные, которые должны перейти в приложение-приемник в том виде, в котором они хранились в приложении-источнике. Остальные данные будут синхронизированы позже, когда произойдет перенос нужной информации из приложения-приемника в приложение-источник.

2. Если один из приложений (точнее, информационных баз) пустая или практически пустая, то выбор источника упрощается.

■ При выборе приложения-источника также следует руководствоваться рекомендациями, изложенными во встроенной справке помощника настройки синхронизации данных (по ссылке Подробное описание).

Общие рекомендации по синхронизации данных в двух приложениях

Топология синхронизации данных может быть произвольной. В связи с этим при настройке рекомендуется избегать случаев, в которых синхронизация производится по замкнутому кругу (т. е. приложение A синхронизируется с приложением B, приложение B синхронизируется с приложением C, а приложение C синхронизируется с приложением А), так как это может привести к бесконечным итерациям синхронизаций, т.е. зацикливанию. Рассмотрим пример зацикливания. Имеем 4 приложения со следующими контурами синхронизации:

Приложение А синхронизируем с приложением В;

Приложение В синхронизируем с приложением D;

Приложение D синхронизируем с приложением C;

Приложение C синхронизируем с приложением A.

Таким образом, при получении данных в приложении В от приложения А полученные данные будут зарегистрированы и отправлены в приложение D, в приложении D полученные данные от приложения B будут зарегистрированы и отправлены в приложение С, а в приложении С эти же данные зарегистрируются для отправки в приложение А, и так по кругу. Такая бесконечная регистрация и выгрузка данных и называется зацикливанием. Зацикливание может сильно увеличить время прохождения синхронизации, и чтобы его избежать, осуществляется ограничение на отправку данных из приложения С в приложение А (на рисунке обозначено красным цветом).

Подробнее про контроль зацикливания и про снятие контроля см. раздел Контроль зацикливания.

Синхронизация данных в распределенной информационной базе

Примечание для технического писателя: в данном разделе рассматривается создание распределенной информационной базы (РИБ). Синхронизация в распределенной информационной базе может быть полной или с использованием правил синхронизации.

Назначение

Распределенная информационная база имеет иерархическую структуру, состоит из отдельных информационных баз – узлов распределенной информационной базы (РИБ). У каждого узла РИБ может быть произвольное количество подчиненных узлов и один главный узел (вышестоящая база). Узел, у которого нет главного узла, называется корневым узлом распределенной информационной базы.

Синхронизация данных в распределенной информационной базе может быть использована для организации совместной работы вместо других вариантов совместной работы, такие как клиент-серверный вариант или работа с приложением в режиме веб-приложения. Например, этот вариант может быть использован в территориально распределенных офисах предприятия, если наладить стабильный канал связи между ними не представляется возможным. В этом случае работа в каждом офисе производится в своем узле распределенной информационной базы независимо в режиме off-line, а синхронизация данных между узлами происходит с помощью файлов сообщений.

Необходимо создать узлы распределенной информационной базы и настроить синхронизацию между ними. Может быть настроена полная синхронизация, без применения правил синхронизации (подробнее см. раздел Применение правил синхронизации данных), в этом случае происходит синхронизация практически всех данных: значений констант, элементов справочников и планов видов характеристик, документов и их движений, элементов регистров сведений и накопления, бизнес-процессов и задач.

Особенности отправки некоторых видов данных представлены в разделе Особенности синхронизации данных в распределенной информационной базе. Список объектов, не участвующих в синхронизации данных, представлен в разделе Не участвующие в синхронизации данные.

При синхронизации данных не поддерживается автоматическое создание пользователей в списке пользователей информационной базы: элементы списка Пользователи переносятся в подчиненный узел не сопоставленными конкретным пользователям приложения. Добавление пользователя в список Пользователи выполняется непосредственно в каждом узле. Особенности работы со списком Пользователи подробно рассматриваются в разделе Администрирование списка пользователей и управление доступом.

Этапы настройки РИБ

Настройка синхронизации всегда начинается в главном узле и продолжается в периферийном узле. Процесс настройки состоит из следующих этапов:

■ в главном узле производится настройка синхронизации, устанавливаются параметры синхронизации, создается начальный образ подчиненного узла;

■ начальный образ подчиненного узла устанавливается в филиале, устанавливаются параметры синхронизации, завершается настройка синхронизации.

Создание начального образа подчиненного узла

Для создания начального образа подчиненного узла РИБ есть два способа способами:

■ Непосредственно при создании настройки синхронизации данных в главном узле РИБ (подробнее см. раздел Настройка синхронизации в главном узле) приложение предлагает создать начальный образ подчиненного узла;

■ Уже после настройки РИБ в любое удобное время откройте нужную настройку синхронизации в списке Настройки синхронизации данных с помощью кнопки Настроить. Также можно перейти к настройке с помощью двойного щелчка мышью. Нажмите кнопку Создание начального образа с файлами.

С помощью переключателя выберите, где будет создаваться начальный образ:

■ На данном устройстве или на устройстве в локальной сети;

■ На сервере 1С:Предприятия.

Далее необходимо указать Параметры информационной базы.

Для создания начального образа На данном устройстве или на устройстве в локальной сети задайте Параметры информационной базы – Язык (Страна). По умолчанию предлагаются те параметры, которые были заданы при создании синхронизации данных.

Задайте Полное имя файловой базы – укажите путь к базе на устройстве или в локальной сети для сервера 1С:Предприятия под управлением Microsoft Windows (Linux) с помощью кнопки . Рекомендуется выбрать тот же каталог, который был указан при настройке синхронизации данных, для того чтобы при установке в филиале быстро найти все необходимые файлы.

Если файлы хранятся в томах, укажите Полное имя архива с файлами томов для сервера 1С:Предприятия под управлением Microsoft Windows (Linux) с помощью кнопки . Подробнее см. раздел документации Работа с файлами.

Параметры показываются в зависимости от настроек устройства и приложения.

Для создания начального образа информационной базы На сервере 1С:Предприятия необходимо задать следующие параметры:

■ Кластер серверов 1С:Предприятия;

■ Имя информационной базы в кластере;

■ Защищенное соединение – выберите параметры защищенного соединения (Выключено, Установка соединения, Постоянно);

■ Язык (Страна) – выберите нужное значение из списка;

■ Установить блокировку регламентных заданий – при необходимости включите флажок;

■ Выберите Тип СУБД (Microsoft SQL Server, PostgreSQL, IBM DB2, Oracle Database);

■ Сервер базы данных;

■ Имя базы данных;

■ Пользователь базы данных;

■ Пароль пользователя;

■ Выберите из списка Смещение дат.

После установки необходимых параметров нажмите кнопку Создать начальный образ.

Через некоторое время приложение выводит сообщение об успешном создании начального образа подчиненного узла распределенной информационной базы. Нажмите кнопку Закрыть.

Настройка синхронизации в главном узле

Производится из главного узла.

Необходимо провести настройки приложения, см. раздел Настройка приложения.

В списке Настройки синхронизации данных раздела Администрирование – Синхронизация данных нажмите кнопку Новая синхронизация данных. Выберите из предложенного списка настроек значение Распределенная информационная база. Следуйте указаниям приложения.

Перед настройкой синхронизации данных рекомендуется сделать резервную копию данных. Для этого перейдите по ссылке. Подробнее см. раздел документации Резервное копирование. Также можно сделать резервную копию сторонними средствами.

Настройка состоит из следующих этапов:

■ Выбор типа подключения. На данном этапе нужно выбрать вариант подключения, обмен с базой подчинённого узла может быть настроен через локальный или сетевой каталог, через ftp, через email, через Яндекс.Диск или Google Drive Подробнее см. раздел Выбор варианта подключения.

■ Настроить параметры подключения. На данном этапе необходимо указать параметры подключения. Например, при подключении через локальный или сетевой каталог, необходимо указать любой каталог, доступный и приложению-источнику, и приложению-приёмнику. Каталог может быть на устройстве приложения-источника, в сетевом каталоге или на съёмном носителе. После выбора варианта подключения нажмите кнопку Далее для перехода к настройке параметров синхронизации данных. Подробнее см. раздел Выбор варианта подключения.

■ Настроить общие параметры синхронизации. На данном этапе нужно указать название и префикс базы подчинённого узла.

■ Настроить правила отправки и получения данных (правила синхронизации данных). Для частичной отправки данных (можно указать, в разрезе каких Организаций, Складов и Подразделений будут выгружаться данные, с какой даты) нажмите ссылку Изменить правила выгрузки данных. Подробнее см. раздел Применение правил синхронизации данных.

■ Создать начальный образ подчиненного узла РИБ. Подробнее см. раздел Создание начального образа подчиненного узла.

По окончании этого этапа настройки можно при необходимости прервать настройку синхронизации данных и продолжить ее в любое удобное время.

Сохраните файл с начальным образом подчиненного узла распределенной информационной базы на устройстве другого подразделения в новый каталог, которая будет рабочим каталогом новой базы. Не рекомендуется использовать для этого каталог на съёмном носителе, его можно использовать только для синхронизации данных.

Откройте приложение 1С:Предприятие, нажмите кнопку Добавить, выберите Добавление в список существующей информационной базы.

Нажмите кнопку Далее, укажите наименование информационной базы, например, База1. С помощью переключателя выберите тип расположения информационной базы, например, На данном устройстве или на устройстве в локальной сети. Подробнее см. книгу 1С:Предприятие 8.3. Руководство пользователя. Нажмите кнопку Далее.

С помощью кнопки  укажите путь к новому каталогу, в которую был помещен файл с начальным образом подчиненного узла распределенной информационной базы, например, E:\Обмен данными. Нажмите кнопку Далее, укажите необходимые параметры для добавления базы (пароль и т. д.). Указанная информационная база будет добавлена в список баз. Подробнее см. книгу 1С:Предприятие. Руководство пользователя.

После входа в приложение автоматически открывается Помощник синхронизации данных.

Настройка в подчиненном узле состоит из следующих этапов:

■ Настроить параметры подключения (подробнее см. раздел Выбор варианта подключения).

■ Настроить общие параметры синхронизации:

■ Настроить правила отправки и получения данных – можно ограничить отправку данных из этой базы (в разрезе организаций, складов, подразделений или по дате). Подробнее см. раздел Применение правил синхронизации данных.

После завершения этапов настройки можно выйти из помощника.

Созданная настройка синхронизации данных появится в списке Настройки синхронизации данных новой информационной базы филиала. Подробнее см. раздел Список Настройки синхронизации данных.

Список пользователей будет также скопирован, при этом вход в приложение для них будет отключен. Проверьте список и настройте права доступа пользователей новой базы. Подробнее см. раздел Администрирование списка пользователей и управление доступом.

Особенности эксплуатации приложения при настроенной синхронизации РИБ

Совместная работа в распределенной информационной базе должна вестись по определенным правилам во избежание возникновения коллизий, связанных с одновременным изменением одних и тех же данных, произведенным в разных узлах информационной базы. Подобные правила основаны на принципах разделения доступа из разных узлов к данным информационной базы.

Приложение позволяет организовать такую схему по двум направлениям:

■ Структуризация данных;

■ Настройка управления доступом (подробнее см. раздел Администрирование списка пользователей и управление доступом).

При корректной настройке риск возникновения коллизий сводится к минимуму.

Администрирование списка пользователей и управление доступом

Администрирование списка пользователей в распределенной информационной базе можно организовать двумя способами:

1. Централизованная схема

■ При использовании централизованной схемы список пользователей полностью ведется из какого-либо одного узла. Рекомендуется использовать для этих целей центральный узел распределенной информационной базы;

■ В результате выполнения синхронизации информация о пользователях из центрального узла распространяется по периферийным узлам. Настройки доступа пользователей также принимаются из центрального узла.

2. Децентрализованная схема

■ При использовании децентрализованной схемы важно выделить отдельные группы пользователей (в списке Группы пользователей) для каждого узла распределенной базы, из которого планируется вести администрирование пользователей. Например, можно организовать группы: Пользователи центрального офиса, Пользователи дальневосточного офиса и т. д.;

■ Настройки прав доступа, хранимые в списках Группы доступа и Профили групп доступа, необходимо вести централизованно во избежание возникновения коллизий при синхронизации данных между узлами. В составе групп доступа вместо конкретных пользователей необходимо указывать группы пользователей. Подробнее см. раздел документации Управление доступом.

Таким образом, добавление новых пользователей (подробнее см. раздел документации Пользователи) одновременно в разных узлах информационной базы не приведет к возникновению коллизий, связанных с одновременным редактированием одних и тех же данных.

Обновление распределенной информационной базы

Обновление информационной базы периферийного узла отличается от стандартного тем, что изменения приложения поступают в узел в результате синхронизации данных.

Процесс обновления состоит из нескольких этапов:

1. Обновление информационной базы центрального узла;

2. Выполнение сеанса синхронизации данных в центральном узле – в сообщение синхронизации данных помещается информация о произошедшем обновлении приложения центрального узла;

3. Выполнение сеанса синхронизации данных в периферийном узле – в процессе получения данных приложение выводит сообщение, что пришли обновления из базы центрального узла и появится ссылка на обновление.

■ Далее необходимо будет перейти по ссылке, откроется помощник обновления, в котором будет возможность выполнить резервное копирование базы.

■ При завершении работы помощника будет запущено выполнение обработчиков обновления информационной базы. После выполнения работы помощника база обновится, в ней можно будет работать.

Если в приложении настроена синхронизация данных в распределенной информационной базе, то расширения приложения, подключенные в главном узле, автоматически передаются и устанавливаются во все подчиненные узлы в том случае, если у плана обмена включено свойство Включать расширение конфигурации. Данное свойство включается в Конфигураторе.

Ручное обновление распределенной информационной базы

Процесс ручного обновления состоит из следующих этапов:

1. Обновление информационной базы центрального узла;

2. Выполнение сеанса синхронизации данных в центральном узле – в сообщение синхронизации данных помещается информация о произошедшем обновлении приложения центрального узла;

3. Выполнение сеанса синхронизации данных в периферийном узле – в процессе получения данных приложение выводит сообщение, что пришли обновления из базы центрального узла. В периферийном узле производятся дальнейшие действия по обновлению приложения:

■ Далее необходимо закрыть приложение и зайти в него в режиме Конфигуратор.

■ Производится применение обновлений приложения в режиме конфигуратора, запуск приложения в обычном режиме;

■ При запуске приложение предлагает получить данные из сообщения синхронизации данных. Получение данных является обязательным условием для продолжения работы в приложении;

■ После получения данных автоматически стартует процедура обновления информационной базы, по окончании которой в приложении можно работать.

Восстановление информационной базы главного узла

Восстановление информационной базы главного узла может понадобиться в случае, если произошел сбой, в результате которого информационная база главного узла была повреждена. Во избежание потери или порчи данных рекомендуется регулярно проводить резервное копирование информационной базы. Подробнее см. раздел документации Резервное копирование.

Процедуру восстановления информационной базы главного узла можно разделить на несколько этапов:

1. Восстановить базу данных главного узла.

Если есть резервная копия главного узла, то выполнить восстановление из нее. Подробнее см. раздел документации Резервное копирование.

Если нет резервной копии главного узла, или данные в подчиненном узле более полные, то

■ скопировать подчиненный узел и отключить его от главного узла, например, с помощью параметра запуска конфигуратора /ResetMasterNode. Подробнее см. раздел Отключение информационной базы от главного узла.

■ запустить в режиме 1С:Предприятия, если появится предложение на восстановление связи с главным узлом, тогда отказаться от восстановления и выбрать отключение. Внимание! Данная операция является необратимой. Восстановление связи с главным узлом после этого возможно будет только программными средствами.

2. Обновить конфигурацию главного узла до текущей версии (подробнее см. раздел Обновление распределенной информационной базы, а также раздел документации Обновление приложения).

Если конфигурация главного узла, восстановленного из резервной копии, имеет более раннюю версию, чем конфигурация подчиненного узла, то нужно загрузить конфигурацию подчиненного узла в главный узел. О выгрузке и загрузке конфигурации подробнее см. раздел Восстановление информационной базы подчиненного узла.

3. Восстановить настройки синхронизации данных с подчиненными узлами.

Восстановить состав узлов планов обмена, чтобы он соответствовал тому, который был до сбоя (подробнее см. разделы Настройка синхронизации в главном узле и Изменение настройки синхронизации данных).

Затем синхронизировать номера сообщений между главным и подчиненным узлами. Для этого в главном узле из раздела Администрирование – Синхронизация данных открыть Настройки синхронизации данных (или окно Автономная работа). По команде Еще – Состав отправляемых данных открыть окно Регистрация изменений (подробнее см. раздел Состав отправляемых данных):

■ установить номера отправленных сообщений на единицу больше номеров сообщений, принятых в подчиненных узлах;

■ установить номера принятых сообщений на единицу меньше номеров сообщений, отправленных из подчиненных узлов.

Восстановление информационной базы подчиненного узла

Восстановление информационной базы подчиненного узла может понадобиться в случае, если произошел сбой, в результате которого информационная база подчиненного узла была повреждена. Во избежание потери или порчи данных рекомендуется регулярно проводить резервное копирование информационной базы. Подробнее см. раздел документации Резервное копирование.

Описанные рекомендации применимы в том числе к автономным рабочим местам (АРМ) для приложения в интернете.

Процедуру восстановления информационной базы подчиненного узла можно разделить на несколько этапов:

■ Обновить конфигурацию подчиненного узла путем загрузки конфигурации главного узла (см. также раздел Обновление распределенной информационной базы).

Для восстановления синхронизации данных требуется полное соответствие конфигураций главного и подчиненного узлов. Если это не так, тогда требуется:

■ В главном узле зарегистрировать данные для восстановления подчиненного узла. Для этого в главном узле из раздела Администрирование – Синхронизация данных открыть Настройки синхронизации данных (или окно Автономная работа).

■ С помощью кнопки панели навигации  или команды Еще – Состав отправляемых данных открыть окно Регистрация изменений, в которой воспользоваться командой Еще – Зарегистрировать данные для восстановления подчиненного узла РИБ. На запрос приложения нажмите Да. Подробнее см. раздел Состав отправляемых данных.

После этого необходимо произвести синхронизацию данных в главном узле.

■ Временно отключить подчиненный узел от главного узла, например, с помощью параметра запуска конфигуратора /ResetMasterNode. Подробнее см. раздел Отключение режима распределенной информационной базы.

■ Выгрузить конфигурацию главного узла в файл *.cf в режиме конфигуратора.

■ Загрузить конфигурацию главного узла из файла *.cf в подчиненный узел в режиме конфигуратора.

Отключение от главного узла требуется в случае, если было принято решение использовать подчиненный узел как самостоятельную информационную базу. Описанные рекомендации применимы, в том числе, к автономным рабочим местам (АРМ) для приложений в интернете.

Процедуру отключения информационной базы подчиненного узла можно разделить на несколько этапов:

Отключение режима распределенной информационной базы

Такая процедура может потребоваться как при отключении информационной базы от главного узла, так и при проведении восстановительных работ.

Если после этого открыть конфигуратор, то можно увидеть, что в приложении произошли изменения: связь с главным узлом временно отключена.

Особенности синхронизации данных в распределенной информационной базе

Полная синхронизация РИБ (без применения правил синхронизации) имеет такую структуру, которая позволяет эффективно использовать ее при решении нескольких задач:

■ Создание резервной копии путем создания начального образа приложения;

■ Создание копии приложения с целью удаленной работы в ней и последующего получения в оригинал всех изменений;

Для реализации первой и второй задачи в состав синхронизации данных включены практически все виды данных. Сценарии синхронизации в приложении в сервисе

В приложении в Интернете сценарий синхронизации доступен только для планов обмена через универсальный формат с подключением к базе корреспонденту через внутреннюю публикацию (Подробнее см. раздел Внутренняя публикация).

Но при настройке сценария есть ряд ограничений:

■ Минимальный интервал запуска сценария не может быть меньше 15 минут, но точное время его выполнения зависит от загруженности приложения. Об этом предупреждает подсказка в окне синхронизации.

■ Обязательно должно быть задано два действия для одного узла (Получение/Отправка). В противном случае, при записи сценария будет выдано предупреждение.

■ При настройке синхронизации данных через Web-cервис автоматическое выполнение синхронизации данных настраивается только в одной из баз.

Внутренняя публикация (Синхронизация между областями в сервисе)

Внутренняя публикация — это вариант подключения, используемый для синхронизации между двумя приложениями, находящимися в одном сервисе (например, fresh1c.ru).

Данный вариант подключения выбирается автоматически, если при настройке подключения была выбрана база из списка. По сути – это разновидность обмена через Интернет (веб-сервис), с той лишь разницей, что не нужно указывать никаких учетных данных для подключения. Обмен будет происходить через внутренние ресурсы самого сервиса.

 

Такой вариант обмена можно настроить только посредством помощника настройки подключения.

Перевод обмена на внутреннюю публикацию

До версии БСД 1.0.2 (библиотека синхронизации данных) обмен выполнялся посредством управляющего приложения – Менеджера сервиса. В таком случае нельзя задать расписание синхронизации (задается администратором сервиса), и время запуска синхронизации зависит от загруженности менеджера сервиса.

Если в приложении есть возможность перейти на обмен посредством внутренней публикации, то в окне настройки синхронизации данных об этом будет выведена информация.

Такая же информация будет выведена и в узле плана обмена.

Для того чтобы эта информация больше не появлялась, необходимо выбрать ссылку Больше не предлагать перейти на веб-сервис. После этого перейти на обмен через внутреннюю публикацию можно будет через меню Еще – Помощник перехода на Интернет (внутренняя публикация). Подробнее см. раздел Помощник перехода на Интернет (внутренняя публикация).

■ Это обмен через Менеджер сервиса;

■ Это план обмена через универсальный формат;

■ Настройка синхронизации для узла завершена;

■ Доступен интерфейс ExchangeAdministrationManage 3.0.1.1 в Менеджере сервиса и в базе корреспонденте.

При возникновении проблем на любом из этапов, процесс перехода можно продолжить, запустив помощник заново.

При настройке синхронизации данных в клиент-серверном варианте приложения необходимо иметь в виду, что синхронизация данных выполняется на устройстве, на котором установлен сервер 1С:Предприятия. Поэтому необходимо убедиться, что указанный каталог для синхронизации данных доступен для чтения и записи пользователю операционной системы, от имени которого запущен сервер 1С:Предприятия. Если это не так, то требуется дать этому пользователю необходимые права, или выбрать другого пользователя для запуска сервера 1С:Предприятия с необходимыми правами на каталог для синхронизации данных.

Для синхронизации данных в клиент-серверном варианте могут потребоваться настройки прокси-сервера на устройстве с установленным сервером 1С:Предприятие, а в файловом варианте настройки прокси-сервера на устройстве, на котором осуществляется синхронизация данных. Подробнее см. раздел документации Получение файлов из интернета.

Дата запрета загрузки данных. Приложение позволяет устанавливать дату запрета загрузки данных. Дата запрета загрузки данных может быть установлена для дополнительной защиты данных текущего приложения (в которой выполняется настройка) от изменений, которые могут быть получены в результате загрузки данных из других приложений. Дату запрета загрузки данных можно устанавливать как для всех информационных баз, так и для конкретной информационной базы, из которой будут загружаться данные.

Если дата запрета загрузки данных установлена, то при попытке получить данные в приложение до даты запрета загрузки все запрещенные для получения данные будут пропущены, сведения о них будут записаны в журнал регистрации и также будут отражены в списке предупреждений (см. раздел Список предупреждений по синхронизации данных). Разрешенные данные будут получены. Подробнее см. раздел документации Даты запрета изменения.

Хранение файлов в томах на сервере. Если для хранения файлов используются тома на сервере, то вместе с созданием начального образа автоматически будет создан архив с файлами, хранящимися в томах (для этого необходимо указать каталог). Затем в процессе создания информационной базы подчиненного узла из начального образа в приложении-приемнике следует получить файлы из этого архива. Для того чтобы получить файлы из архива, необходимо выполнить синхронизацию подчиненного узла с главным узлом. Подробнее см. раздел документации Работа с файлами.

Перед синхронизацией данных рекомендуется создать резервную копию данных. Резервную копию можно создать средствами приложения. Можно также произвести резервное копирование сторонними средствами. Подробнее см. раздел документации Резервное копирование ИБ.

Внимание! При копировании базы данных или восстановлении базы данных из резервной копии вся работа с внешними ресурсами, в том числе и синхронизация данных, будет заблокирована. Приложение выводит об этом сообщение в начале работы с базой данных. Если эта база данных становится основной, то для разблокирования нажмите кнопку Информационная база перемещена. Также это можно сделать в разделе Администрирование – Обслуживание – Регламентные операции с помощью кнопки Разблокировать работу с внешними ресурсами. Подробнее см. раздел документации Регламентные задания.

Архивирование сообщений обмена

В процессе синхронизации данных есть возможность сохранять входящие сообщения (файлы) обмена. К примеру, это может понадобиться для расследования проблем при загрузке данных.

Для того чтобы настроить архивирование сообщений, необходимо в окне узла обмена нажать кнопку Параметры синхронизации данных, в выпадающем меню выбрать команду Архив сообщений обменов.

В появившемся окне необходимо настроить параметры сохранения сообщения.

На вкладке Настройки можно установить параметры:

■ Количество файлов – количество сообщений, сохраняемых при обмене. При работе в приложении в Интернете (например, fresh1c.ru) максимальное количество сохраняемых файлов не может превышать одного. Если необходимо отключить архивирование, то количество файлов устанавливается равным нулю.

■ Сжимать файлы – если флажок установлен, то сообщение обмена будет запаковано в zip-архив.

■ Место хранения – с помощью переключателя можно выбрать, где будет расположен архив. Если переключатель установлен в положение На устройстве, то файлы будут располагаться в указанном каталоге (или сетевом ресурсе), доступность каталога можно проверить по кнопке Проверить. Если выбрано положение переключателя В информационной базе, то сообщения будут сохранены в самой информационной базе. При этом файлы размером более 100 Мб будут игнорироваться.

На вкладке Архив сообщений находится краткая информация о сохраненных сообщениях обмена. Здесь же можно Сохранить указанные файлы с помощью кнопки панели навигации.

Выбор варианта подключения

Для синхронизации данных между двумя приложениями могут быть выбраны различные варианты подключения.

Для синхронизации данных в распределенной информационной базе используются только типы подключения без прямого соединения с базой-приёмником.

На странице помощника синхронизации данных Выбор типа транспорта укажите параметры подключения к приложению-приемнику или к подчиненному узлу информационной базы.

Вариантов подключения может быть настроено несколько, при этом один вариант подключения должен быть выбран по умолчанию. Рассмотрим варианты подключения:

■ Прямое подключение (СОМ-соединение) используется для синхронизации данных между двумя приложениями, причем оба приложения должны быть доступны для подключения. Подробнее см. раздел Прямое подключение к приложению на этом устройстве или в локальной сети.

■ Подключение через локальный или сетевой каталог. Такой вариант подходит для синхронизации данных с приложениями, расположенными в других сетях (офисах), так же для приложений в одной сети. При настройке синхронизации будет сформирован файл(ы) с настройками подключения (*.xml и *.json). В программе-корреспонденте при выборе типа подключения, необходимо выбрать опцию Продолжение настройки, выбрать необходимый тип подключения и загрузить файл с настройками подключения.

■ Подключение через ftp-сервер так же подходит для синхронизации данных с приложениями, расположенными в других сетях (офисах), или для приложений в одной сети. Настраивается аналогично подключению через локальный или сетевой каталог.

■ Подключение через электронную почту так же подходит для синхронизации данных с приложениями, расположенными в других сетях (офисах), или для приложений в одной сети. Настраивается аналогично подключению через локальный или сетевой каталог.

■ Подключение через Яндекс.Диск или через Google Drive так же подходит для синхронизации данных с приложениями, расположенными в других сетях (офисах), или для приложений в одной сети. Настраивается аналогично подключению через локальный или сетевой каталог.

■ Подключение к другому приложению через Интернет. Подробнее см. раздел Подключение к приложению через Интернет (веб-сервис);

Может быть настроено несколько вариантов подключения через другие каналы связи, в этом случае один из них выбирается в качестве основного. Подробнее см. раздел Синхронизация данных через файл.

Для вариантов подключения, связанных с интернетом, может потребоваться настройка прокси-сервера. Для настройки перейдите по ссылке Параметры доступа в интернет. Подробнее см. раздел документации Получение файлов из интернета.

Проверка варианта подключения во время настройки производится приложением автоматически.

Варианты подключения можно настроить и в уже сохраненной настройке синхронизации данных. Для этого воспользуйтесь командой (кнопкой) Настройки подключения. Об изменении сохраненной настройки синхронизации данных подробнее см. раздел Изменение настройки синхронизации данных.

Прямое подключение к приложению на этом устройстве или в локальной сети

Данный вариант подключения используется в том случае, если приложение-источник находится на том же устройстве, что и приложение-приемник, или в локальной сети одного офиса, причем во время настройки синхронизации данных и при синхронизации приложение должна быть доступна, т. е. устройство включено и работает в сети.

С помощью переключателя выберите Расположение приложения:

■ Файловая база-корреспондент. Далее укажите Каталог информационной базы (например, C:\Users\Admin\Documents\1C\DemoSSL).

■ Клиент-серверная база-корреспондент. В случае если приложение-приемник находится на сервере, с помощью переключателя выберите параметры подключения к клиент-серверному приложению.

Далее укажите Имя сервера (например, Demo-Server) и Имя информационной базы, (например, Demo-SSL).

Далее можно установить флажок Использовать учетную запись операционной системы, либо использовать указанные имя пользователя и пароль (таким образом выбрана аутентификация 1С:Предприятия), в этом случае укажите Имя пользователя-администратора (например, Администратор) и Пароль для входа приложение-приемник (например, 123).

Подключение к приложению через Интернет (веб-сервис или http)

Такой вариант подключения используется для синхронизации данных между двумя приложениями. Он может быть использован в том случае, если приложение-приемник находится в другом офисе, при этом она доступна для синхронизации через интернет.

■ Введите Адрес приложения (например, http://DemoServer/DemoSSL1);

■ Укажите имя Пользователя-администратора (например, Администратор) и Пароль для входа в приложение-приемник (например, 123). При необходимости включите флажок Запомнить пароль.

Настройка через http-сервера проходит аналогично.

Когда одно из приложений опубликовано в веб-сервисе, оно является ведомым (пассивным) и только отвечает на запросы, которые к нему приходят, со стороны ведущего приложения (из которого выполняется настройка синхронизации).

При настройке подключения через Интернет (веб-сервис) приложение-приёмник, опубликованное в веб-сервисе, будет иметь настройку подключения Пассивный режим.

 

При такой настройке синхронизация выполняется только со стороны ведущего приложения. При попытке выполнить синхронизацию со стороны пассивного приложения выйдет предупреждение, что запуск синхронизации из этого приложения не поддерживается.

Синхронизация данных через локальный или сетевой каталог

Синхронизация данных через локальный или сетевой каталог, без прямого подключения к другому приложению, может использоваться:

■ для синхронизации данных с приложением в другом офисе, которая может работать в автономном режиме, причем два приложения, участвующие в синхронизации данных, могут работать в разное время (подробнее см. раздел Синхронизация данных между разными приложениями). Данный вариант подключения может использоваться для синхронизации данных с приложением, которая находится в этом же или удаленном офисе, но не имеет доступа к локальной сети и Интернету (прямое подключение в данном случае невозможно), например, для синхронизации данных основного магазина с небольшой розничной точкой. Компьютер, на котором находится приложение-приемник, в момент настройки синхронизации данных может быть выключен;

■ для синхронизации данных в распределенной информационной базе (подробнее см. раздел Синхронизация данных в распределенной информационной базе).

■ Перейдя по ссылке Выбор типа подключения, выберете вариант Локальный или сетевой каталог (включен по умолчанию).

■ Введите путь к Каталогу, например D:\Обмен данными. Каталог может быть на том же устройстве, в сетевом каталоге или на съёмном носителе.

Для завершения настройки в приложении-источнике нужно пройти все остальные шаги настройки новой синхронизации данных.

Для продолжения настройки синхронизации в приложении-приемнике перейдите на вкладку Продолжение настройки, нажмите кнопку Загрузить настройки подключения и укажите путь к файлу с настройками.

Синхронизация данных через FTP-ресурс

Перейдя по вкладке Выбор типа подключения, выберете вариант FTP-сервер.

Введите Путь к каталогу, например ftp://ftp.Demo.ru/, Порт (по умолчанию 21).

Укажите имя Пользователя (логин), например, Administrator и Пароль, например, 123.

Вы можете включить флажок, для того чтобы использовать Пассивный режим при необходимости.

Каналы связи, связанные с интернетом, могут иметь ограниченную емкость и скорость. В приложении предусмотрены возможности по рациональному их использованию.

Для ограничения размера передаваемого сообщения введите Максимальный размер сообщения обмена, Кбайт. Если сообщение может быть неограниченного размера, оставьте значение 0 (по умолчанию).

Внимание! Необходимо учитывать, что если при синхронизации данных передаваемое сообщение будет превышать указанное ограничение, отправка или получение данных не состоится, в журнале регистрации будут зафиксированы сведения об этом.

Уменьшить объем пересылаемого сообщения можно с помощью его архивирования. Для этого включите флажок Сжимать файл исходящего сообщения, при необходимости укажите Пароль архива сообщения обмена для защиты данных.

Включите флажок, для того чтобы Транслитерировать имена файлов обмена. В этом случае имена файлов будут автоматически написаны на латинице. Подробнее см. раздел документации Работа с файлами.

Синхронизация данных через электронную почту.

Перейдя по вкладке Выбор типа подключения, выберете вариант Электронная почта.

Выберите из списка Электронную почту с помощью кнопки . Подробнее см. раздел документации Работа с почтовыми сообщениями.

Для того чтобы ограничить размер сообщения, включите флажок Сжимать файл исходящего сообщения.

Нажмите кнопку Готово для перехода к настройке общих параметров синхронизации данных.

Синхронизация данных через Яндекс.Диск или Google Drive.

Перейдя по вкладке Выбор типа подключения, выберете вариант Яндекс.Диск.

Для настройки параметров подключения в открывшемся окне необходимо нажать кнопку Получить токен. После нажатия на эту кнопку откроется инструкция для подключения к сервису Яндекс.Диск и получения токена. Вам необходимо будет выполнить все пункты в той инструкции, и в завершении ввести сформированные Client ID и Client secret в зелёное поле. Далее необходимо будет нажать в зелёном поле кнопку Получить токен.

Далее поля Client ID, Client secret, Ассess token и Refresh token заполнятся автоматически.

Для того чтобы ограничить размер сообщения, включите флажок Сжимать файл исходящего сообщения. Нажмите кнопку Готово для перехода к настройке общих параметров синхронизации данных.

Подключение через Google Drive настраивается аналогично.

Особенности синхронизации через формат EnterpriseData с использованием синхронизации данных через файл

Настройка варианта подключения при обмене через формат EnterpriseData через каналы связи, отличные от прямого подключения, (подробнее см. раздел Синхронизация данных через файл) немного отличается от остальных:

■ Настройте вариант подключения через Локальный или сетевой каталог (либо ftp, либо электронная почта, либо Яндекс.Диск, либо Google Drive) в приложении-источнике;

■ Продолжите настройку синхронизации данных в приложении-приемнике. Настройте вариант подключения через файл. Для этого перейдите в приложение-приемник, в разделе Выбор типа подключения перейдите на вкладку Продолжение настройки, выберете файл с настройками  в формате .xml, либо .json полученными из приложения-источника.

Только после проведения настройки вариантов подключения в двух приложениях можно будет перейти к дальнейшей настройке синхронизации данных. Подробнее см. разделы Настройка в приложении-источнике и Настройка в приложении-приемнике.

Применение правил синхронизации данных

На странице помощника настройки синхронизации данных нажмите ссылку Настроить правила отправки и получения данных.

Правила синхронизации данных используются, если необходимо синхронизировать не все данные, а только часть. При настройке синхронизации необходимо учитывать, что часть данных передать и получить быстрее, чем все данные.

Принцип действия правил синхронизации данных таков, что новые настройки действуют для всех данных только в момент создания синхронизации данных.

При необходимости можно изменить правила синхронизации данных и в уже существующей настройке синхронизации данных (подробнее см. раздел Изменение настройки синхронизации данных).

Общие правила синхронизации данных

Нужно учитывать, что после создания синхронизации данных новые настройки действуют уже только для тех данных, которые были изменены после момента применения новых настроек, поэтому рекомендуется максимально ответственно подойти к настройке фильтров при создании синхронизации данных.

С помощью переключателя на вкладке Общие правила синхронизации данных можно определить, как они будут синхронизироваться документы:

■ Отправлять и получать автоматически – документы будут синхронизироваться в двух приложениях;

■ Отправлять автоматически – документы будут автоматически отправляться во второе приложение, в первом приложении автоматического получения документов из второго приложения не будет;

■ Получать автоматически – документы будут доставляться из второго приложения, из этого приложения документы отправляться не будут;

■ Отправлять и получать вручную – документы автоматически синхронизироваться не будут. Отправку и получение документов необходимо будет выполнять вручную.

С помощью переключателя Нормативно-справочная информация выберите режим выгрузки списков приложения:

■ Отправлять и получать автоматически – данные будут синхронизироваться в полном объеме, нормативно-справочная информация будет автоматически синхронизироваться в этой и во втором приложении;

■ Отправлять и получать только используемую в документах – синхронизироваться будут только те данные, ссылки на которые есть в документах, участвующих в синхронизации данных;

■ Отправлять и получать вручную – нормативно-справочная информация не будет автоматически синхронизироваться, ее отправку и получение необходимо будет выполнять вручную.

Фильтры (Правила отправки данных)

На вкладке Правила отправки данных можно ограничить данные, участвующие в синхронизации – и задать, в разрезе каких Организаций, Складов и Подразделений будут отправляться данные (в соответствующих разделах):

■ Включение фильтра По организациям позволяет ограничить список организаций, по которым разрешена синхронизация данных. Наличие включенного фильтра влияет как на отправку самого списка организаций, так и на отправку других данных, связанных с организациями (списки и документы). Для включения фильтра установите переключатель в положение С отбором по выбранным организациям, выберите с помощью флажков нужные организации из списка.

■ Для включения фильтра По подразделениям установите переключатель в положение С отбором по выбранным подразделениям, включите соответствующие флажки.

■ Также можно выгружать информацию С отбором по выбранным складам. Для этого с помощью переключателя выберите нужное значение, с помощью флажков выберите нужные склады.

Выборочная регистрация объектов

Кроме фильтров, которые определены в окне настройки синхронизации, в приложении дополнительно может быть включен режим выборочной регистрации данных. Выборочная регистрация объектов – это проверка признака изменения объекта, которая выполняется до алгоритмов правил регистрации и в некоторых моментах существенно экономит время. Так, например, при групповом проведении документов из списков, если режим выборочной регистрации используется, документы не будут регистрироваться к отправке. Настройку выборочной регистрации производит разработчик приложения на этапе внедрения, т. е. пользователь не может влиять на включение или отключение этого режима.

Информацию о том, как настроена выборочная регистрация, можно посмотреть в нижней части окна Регистрация изменений, которое открывается с помощью кнопки  Состав отправляемых данных или с помощью команды Еще – Состав отправляемых данных (подробнее см. раздел Состав отправляемых данных) из окна списка Настройки синхронизации данных. Для этого в нижней части окна Регистрация изменений нажмите кнопку  Дополнительная информация.

Правила получения данных – значения по умолчанию

Применяются в синхронизации данных между двумя приложениями.

Значения по умолчанию необходимы для правильного отражения документов в учете при синхронизации данных. Используются для автоматического дозаполнения документов при отправке данных. Возможно, в документах, полученных из другого приложения, не были предусмотрены некоторые реквизиты. В этом случае при проведении синхронизации данных эти реквизиты будут заполнены приложением автоматически. Их можно указать сразу же при настройке синхронизации (по ссылке Настроить правила отправки и получения данных).

Также можно указать или изменить их позже, открыв готовую настройку синхронизации из списка. Подробнее см. раздел Изменение настройки синхронизации данных. В окне настройки синхронизации данных перейдите на вкладку Правила получения данных.

С помощью кнопки  выберите Номенклатуру, которая будет использоваться по умолчанию для списания в производство. Поле обязательно для заполнения.

Иногда требуется указать, каким значением по умолчанию будет заполнен реквизит Ставка НДС в документах. Для этого в приложении необходимо произвести настройки (см. раздел Настройка приложения). Для выбора ставки НДС из списка нажмите кнопку . Выберите из списка нужную ставку НДС или создайте новую ставку.

Для возвращения к настройке синхронизации данных нажмите кнопку Записать и закрыть.

При настройке синхронизации через формат EnterpriseData или состав и другие характеристики получаемых данных настраиваются с помощью правил отправки в приложении-корреспонденте.

В списке Настройки синхронизации данных раздела Администрирование – Синхронизация данных выберите нужную настройку синхронизации данных, затем нажмите кнопку Изменить настройки. Также для настройки можно воспользоваться двойным щелчком мыши.

■ Правила получения данных. Подробнее см. раздел Правила получения данных – значения по умолчанию;

■ Параметры подключения. Можно выбрать любой вариант подключения из ранее используемых или настроить новый. Подробнее см. раздел Выбор варианта подключения.

В настройке синхронизации данных двух приложений перейдите по ссылке Настройки подключения.

Контроль актуальности типовых правил обмена

Настройка синхронизации данных производится в соответствии с так называемыми Типовыми правилами обмена (это небольшая специальное приложение). Если эти правила устарели, то выполнение синхронизации данных приведет к очень серьезным проблемам, порче информации.

Поэтому при настройке новой синхронизации данных, а также при выходе очередного обновления любого из приложений, участвующих в синхронизации данных, необходимо контролировать актуальность используемых типовых правил обмена, которые могут состоять из правил конвертации объектов и правил регистрации объектов:

■ Для синхронизации данных между двумя приложениями используются как правила конвертации данных, так и правила регистрации объектов;

■ Для синхронизации данных в распределенной информационной базе используются только правила регистрации объектов.

В случае синхронной публикации приложений Управление торговлей и Бухгалтерия предприятия КОРП комплект актуальных правил обмена публикуется на сайте технической поддержки http://users.v8.1c.ru/project.jsp?id=Trade110. Исправительные версии правил обмена также публикуется на данном сайте.

Необходимо обратить внимание на следующие параметры:

■ номера релизов приложения-источника и приложения-приемника, для которых предназначены правила;

■ дата создания правил.

При дальнейшем описании будем называть их «контролируемые параметры».

Контроль производится по следующим правилам:

■ Определяется значение контролируемых параметров, которые загружены в приложение-источник;

■ Определяется значение контролируемых параметров, которые загружены в приложение-приемник;

■ Определяется значение контролируемых параметров, которые включены в поставку приложения-источника;

■ Определяется значение контролируемых параметров, которые включены в поставку приложения-приемника.

После анализа всех этих правил выбираются те правила, дата создания которых является наиболее актуальной. При анализе правил необходимо обратить внимание на номера релизов приложения. Номера релизов приложения, указанные в правилах, должны обязательно соответствовать тем релизам приложения, между которыми настраивается синхронизация данных.

Для определения значения контролируемых параметров, которые загружены в приложения, выполните следующие действия:

■ Создайте новую синхронизацию данных, но не выполняйте ее;

■ Выделите в списке созданную настройку синхронизации данных;

■ Выполните команду Загрузить правила меню Еще (подробнее об этой и других командах см. раздел Список Настройки синхронизации данных). Проконтролируйте информацию о комплекте правил.

Аналогичным образом можно произвести анализ контролируемых параметров, которые загружены в приложение, и для уже существующей настройки синхронизации данных. Например, для проверки правил регистрации объектов в существующей настройке синхронизации данных в подчиненном узле.

Для проверки синхронизации данных двух приложений данные действия следует производить последовательно для приложения-источника и приложения-приемника.

Для определения значения контролируемых параметров, которые входят в поставку приложений, выполните следующие действия:

■ С помощью переключателя выберите Загрузить из файла на устройстве;

■ Нажав кнопку Загрузить, выберите файл правил из комплекта поставки приложения;

■ Путь к файлу зависит от комплекта поставки приложения. Например, при настройке синхронизации на стороне приложения Управление торговлей файл следует искать в подкаталоге "Обмены данными\Обмен с конфигурацией Бухгалтерия предприятия КОРП, ред. 2.0". При настройке синхронизации на стороне приложения Бухгалтерия предприятия КОРП - в подкаталоге "Обмены данными\Обмен с конфигурацией Управление торговлей, ред. 11.0";

■ Загрузите новые правила, проверьте контролируемые параметры.

Данные действия следует производить последовательно для двух приложений, которые участвуют в синхронизации данных.

При загрузке правил из файла предусмотрена возможность произвести отладку. Для этого нажмите ссылку Настройка режима отладки:

При необходимости включите флажок Включить режим отладки, после этого становятся доступными настройки режима отладки:

■ Подключить внешнюю обработку для отладки выгрузки – включите флажок, укажите путь к файлу внешней обработки на устройстве;

■ Подключить внешнюю обработку для отладки загрузки – включите флажок, укажите путь к файлу внешней обработки на устройстве;

■ Включите флажок Режим протоколирования обмена данными, укажите путь к текстовому файлу протоколирования обмена данными;

■ При необходимости включите флажок Не останавливать выполнение обмена данными при возникновении ошибки.

Если источник правил – внешний файл, то необходимо осуществить дополнительную проверку, для этого:

■ Необходимо посмотреть информацию об этих правилах, затем сохранить копию используемых правил в файл с помощью команды Еще – Сохранить правила в файл;

■ Установить переключатель в положение Из конфигурации;

■ Посмотреть представленную информацию о правилах.

Если правила в выбранном файле устарели, то после выбора файла по кнопке Загрузить приложение выводит предупреждение.

В результате проверки контролируемых параметров принимается одно из решений:

2. Использовать свежие правила из комплекта правил в одном из приложений.

Выполнение синхронизации данных

Если настроено автоматическое выполнение синхронизации данных, то синхронизация данных будет осуществляться по заданному расписанию. Подробнее см. раздел Автоматическое выполнение синхронизации данных по расписанию.

Если автоматическое выполнение синхронизации данных не настроено или необходимо выполнить синхронизацию данных в любой момент времени, то для выполнения синхронизации данных вручную необходимо открыть список Настройки синхронизации данных (подробнее см. раздел Список Настройки синхронизации данных), например, на Начальной странице приложения и нажать кнопку Синхронизировать. Выполнение синхронизации вручную доступно для всех синхронизаций в списке, при этом синхронизация между двумя приложениями может производиться интерактивно. Подробнее см. раздел Выполнение синхронизации данных при необходимости (интерактивно).

В журнале регистрации приложения отражаются события синхронизации данных (подробнее см. раздел События синхронизации данных).

Выполнение синхронизации данных при необходимости (интерактивно)

Данная функция предусмотрена для синхронизации данных между разными приложениями (см. раздел Синхронизация данных между разными приложениями).

Режим интерактивной синхронизации данных следует выбирать в том случае, если до синхронизации данных один и тот же объект мог быть введен независимо в оба приложения, участвующие в синхронизации. Например, интерактивный режим синхронизации данных следует выбирать для первой синхронизации данных между двумя приложениями, учет в которых уже ведется, и в них имеются одинаковые списки Демо: Номенклатура. Вероятность существования дублирования данных в таких приложениях очень высока. Интерактивный режим позволит такие данные сопоставить автоматически или вручную.

Для того чтобы произвести синхронизацию данных вручную, в списке Настройки синхронизации данных выберите нужную настройку синхронизации данных, затем нажмите кнопку Синхронизировать, задав дополнительные отборы, для того чтобы открыть Помощник интерактивной синхронизации данных. Помощник предназначен для выполнения отправки и получения данных с возможностью предварительного просмотра и сопоставления получаемых данных.

Отправка данных

На первой странице Помощника интерактивной синхронизации данных указаны параметры производимой синхронизации данных, заданные при настройке синхронизации, при необходимости нажмите кнопку Настроить для указания других параметров. Подробнее см. разделы Применение правил синхронизации данных и Выбор варианта подключения. Нажмите кнопку Далее для перехода к сопоставлению объектов.

Получение и сопоставление данных

В ходе интерактивной синхронизации приложение производит автоматическое сопоставление данных и выводит таблицу сопоставленных данных.

Выполнять получение данных рекомендуется только после выполнения сопоставления данных. Если данные не были сопоставлены, то после получения данных будут созданы дубли «не сопоставленных» данных.

Приложение выводит для просмотра результаты автоматического сопоставления данных.

При необходимости можно сопоставить данные вручную. Для этого выделите данные, нажмите кнопку Сопоставить. Открывается список для предварительного просмотра получаемых данных и выполнения сопоставления объектов вручную.

При использовании интерактивного режима получения данных рекомендуется вначале выполнять автоматическое сопоставление, а затем выполнять сопоставление вручную для объектов, которые не были сопоставлены автоматически. Сопоставленные вручную объекты двух приложений запоминаются и при выполнении следующей синхронизации данных сопоставляются автоматически.

После сопоставления всех совпадающих объектов в информационных базах синхронизацию между ними можно выполнять в автоматическом режиме (при условии, что далее все объекты будут заводиться только в каком-то одном приложении, а в другую будут переноситься с помощью синхронизации данных). Для того чтобы такие объекты переносились быстрее, рекомендуется увеличивать частоту автоматической синхронизации данных.

После получения данных по кнопке Далее помощник выполнит отправку данных.

На заключительной странице помощника будет предложено настроить выполнение синхронизации данных автоматически по расписанию. Если текущая синхронизация данных уже включена в одно из существующих расписаний выполнения синхронизации данных, то данное предложение будет недоступно.

Для настройки расписания синхронизации данных в автоматическом режиме нажмите кнопку Настроить. Подробнее см. раздел Автоматическое выполнение синхронизации данных по расписанию.

С помощью ссылки Подробно можно посмотреть события синхронизации в журнале регистрации. Подробнее см. раздел документации Настройки приложения.

Для выхода из помощника интерактивной синхронизации данных нажмите кнопку Готово.

С помощью ссылки Синхронизация по расписанию в нижней части списка Настройки синхронизации данных по выбранной настройке можно просмотреть список сценариев синхронизации данных, создать новый сценарий синхронизации данных или изменить существующие.

Не рекомендуется выполнять только отправку данных или только получение данных, хотя сценарий позволяет это сделать. Надо выполнять полноценную синхронизацию данных в одном сценарии.

При настройке синхронизации данных между облачными приложениями, при подключении через веб-сервис также есть возможность добавить сценарии синхронизации и настроить обмен в автоматическом режиме. Об этом сообщает соответствующее предупреждение, которое выводится в форме сценария, при добавлении.

Ограничения при настройке сценария в облачном приложении:

■ нет возможности выбрать тип подключения;

■ обязательно нужно указывать действия на отправку и на получение данных;

■ минимальный интервал выполнения сценария – 15 мин, но он может быть автоматически скорректирован приложением в большую сторону, в зависимости от загрузки на сервере.

Подробнее о работе с журналом регистрации см. в разделе документации Настройки приложения.

Контроль зацикливания

Ранее, в разделе Общие рекомендации по синхронизации данных в двух приложениях, упоминалась ситуация, когда синхронизация может быть настроена по замкнутому кругу (зациклилась) и к какой негативной ситуации это может привести.

При использовании синхронизации через универсальный обмен данными (УОП) ситуация зацикливания контролируется автоматически (С версии БСД 1.0.2). Делается это за счет того, что вместе с сообщением обмена также передается информация обо всех настроенных обменах в приложении. Таким образом, каждая база «знает» полную схему синхронизации.

Как только будет определено, что возникло зацикливание, в приложении будет отключена регистрация объектов при получении данных. Регистрация будет отключена только в приложении, в котором впервые было обнаружено зацикливание.

Предупреждение о том, что произошло зацикливание, можно увидеть в нескольких местах:

■ На панели Текущие дела в главном окне приложения;

■ Непосредственно в форме настройки синхронизации.

■ В форме Настройки синхронизации данных над списком настроек синхронизаций.

Предупреждение, которое сообщает о зацикливании сопровождено двумя ссылками, которые позволяют:

■ Скрыть предупреждение, если настройки синхронизации не приводят к бесконечной миграции данных;

■ Перейти в форму Зацикливание синхронизации.

Если окно Зацикливание синхронизации было открыто в приложении-корреспонденте, то в нем будет только предупреждение о зацикливании и рекомендации по его устранению.

В форме Зацикливание синхронизации можно:

■ Отключить контроль либо для одного, либо для нескольких настроек. При отключении контроля хотя бы частично в списке настроек синхронизаций окно с предупреждением о зацикливании исчезает. При этом для настройки, у которой контроль зацикливания не был отключен, предупреждение остаётся непосредственно в форме настройке синхронизации;

■ Возобновить или приостановить регистрацию объектов, которые были получены при обменах;

■ Перейти к просмотру незарегистрированных данных, которые были получены при синхронизации;

■ Включить, отключить отображение предупреждения для всех пользователей;

■ Перейти в список незарегистрированных объектов.

Данные, не зарегистрированные при обмене

В ситуации зацикливания в приложении, в котором обнаружено зацикливание, автоматически отключается регистрация объектов метаданных, полученных при синхронизации для того, чтобы предотвратить дальнейшую миграцию полученных данных. О такой ситуации пользователь получает предупреждение. С помощью ссылки в форме зацикливания синхронизации можно перейти к списку объектов, не зарегистрированных при синхронизации.

Отключение контроля зацикливания

Возможны сценарии, когда контроль циклично настроенных синхронизаций не нужен. Например, фильтры выгрузки в настройках синхронизаций могут быть настроены так, что полученные при синхронизации данные не смогут зарегистрироваться дальше и выгружаться по кругу. В таком случае, есть возможность в пользовательском режиме отключить контроль зацикливания, а также скрыть предупреждение о зацикливании.

Важно! При отключении контроля зацикливания предупреждение об обнаружении зацикливания так же будет скрыто.

Отключить контроль зацикливания можно как из формы списка настроек синхронизации для всех настроек синхронизации, так и для конкретных настроек в форме необходимой настройки синхронизации.

Перейти к форме Зацикливание синхронизации, когда предупреждение скрыто или отключен контроль, можно из формы настройки синхронизации. Для этого нужно перейти в меню Еще, далее Предупреждение цикличности настроек обменов.

Включение отображения скрытых предупреждений выполняется в форме Зацикливание синхронизации из меню Ещё, далее Отображать предупреждение о зацикливании.

Список предупреждений по синхронизации данных

При выполнении синхронизации данных возможно возникновение проблемных ситуаций, требующих вмешательства пользователя.

Приложение предоставляет возможность:

■ расследовать проблемы в обмене данными;

■ исправлять ошибки в исходных данных, препятствующие выгрузке;

■ под свою ответственность включить обмен проблемными данными.

Результаты каждой синхронизации данных можно увидеть в списке Настройки синхронизации данных, например, на Начальной странице приложения в виде ссылок. В случае возникших в ходе синхронизации коллизий в ссылке указывается количество предупреждений (точный подсчет идет до 100, далее указывается более 100). Если синхронизация не состоялась, по ссылке можно перейти для просмотра проблем.

Список по конкретной синхронизации включает предупреждения всех типов. Если их много, для удобства имеются отборы по параметрам (для выбора параметра нажмите кнопку ). Подробнее см. раздел Отборы.

В списке выводится информация о предупреждениях и связанных с ними объектах приложения:

■ Признак наличия комментария – в колонке выводится значок , если в предупреждении заполнено поле комментарий.

■ Дата возникновения;

■ Описание – выводится сущность проблемы;

■ Тип – по этой колонке удобно сортировать предупреждения.

В список выведено минимальное количество полей, с помощью команды Еще – Изменить форму можно изменить список, добавить необходимые поля.

С помощью кнопок панели навигации в списке можно:

■ Обновить – список не является динамическим, поэтому для получения новых предупреждений нажмите кнопку;

■ Открыть объект – быстрый переход к объекту приложения – предмету предупреждения для исправления проблем;

■ Скрыть из списка – не показывать это предупреждение. Эта кнопка выключает видимость предупреждения в списке, при этом само предупреждение остается в приложении и к нему можно будет вернуться позже. Надо понимать, что проблема этим не решается, а игнорируется, откладывается «на потом».

С помощью кнопки Групповая обработка можно открыть выпадающее меню и выбрать нужную команду для быстрого решения проблем из нескольких однотипных предупреждений:

■ Проведение документов (подробнее см. раздел Непроведенные документы);

■ Групповое изменение реквизитов (применяется для исправления реквизитов при всех проблемах, подробнее см. раздел документации Групповое изменение объектов);

■ Коллизии (подробнее см. раздел Коллизии);

■ Запрет загрузки по дате (подробнее см. раздел Непринятые по дате запрета).

В контекстном меню списка по правой кнопке мыши можно найти дополнительные команды для работы со списком, например, можно:

■ Включить видимость ранее скрытых предупреждений с помощью команды Показать скрытые в списке – по этой команде скрытые предупреждения показываются серым цветом и неактивны.

■ Показать в списке – с помощью команды скрытые предупреждения становятся активными, с ними можно работать;

■ перейти в Журнал регистрации в указанное время. Эта команда применяется относительно текущей строки, а точнее Даты возникновения предупреждения, которая указана в текущей строке списка. При нажатии будет выведена информация о событиях, которые произошли по времени Даты возникновения (с точностью +-1 секунда от события) без отбора по типам события, т. е. пользователь увидит весь журнал за указанное время, в том числе и те процессы, которые происходили параллельно синхронизации. Это позволит проанализировать причины возникновения предупреждения.

Можно просмотреть информацию о предупреждении, дважды кликнув по нему. В карточке предупреждения указывается метод решения данной проблемы. В поле Объект выводится ссылка на документ или элемент списка, с которым связана проблема. По ссылке можно открыть проблемный объект приложения и попытаться исправить проблему: например, провести документ, заполнить недостающие обязательные реквизиты. После этого предупреждение автоматически удаляется из списка.

Также можно воспользоваться флажком Скрыть предупреждение, для того чтобы отложить решение проблемы на другое более удобное время.

С помощью ссылок в нижней части списка можно:

■ Перейти в журнал регистрации – просмотреть события данной синхронизации;

■ Произвести Удаление устаревших записей – если синхронизация проводится регулярно некоторое время, то накапливаются неактуальные или скрытые предупреждения. Их можно удалить.

При удалении предупреждений можно указать дополнительные параметры для отбора предупреждений с помощью кнопки :

■ Период – используется для отбора устаревших записей;

■ Синхронизации;

■ Тип.

С помощью флажка Только скрытые записи, которые удовлетворяют условиям выше можно дополнить отбор и удалить те предупреждения, которые были помечены как скрытые. Важно понимать, что команда Скрыть из списка только отключает видимость предупреждений, а команда Удаление устаревших записей физически удаляет предупреждения без возможности их восстановить. Поэтому рекомендуется использовать эту команду ответственно и вдумчиво, потому что удаление большей части предупреждений происходит автоматически при решении проблемы, а удаление предупреждений, связанных с коллизиями (непринятые данные по коллизии, принятые данные по коллизии) и датой запрета загрузки (объект существует, объект не существует в информационной в базе) приведет к удалению версий объектов (см. раздел также раздел документации Версионирование объектов).

При необходимости можно Показать скрытые в списке с помощью команды меню Еще.

Также ссылка Предупреждения при синхронизации данных предусмотрена в разделе Администрирование – Синхронизация данных (подробнее см. раздел Настройка приложения). Данная ссылка позволяет просмотреть полный список предупреждений синхронизации без каких-либо отборов. С помощью команды Еще – Предыдущая форма предупреждений можно открыть список предупреждений в прежнем виде.

Отборы

Для удобства просмотра предупреждений предусмотрены отборы:

■ Период – установите нужный, например, конкретную дату и время синхронизации;

■ Синхронизация – список является общим для всех синхронизаций, при переходе из списка синхронизаций включается отбор по выбранной синхронизации. При необходимости можно поменять значение с помощью флажков;

■ Тип – если список большой, можно выбрать предупреждения определенного типа.

Проблемные ситуации или предупреждения можно условно разделить на следующие типы:

■ Ошибка проверки перед отправкой (XDTO) – сведения о предупреждениях и ошибках при отправке данных (подробнее см. раздел Проблемы при отправке);

■ Непроведенные документы (подробнее см. раздел Непроведенные документы);

■ Незаполненные реквизиты (подробнее см. раздел Незаполненные реквизиты);

■ Конфликты (подробнее см. раздел Конфликты);

■ Непринятые по дате запрета (подробнее см. раздел Непринятые по дате запрета).

■ Ошибки кода обработчиков при отправке;

■ Ошибки кода обработчиков при получении, подробнее см. раздел ошибки кода обработчиков при отправке (получении).

Ошибка проверки перед отправкой (XDTO)

Сообщения об ошибках при отправке – ошибки проверки сконвертированного объекта дополнительно дублируются в журнале регистрации и говорят о том, что при попытке отправить данные приложения обнаружила пустые сведения, которые обязательно должны быть заполнены, например, документ Демо: Счет на оплату покупателю с пустой суммой.

В предупреждении предлагается расшифровка проблемы и ссылка на объект приложения, при конвертации которого обнаружены пустые сведения. При переходе в объект, как правило, можно разобраться в причинах проблемы, но стоит заметить, что такая возможность иногда отсутствует, т. к. есть данные, которые вычисляются динамически или по умолчанию не отображаются. В таких случаях рекомендуется обратиться к администратору приложения.

Если предупреждений конвертации объекта при отправке по одному справочнику несколько, можно выделить их в списке и отработать с помощью кнопки Групповая обработка - Групповое изменение реквизитов.

Непроведенные документы

В ходе синхронизации могут возникать предупреждения о документах, которые не удалось провести по каким-либо причинам.

Для решения проблемы с проведением документа рекомендуется открыть карточку предупреждения, перейти по ссылке в документ и устранить недочеты, мешающие его проведению (это может быть, например, недостаточный остаток по товару), а после этого провести. При проведении предупреждение автоматически будет удалено из списка.

Также можно воспользоваться групповым проведением документов из меню Групповая обработка. Сценарий работы может быть, например, такой: администратор или продвинутый пользователь при помощи групповой обработки в режиме технического специалиста исправляет ряд однотипных проблем (например, можно использовать команду Групповое изменение реквизитов), а после этого проводит несколько выделенных документов из списка предупреждений.

Незаполненные реквизиты

Предупреждения этого типа означают, что при получении данных были записаны объекты, но в этих объектах (документы, списки и т. д.) остались пустые реквизиты.

Для исправления необходимо открыть элемент списка (это можно сделать, нажав кнопку Открыть объект или из карточки предупреждения с помощью ссылки) и заполнить обязательные для заполнения поля, затем сохранить изменения. При записи элемента предупреждение будет автоматически удалено.

Для того чтобы попытаться отработать несколько предупреждений и заполнить реквизиты в выбранных элементах одного списка, нажмите кнопку Групповая обработка – Групповое изменение реквизитов. Подробнее см. раздел документации Групповое изменение объектов.

Коллизии

При настроенной синхронизации данных между двумя приложениями возникают ситуации, когда одни и те же данные изменяются одновременно (в промежуток между выполнением сеанса синхронизации данных) в двух приложениях. Это приводит к возникновению двух различающихся версий одинаковых данных в этих приложениях. Такая ситуация называется конфликтом изменения данных.

Конфликты изменения данных разрешаются (выбирается одна из версий) автоматически, однако можно изменить результат автоматического разрешения конфликта.

В карточке предупреждения подробно описывается суть проблемы, выводится ссылка на объект приложения, по которому произошла коллизия. Можно перейти по ссылке и проконтролировать правильность заполнения реквизитов после автоматического разрешения конфликта.

Можно сравнить две версии данных с помощью кнопки Показать отличия.

Для принятия решения, какую версию оставить, можно просмотреть обе версии. Для этого предусмотрены кнопки Показать версию в том приложении или Показать версию из другого приложения.

После принятия решения о версии, которая должна быть сохранена, нажмите кнопку Скрыть из списка для сохранения результата автоматического разрешения конфликта или кнопку Пересмотреть результат для изменения результата рассмотрения конфликта на противоположный.

Можно также воспользоваться кнопкой Групповая обработка – Коллизии и работать в списке с выделенными предупреждениями.

Непринятые по дате запрета

В этих предупреждениях выводятся сведения о данных, которые были отклонены из-за установленного запрета на загрузку данных прошлых периодов. Подробнее см. раздел документации Даты запрета изменения.

В карточке предупреждения имеются рекомендации по устранению проблемы.

По ссылке можно открыть объект приложения и посмотреть, правильно ли заполнены реквизиты в результате автоматического решения проблемы.

Для сравнения отклоненных данных с текущими данными в приложении нажмите кнопку Показать отличия (при наличии данных в текущем приложении).

С помощью кнопки можно Показать версию этого приложения.

Для просмотра другой версии нажмите кнопку Показать непринятую версию.

Для получения данных несмотря на установленный запрет загрузки данных можно нажать кнопку Принять отклоненную версию.

С помощью кнопки Групповая обработка – Запрет загрузки по дате можно отработать несколько предупреждений.

Для групповой обработки предусмотрены кнопки:

■  Принять версию – будет принята выделенная версия.

■ С помощью кнопки Показать отличия можно изучить обе версии данных для принятия решения.

С помощью кнопки Открыть объект можно просмотреть документ или элемент списка.

Ошибки кода обработчиков при отправке (получении)

В карточке предупреждения обработчиков отправки/получения указывается, что были обнаружены ошибки в коде правил конвертации объектов.

Указываются пути решения проблемы:

■ обновиться на актуальную версию приложения;

■ использовать актуальные правила конвертации (подробнее см. раздел Контроль актуальности типовых правил обмена).

Ошибки обработчиков выделяются в списке красным цветом. Предполагается, что они будут исправлены продвинутыми пользователями, администраторами, или разработчиками.

Состав отправляемых данных

Приложение позволяет администратору проанализировать отправляемые данные для последующей отправки данных при синхронизации в другие приложения и при необходимости внести некоторые изменения в их состав. С помощью списка Регистрация изменений для обмена производится выборочная регистрация изменений данных в приложении.

Список Регистрация изменений для обмена можно открыть по кнопке  или по команде Еще – Состав отправляемых данных из списка Настройки синхронизации данных.

С помощью кнопки  Дополнительная информация можно просмотреть информацию о том, как настроена выборочная регистрация. Правила выборочной регистрации может изменить только разработчик. См. также раздел Выборочная регистрация объектов.

В приложении ведется регистрация номеров сообщений. Нажмите на ссылку с номерами сообщений, для того чтобы просмотреть их или исправить.

В списке можно произвести отбор изменений.

В поле Отображать выберите нужное значение из списка:

■ все;

■ только выгруженные;

■ только невыгруженные.

Список состоит из двух частей:

1. левая часть состоит из двух колонок:

■ объект конфигурации – перечислены объекты приложения (справочники, документы и т. д.) в виде дерева;

■ количество – количество зарегистрированных измененных (или вновь введенных) / не выгруженных элементов в этих объектах;

2. правая часть меняется в зависимости от выделенного объекта в левой части:

■ по выделенной группе объектов в колонке Описание приводится подробное описание статистических данных левой части;

■ по выделенному объекту приложения правая часть делится на две колонки:

■ наименование конкретного объекта (например, Демо: Договор контрагента) – приводится перечень всех измененных и не выгруженных элементов списка;

■ № отправленного – номер сообщения, в котором отправлены измененные элементы списка (указывается номер сообщения или выводится Не выгружалось).

Измененные, удаленные и вновь вводимые объекты приложения регистрирует автоматически.

Для ручной регистрации объектов выберите объект (тип объектов) в дереве с помощью флажков, нажмите Зарегистрировать:

■ все объекты выбранных типов – можно выбрать объект и все его подчиненные объекты;

■ объекты выбранных типов с авторегистрацией;

■ одиночный объект (выберите из списка объект или создайте новый);

■ объекты при помощи отбора (задайте отбор, отберите нужные элементы);

■ результаты запроса (предварительно настройте параметры регистрации изменений объектов с помощью команды Еще – Настройки).

Для того чтобы отменить отправку всех данных, приготовленных для других приложений, в дереве объектов выделите корень (информационную базу) и нажмите кнопку Отменить регистрацию (выбор объектов для отмены аналогичен предыдущему).

Для того чтобы настроить параметры регистрации изменений объектов, нажмите Еще – Настройки. Можно настроить параметры авторегистрации, установить номер сообщения при регистрации, при необходимости указать путь к каталогу консоли запросов.

С помощью флажков можно включить Авторегистрацию:

■ движений вместе с документами;

■ последовательностей вместе с документами.

С помощью переключателя можно настроить Установку номера сообщения при регистрации:

■ регистрировать как неотправленные;

■ использовать номер сообщения узла обмена.

Для использования Консоли запросов переключатель установите в положение В каталоге, укажите путь к консоли запросов с помощью кнопки . Если она не нужна, переключатель установите в положение Не использовать.

Включите флажок, для того чтобы Использовать Библиотеку стандартных подсистем при регистрации изменений объектов ограничения миграции данных.

Для того чтобы настройки вступили в силу, нажмите Записать.

Для того чтобы просмотреть результат стандартной выгрузки (РИБ), выделите объект, по которому зарегистрированы изменения, в левой части списка, при этом в правой части появляется список элементов. Выделите нужный элемент, нажмите кнопку  Показать результат выгрузки или Еще – Стандартный результат выгрузки (РИБ). Подробнее о РИБ см. раздел Синхронизация данных в распределенной информационной базе.

Настройка синхронизации с порционной отправкой данных

В приложении предусмотрена возможность порционной отправки данных. Такая возможность может быть востребована, например, при первоначальной настройке обмена, если обмен данных производится в приложении в Интернете и нужно синхронизировать большой объем данных, например, в приложении-источнике введено много нормативно-справочной информации.

Процесс настройки синхронизации (подробнее см. раздел Синхронизация данных между разными приложениями) в этом случае состоит из нескольких последовательных этапов:

1. Настройка подключения (подробнее см. раздел Выбор варианта подключения) – здесь задаются параметры подключения к базе-корреспонденту. Для приложения в Интернете – выбор приложения из списка доступных или (доп. опция для обмена через EnterpriseData) через указание url приложения, ввод логина и пароля.

2. Настройка правил отправки и получения данных (подробнее см. раздел Применение правил синхронизации данных) – указываются правила регистрации данных для выгрузки, и заполняются (при их наличии) значения по умолчанию, используемые при получении данных. После выполнения данного этапа настройка синхронизации считается завершенной. Можно завершить настройку и выйти из помощника.

Обычно для настройки обмена данными между двумя приложениями далее следует этап 3:

3. Первоначальная выгрузка данных для сопоставления (применяется для обмена данными между двумя приложениями, подробнее см. раздел Начальная выгрузка для сопоставления данных).

Для того чтобы выполнить порционное сопоставление, необходимо пропустить 3-й этап, далее в списке Настройки синхронизации данных (подробнее см. раздел Изменение настройки синхронизации данных):

■ выполнить ручную регистрацию порции данных к обмену с помощью кнопки  Состав отправляемых данных, подробнее см. раздел Состав отправляемых данных);

■ выполнить команду Выгрузка данных для сопоставления меню Еще, в режиме Выгрузить только зарегистрированные к обмену данные (если предварительно произведена регистрация порции, то этот режим включается по умолчанию). Нажмите кнопку Далее.

Будет выгружена зарегистрированная порция данных.

Далее можно перейти в приложение-корреспондент, открыть в ней список Настройки синхронизации данных. Найти нужную настройку синхронизации (она перейдет в состояние Получены данные для сопоставления), выделить ее. Нажать кнопку Синхронизировать. Будет выполнен анализ полученных данных, станет доступным выполнение интерактивного сопоставления. Подробнее см. разделы Список Настройки синхронизации данных, Выполнение синхронизации данных при необходимости (интерактивно).

Можно повторить регистрацию данных и выгрузку столько раз, сколько это потребуется.

Регистрация данных к обмену с помощью Консоли запросов.

Если в состав конфигурации включена типовая обработка Консоль запросов, то у пользователя (администратора) появляется возможность зарегистрировать набор данных, выполнив произвольный запрос. Фактически функциональность регистрации из консоли запросов похожа на регистрацию данных по отбору, но предоставляет более широкие возможности в части определения условий.

Для включения регистрации данных по запросу необходимо в настройках регистрации перейти в меню Ещё, далее Настройки, где включить опцию В составе конфигурации.

Описание шагов регистрации данных из консоли запроса.

Для того, чтобы зарегистрировать данные с помощью Консоли запросов, рекомендуется выполнить следующие шаги:

1. Вызвать Консоль запросов в форме регистрации данных к обмену. Для этого необходимо перейти по кнопке Зарегистрировать в Результаты запроса.

2. Далее в открывшейся консоли появится команда Выполнить выбор результата запроса, а затем в поле Текст запроса написать произвольный запрос, результатом которого должно быть поле Ссылка с типом метаданных, которые входят в состав плана обмена.

3. Далее выполнить запрос. При выполнении запроса и передачи результата в обработку регистрации будет произведена попытка зарегистрировать данные на узле плана обмена согласно содержимому запроса.

Важно! Консоль запросов – достаточно сложный инструмент, предназначенный для администратора, либо разработчика. Даже продвинутому пользователю проще регистрировать данные с помощью отборов, чем писать запросы.

Удаление настройки синхронизации данных

Возникают ситуации, когда необходимо удалить существующую настройку синхронизации данных. Например, вторая база-корреспондент была удалена, и надо создать новую настройку синхронизации данных, или изменяется топология синхронизации и надо выполнять настройку синхронизации данных заново. Также имеет смысл удалить настройку и начать ее заново, если в процессе возникли проблемы.

Удаление производится следующим образом:

1. в списке Настройки синхронизации данных выделите удаляемую настройку и выполните команду Еще – Удалить настройку синхронизации. Если настройка в списке одна, нажмите кнопку Удалить эту настройку синхронизации;

2. подтвердите свой выбор. В ответ на вопрос приложения нажмите кнопку Да;

3. при необходимости повторите этот сценарий удаления во всех приложениях, участвовавших в синхронизации данных.

Если удаление настройки синхронизации данных не удалось (например, введены сценарии синхронизации данных и приложение из-за этого не может удалить настройку), то сначала следует произвести подготовительные действия:

4. Удалите связи этой настройки с другими элементами – сценариями синхронизации данных. Подробнее о сценариях синхронизации данных см. раздел Автоматическое выполнение синхронизации данных по расписанию.

■ В списке Настройки синхронизации данных выделите удаляемую настройку и выполните команду Еще – Сценарии синхронизации данных;

■ В окне Сценарии синхронизации данных исключите удаляемую настройку синхронизации данных из всех сценариев синхронизации данных с помощью кнопок Включить/Отключить.

После этого повторите удаление синхронизации данных.

Роли для синхронизации данных

Для работы с синхронизацией данных необходимо назначить одну или комбинацию из следующих ролей:

Роль

Краткое описание

Выполнение синхронизации данных

Дает право запускать синхронизацию данных вручную, осуществлять мониторинг синхронизации данных.

Полный доступ ко всем операциям. Позволяет также удалять настройки, помеченные на удаление, включать и выключать использование синхронизации данных.
