# Эксперт по БСП

Skill `bsp-consultant` предназначен для разработчика, который пишет код самостоятельно и хочет получить проверенную консультацию по БСП без изменения проекта агентом.

## Примеры вопросов

- Какой механизм БСП использовать для хранения адреса и телефона контрагента?
- Как программно добавить файл к объекту?
- Чем отличаются два метода программного интерфейса?
- Какие ограничения и устаревшие параметры есть у метода?
- Как выбранный метод используется в демо-конфигурации?

Навык можно вызвать явно как `$bsp-consultant` или обычным вопросом о выборе и применении API БСП. Для задач, где нужно изменить конфигурацию или написать BSL-код, используется отдельный skill `bsp-development`.

## Как формируется ответ

Для известного метода помощник сразу находит его нормативную документацию. Для вопроса о требуемой возможности он последовательно выбирает подсистему, группу программного интерфейса и метод. Неоднозначное ранжирование документации может быть передано read-only субагенту; основной ответ получает только краткую рекомендацию.

Демо-конфигурация исследуется по запросу примера либо когда одной документации недостаточно для корректного объяснения. Помощник читает содержащую вызов процедуру и необходимые callbacks, клиент-серверные переходы и файлы управляемой формы. Демо считается примером реализации, а не нормативным контрактом.

## Версия БСП

Если доступен проект, помощник определяет его версию БСП автоматически. Можно также указать версию в вопросе. Если версия неизвестна, ответ по последней установленной документации считается ориентировочным, а сделанное предположение указывается явно.

## Формат результата

Ответ начинается с рекомендуемого механизма или прямого ответа и при необходимости содержит:

- полное имя API;
- назначение и условия применения;
- параметры, ограничения и предупреждения;
- небольшой адаптированный пример;
- путь к реализации в демо;
- оставшуюся неопределённость.

Сырые результаты поиска, полные навигационные карты и страницы документации в ответ не включаются.
