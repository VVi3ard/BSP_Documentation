5.37 Обновление конфигурации

Можно обновлять приложение, установить исправление (патч) в режиме 1С:Предприятия. Обновление производится по требованию или в указанное время. Обновление приложения доступно только пользователю с ролью Администратор системы.

Для обновления приложения (установки исправлений) можно воспользоваться помощником, который открывается с помощью ссылки Установка обновлений и исправлений (патчей) раздела Администрирование – Обслуживание – Обновление приложения. Помощник установки обновлений позволяет провести обновление из файла в локальном или сетевом каталоге (например, с диска 1С:ИТС).

Внимание! Помощник не следует использовать, если в приложении включена возможность изменения объектов метаданных. В таких случаях рекомендуется выполнять обновление в Конфигураторе. Подробнее см. книгу «1С:Предприятие 8.3. Руководство разработчика».

Если в приложении имеются расширения, об этом выводится сообщение. Необходимо учитывать, что расширения могут быть несовместимы с новой версией приложения. Можно предварительно выполнить обновление на резервной копии, для того чтобы проверить их совместимость. По ссылке можно Перейти к списку расширений (подробнее о списке см. раздел документации Базовая функциональность).

С помощью ссылки Установка обновлений и исправлений (патчей) можно обновить приложение несколькими способами:

■ Файл обновления не требуется – данный способ позволяет продолжить обновление, воспользовавшись файлом, уже загруженным в приложение (подробнее см. раздел Обновление конфигурации из файла на компьютере);

■ Укажите файл обновления или исправлений – можно указать имеющийся на компьютере файл обновления или исправлений (подробнее см. раздел Обновление конфигурации из файла на компьютере);

■ Поиск и установка обновлений – с помощью ссылки можно перейти к поиску обновления в Интернете. Примечание для технического писателя: функция доступна, если в приложении подключена https://its.1c.ru/db/uisldoc.

Обновление приложения из файла на компьютере

Приложение позволяет выбрать для установки файл обновления на новую версию или исправление (несколько исправлений). При этом ведется список установленных обновлений (исправлений). Подробнее см. раздел Установка исправлений (патчей).

В случае если файл обновления уже имеется, то помощник позволяет провести обновление с использованием файла поставки обновления (.cfu), файла исправления (.cfe или .zip), или файла поставки (.cf) из локального или сетевого каталога.

Если файл обновления уже загружен в основную конфигурацию, и она отличается от конфигурации информационной базы, то необходимо выбрать вариант обновления Файл обновления не требуется. Эта возможность может быть востребована, например, если администратор загрузил файл обновления, но в приложении в тот момент еще работали пользователи, и обновление пришлось запланировать на другое более подходящее время, например, на ночь.

Приложение определяет необходимость обновления. Если обновление не требуется, об этом выводится сообщение.

С помощью ссылки Поиск и установка обновлений можно проконтролировать необходимость обновления приложения и наличие обновлений приложения и платформы на сайте 1С. Примечание для технического писателя: автоматическая загрузка патчей доступна, если в приложении подключена 1С:Библиотека Интернет-поддержки.

Если файл обновления еще не загружен в приложение, с помощью переключателя Укажите файл обновления, для этого нажмите кнопку . Выберите файл на компьютере, например, C:\Обновления\Обновление10.cf.

Для продолжения нажмите кнопку Далее. Приложение выводит предупреждение безопасности. Если обновление получено из надежного источника, нажмите кнопку Продолжить.

Приложение анализирует файл обновления, и если он не подходит (файл поставки от другой версии или от другого приложения), то об этом выводится предупреждение. Нажмите Закрыть. В этом случае следует найти нужный файл и повторить попытку обновления.

Если указан файл с подходящей версией обновления, после подтверждения легальности его получения приложение предложит установить обновление (подробнее см. раздел документации Проверка легальности получения обновлений).

Установка обновления выполняется от имени текущего пользователя. При необходимости введите Параметры администрирования приложения – Имя пользователя и Пароль, если для доступа к приложению необходима авторизация. В случае клиент-серверного варианта работы приложения также может потребоваться ввести имя и пароль администратора кластера серверов.

Требуется с помощью переключателя уточнить время обновления приложения:

■ Установить обновление прямо сейчас – для обновления потребуется перезапустить приложение;

■ Напомнить при завершении работы;

■ Запланировать установку обновления на указанное время – в клиент-серверном варианте работы приложения есть возможность указать время и дату обновления.

■ Также во время работы в клиент-серверном варианте есть возможность уведомить пользователей о планируемом обновлении заранее, чтобы все успели выйти из приложения. С помощью флажка Уведомлять пользователей о планируемом обновлении можно предупредить пользователей, например, за 5 минут до планируемого обновления.  

Важно! Данная опция не применима, если на время обновления вручную планируется установка блокировки работы пользователей.

Для отправки отчета об успешном или неуспешном выполнении обновления по почте нужно установить флажок Выслать отчет на почту и в поле указать адрес электронной почты. Отправка сообщения производится с устройства, на котором установлен сервер 1С:Предприятие.

Перед началом обновления версии приложения рекомендуется создавать резервную копию приложения. Резервная копия используется для автоматического восстановления приложения в случае нештатной ситуации. Подробнее см. раздел документации Резервное копирование ИБ.

В клиент-серверном приложении рекомендуется создать резервную копию средствами СУБД.

К настройке автоматического создания резервной копии в файловом варианте работы можно перейти по ссылке Создавать временную резервную копию ИБ и выполнять откат при нештатной ситуации.

Для создания резервной копии выберите параметры (подробнее см. раздел документации Резервное копирование):

■ Не создавать резервную копию. Если для резервного копирования используются сторонние средства, то можно отключить автоматическое создание резервной копии. Создать резервную копию можно и другими средствами, например, путем копирования файла приложения;

■ Создать временную резервную копию (установлено по умолчанию). В этом случае копия создается во временной папке, т. е. в папке Тemp, и автоматически будет удалена Windows;

■ Включите флажок Восстанавливать информационную базу (установлен по умолчанию, рекомендуется), для того чтобы можно было осуществить откат в случае возникновения нештатной ситуации при обновлении приложения;

■ Создать резервную копию и сохранить в указанном каталоге, например, C:\Резервное копирование. В этом случае откат к резервной копии при возникновении нештатной ситуации будет выполнен автоматически. Подробнее см. раздел документации Резервное копирование.

После установки параметров резервного копирования нажмите ОК для возврата к установке обновления.

Прежде чем продолжить обновление, необходимо сохранить несохраненные данные или закрыть окна их редактирования.

В клиент-серверном варианте работы приложения все соединения будут завершены автоматически, а на время создания резервной копии и обновления устанавливается блокировка соединений.

Для файлового варианта работы необходимо выполнить следующие действия:

■ Если открыт Конфигуратор, то необходимо его закрыть (приложение выводит сообщение);

■ Завершить работу пользователей. Для того чтобы проконтролировать текущие сеансы, перейдите по ссылке Посмотреть список активных пользователей. Подробнее см. раздел документации Завершение работы пользователей;

■ Если к приложению подключены другие приложения с помощью внешнего соединения, то необходимо завершить их работу.

Если все указанные условия выполнены, после нажатия кнопки Далее приложение автоматически создаст резервную копию ИБ (если это предусмотрено) и установит обновления.

Процесс обновления приложения может занять продолжительное время в зависимости от производительности компьютера и объема информационной базы. Не выключайте питание компьютера до завершения процесса. После завершения обновления приложение будет автоматически запущена и готова к дальнейшей работе.

Если был выбран вариант Напомнить при завершении работы, то автоматического запуска приложения не происходит.

Для базовых версий после обновления требуется выполнить первый запуск приложения от имени администратора, во время которого будет выполнено завершение процесса обновления приложения.

Помощник выводит сообщение об успешном завершении обновления приложения. Нажмите кнопку Готово, для того чтобы приступить к работе в приложении.

Клиент-серверный вариант работы приложения

В клиент-серверном варианте работы приложения можно задавать отложенное по времени обновление, например, можно отложить обновление приложения на ночь.

Для этого при обновлении в помощнике выберите с помощью переключателя Запланировать установку обновления на указанное время и укажите время и дату обновления.

При обновлении, если отложенные обработчики не завершились, например, произошла проблема при выполнении одного из обработчиков или были заблокированы регламентные задания, то необходимо сначала завершить обновление, а после выполнить очистку устаревших данных перед обновлением конфигурации.

Существует возможность настроить отправку отчета на указанный адрес электронной почты об успешном или неуспешном выполнении обновления. Отправка сообщения производится с компьютера, на которой установлен сервер 1С:Предприятие. Для этого включите флажок Выслать отчет на почту, напишите адрес электронной почты.

Запланированное обновление будет выполнено с клиентского компьютера в фоне. Питание компьютера должно быть включено в указанную дату и время.

Установка исправлений (патчей)

Исправление (патч) позволяет оперативно исправлять ошибки в приложении, не дожидаясь следующего исправительного релиза. Установка патчей также не требует обязательного завершения сеансов пользователей, работающих с приложением: для применения исправлений достаточно перезапустить приложение в удобный момент времени.

Технически, патч – это особым образом подготовленное расширение конфигурации, которое локально вносит необходимое изменение в код без установки монопольного режима, контролирует применимость, а также автоматически удаляется при установке нового релиза (в котором данное исправление уже включено). Подробнее о расширениях см. раздел документации Базовая функциональность.

Автоматическая установка патчей

Загрузка и установка патчей выполняется автоматически при наличии подписки 1С:ИТС и доступа к сети Интернет (рекомендуется).

Для настройки автоматической загрузки необходимо перейти в раздел Администрирование – Интернет-поддержка и сервисы, найти раздел Обновление версии приложения и включить флажок Загружать и устанавливать исправления (патчи) автоматически. Потребуется подключение Интернет-поддержки.

Примечание для технического писателя: автоматическая загрузка патчей доступна, если в приложении подключена Библиотека интернет-поддержки

Установка патчей из каталога на устройстве

В некоторых случаях также может потребоваться ручная установка исправлений (патчей). Например, если на компьютере не доступен Интернет, но есть возможность приносить патчи на съемном USB –носителе или другим способом. Для этого заранее необходимо скачать патч с сайта 1С:ИТС (releases.1c.ru). На сайте 1С:ИТС можно прочитать, какую ошибку каждый патч исправляет.

Для этого необходимо:

1. Загрузить архив с патчами с сайта для интересующей версии приложения;

2. Распаковать загруженный архив в произвольный каталог на устройстве;

3. В приложении перейти в раздел Администрирование – Обслуживание – Обновление приложения;

4. Перейти по ссылке Установка обновлений и исправлений (патчей), выбрать способ обновления Укажите файл обновления или исправлений, указать ранее распакованные файлы и нажать Далее.

5. После установки патчей перезапустить сеанс, для того чтобы они применились.

Установленные патчи можно увидеть в списке в разделе Администрирование – Обновление приложения – Обслуживание, подробнее см. раздел Список установленных исправлений (патчей).

Список установленных исправлений (патчей)

Установленные исправления (патчи) можно просмотреть по ссылке в разделе Администрирование – Обслуживание – Обновление приложения.

В списке с помощью кнопок панели навигации можно:

■ Установить исправление – открывается помощник Установка обновлений. Подробнее см. раздел Обновление приложения из файла на компьютере;

■ Удалить исправление, если установленное исправление (патч) по каким-либо причинам не устраивает.

С помощью кнопки Выгрузить подключенные исправления можно выгрузить установленные исправления в каталог на устройстве.

Если после установки исправлений (патчей) не перезагрузить приложение, то будут выходить оповещения (если включен сервис Обсуждения) об установленных обновлениях приложения. Уведомления получат все пользователи, которые работают с приложением.

В окне выводятся первые 5 исправлений (патча) с описанием, также можно перейти ко всем исправлениям (патчам), нажав ссылку Подробнее.

С помощью флажков выберите, когда можно применить исправления, например, в указанное время 23:00.

Также можно настроить напоминания о новых исправлениях, по умолчанию, один раз в день.

Предварительная проверка патчей перед установкой

Если установлена доработанная типовая или нетиповая конфигурация, то патчи с сайта releases.1c.ru могут к ней не подойти или работать некорректно. В таких случаях рекомендуется отключить автоматическую установку патчей и предварительно проверять их на копии приложения перед установкой в рабочую информационную базу. Этот регламент рекомендуется ввести также в тех случаях, если ранее было принято выполнять предварительную проверку новых релизов конфигурации на копии рабочей базы:

1. Скачать архив с патчами с сайта, сохранить в каталог на устройство. На сайте можно прочитать, какую ошибку исправляет каждый патч.

2. В копии приложения загрузить архив с патчами с сайта для вашей версии приложения (пошаговую инструкцию см. в разделе Установка патчей из каталога на устройстве).

3. Проверить работоспособность копии приложения и затем отключить патчи, не прошедшие проверку, в списке Установленные исправления (патчи) из раздела Администрирование - Обновление приложения – Обслуживание с помощью кнопки Удалить исправление.

4. Выгрузить проверенные патчи из копии приложения в каталог на устройстве. Для этого в списке Установленные исправления (патчи) выделить нужные патчи и в подменю Еще нажать Сохранить как.

5. В рабочем приложении перейти в список Установленные исправления (патчи) и выбрать к установке патчи из указанного каталога.

Действия в случае проблем обновления

Для получения технической информации о причинах проблем с установкой обновлений можно воспользоваться следующими средствами:

■ Записи о произведенных операциях и возникших проблем в ходе обновления заносятся в Журнал регистрации (тип события Обновление информационной базы). Воспользуйтесь ссылкой Журнал регистрации, для того чтобы просмотреть технические подробности;

■ В процессе установки обновления во временной папке текущего пользователя Windows создается лог-файл с записями о ходе обновления (содержимое лог-файла впоследствии автоматически добавляется в Журнал регистрации). Последний из каталогов вида %temp%\1CUpdate.<набор цифр>, отсортированных по алфавиту, соответствует последней сессии обновления;

■ Если настройка операционной системы Язык приложений, не поддерживающих Юникод задана некорректно, то процесс обновления завершится с ошибкой invalid procedure call or arguments, при этом лог-файл окажется пустым. Для устранения данной проблемы необходимо, чтобы в региональных настройках операционной системы (Панель управления - Язык и региональные стандарты – Дополнительно) в поле Язык приложений, не поддерживающих Юникод был выбран русский язык;

■ Результат обновления приложения записывается в Журнал событий Windows (Event Log).

Если в результате нештатной ситуации при обновлении приложение оказалось заблокированным, то его можно разблокировать с помощью консоли Администрирование серверов 1С:Предприятия, либо из командной строки, запустив 1С:Предприятие от имени администратора с ключом РазрешитьРаботуПользователей и указав код разблокировки ПакетноеОбновлениеКонфигурацииИБ. Например:

"C:\Program Files\1cv8\8.3.9.2033\bin\1cv8.exe" ENTERPRISE /S"server\base" /N"Администратор" /P"" /WA- /CРазрешитьРаботуПользователей /UCПакетноеОбновлениеКонфигурацииИБ

Если обновление приложения завершилось неудачей, а во временном log-файле имеется запись: Исключение в createConnection: Error, Automation server can't create object, то, скорее всего, используется 32-разрядная компонента comcntr.dll на компьютере под управлением 64-разрядной операционной системы. Для устранения данной проблемы необходимо взять 64-разрядную компоненту comcntr.dll из поставки 1С:Предприятие x64 Сервер и зарегистрировать ее, запустив из командной строки:

regsvr32 <каталог 64-разрядного comcntr.dll>\comcntr.dll

Выяснив причины проблемы, произведите соответствующие настройки компьютера, затем нажмите Далее для повторения попытки.
