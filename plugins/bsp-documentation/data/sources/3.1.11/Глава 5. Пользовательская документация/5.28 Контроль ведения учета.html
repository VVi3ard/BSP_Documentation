Оглавление

5.28 Контроль ведения учета

Приложение позволяет автоматически контролировать корректность данных приложения (например: нарушение ссылочной целостности, отрицательные остатки в регистре накопления, сбой в нумерации счетов фактур и т. д.) по произвольным правилам.

По результатам проведенных проверок в отчете Контроль ведения учета выводится описание выявленных проблем и способов их устранения. При этом результаты проверки могут выводиться «адресно» ответственным исполнителям из окна «проблемного» документа, из списков документов, а также в списке Текущие дела на начальной странице (подробнее см. раздел документации Текущие дела).

Контроль ведения учета состоит из двух этапов:

■ Настройка параметров и расписания выполнения проверок проводится администратором или ответственным с ролью Полные права, см. раздел Правила проверки учета;

■ Просмотр результатов проверки и корректировка данных, проводится ответственными исполнителями, см. раздел Работа с выявленными проблемами.

Правила проверки учета

Для настройки правил проверки учета воспользуйтесь ссылкой Правила проверки учета в разделе Администрирование – Обслуживание – Корректировка данных. Открывается список, в котором представлены все имеющиеся правила проверок данных приложения. Подробнее см. раздел Возможности проверок ведения учета. Также предусмотрена проверка контактной информации, подробнее см. раздел Проверка контактной информации. Далее рассмотрим настройки, общие для всех проверок. Для администраторов: информация о критичных проблемах записывается в журнал регистрации со статусом Ошибка.

По умолчанию все проверки, предусмотренные в приложении, уже включены, а часть из них выполняется автоматически в фоне по общему расписанию: каждый день; с 20:00:00 по 08:00:00 один раз в день. При необходимости изменить общее расписание перейдите по ссылке в нижней части окна. Подробнее см. раздел документации Регламентные задания. В редких случаях может возникнуть необходимость перенастроить конкретную проверку, например, одну из проверок проводить по индивидуальному расписанию. В этом случае нужно открыть ее карточку.

Если проверку в данный момент не нужно проводить, ее можно отключить с помощью флажка Использование.

На вкладке Параметры проверки описываются:

■ Причины проблемы (причина возникновения проблемы, которая определяется данной проверкой, например, для проверки Поиск ссылок на несуществующие файлы в томах хранения выводится Файл был физически удален… и т. д.);

■ Рекомендация по ее устранению.

Эта информация будет выводиться в отчете Контроль ведения учета со списком проблем, выявленных этим правилом проверки (подробнее см. раздел Отчет Контроль ведения учета).

По полю Важность проблемы можно будет в дальнейшем отфильтровать результаты проверок, кроме этого, в зависимости от важности можно по-разному поступать с ними:

■ Информация – просмотреть и принять к сведению;

■ Предупреждение – рекомендация по исправлению приложения;

■ Ошибка (по умолчанию) – может привести к серьезным последствиям и подлежит исправлению;

■ Полезный совет – рекомендация по совершенствованию приложения;

■ Важная информация – просмотреть и запомнить.

Содержание перечисленных полей только для просмотра, вносить в них правки рекомендуется только в крайнем случае:

■ например, разработчик приложения обнаружил и другие причины проблемы, или методы ее устранения и может привести их в соответствующих полях;

■ в настоящее время исправление конкретной ошибки не так актуально и можно просто принять ее к сведению (информация или полезный совет), а исправить, когда будет время.

Для того чтобы проверка проходила в автоматически, включите флажок Выполняется в фоне по расписанию.

С помощью переключателя можно указать параметры проведения автоматической проверки:

■ По общему расписанию (выбрано по умолчанию);

■ По индивидуальному расписанию – после выбора становится доступной ссылка Настроить индивидуальное расписание. Подробнее см. раздел Регламентные задания.

Примечание: при работе в приложении в Интернете настройка расписания недоступна (ни общая, ни индивидуальная).

В поле Комментарий можно написать дополнительную информацию о проверке.

С помощью кнопки Выполнить проверку можно провести проверку вручную в нужный момент. Подробнее см. раздел Выполнение проверок вручную.

С помощью кнопки Отчеты – Результаты проверки учета можно открыть отчет Контроль ведения учета, для того чтобы просмотреть результаты проведенных проверок. Подробнее см. раздел Отчет Контроль ведения учета.

На вкладке Дополнительно указываются следующие параметры проверки:

■ Дата начала проверки – для документов и других объектов приложения, привязанных к временной оси, имеется возможность задания пороговой даты. Например, это полезно для того, чтобы не выполнять проверки в уже закрытых или архивных периодах. По умолчанию эта дата не заполнена, т. е. проверяется все.

■ Лимит проблем – предусмотрена возможность наложить ограничения на количество проблем, выявляемых конкретной проверкой. Например, проверка заполнения обязательных реквизитов в списке с большим количеством элементов может быть ограничена определенным лимитом выводимых проблем (указывается в каждой проверке по умолчанию, например, для проверки Поиск ссылок на несуществующие файлы в томах хранения равно 1000).

Выполнение проверок вручную

Часть проверок проводится автоматически по расписанию, в фоне.

Однако при необходимости можно также произвести проверку в любой момент вручную. Для этого выделите в списке нужные проверки, нажмите кнопку Выполнить проверку. Также предусмотрена кнопка Выполнить все. Подтвердите проведение проверки с помощью кнопки Да. Проверка занимает некоторое время.

Также проверку можно произвести из ее карточки. Подробнее см. раздел Правила проверки учета.

Работа с выявленными проблемами

В приложении предусмотрен просмотр выявленных проблем ведения учета и способов их устранения в отчете Контроль ведения учета. Подробнее см. раздел Отчет Контроль ведения учета.

Выявленные при проверке проблемы выводятся адресно только тем категориям исполнителей, которые могут в них разобраться. Например, если это операция закрытия месяца, то проверку и исправление проблем должен проводить бухгалтер, компетентный в вопросах закрытия месяца, если это проверка на наличие «битых» ссылок или тестирование/исправление, то такую проверку должен проводить администратор приложения и т. д.

Ответственный за участок учета:

■ либо переходит к сводному отчету с текущими проблемами из списка Текущие дела (подробнее см. раздел Переход к просмотру проблем из списка Текущие дела);

■ либо из окна «проблемного» объекта открывает отчет по проблемам этого объекта (подробнее см. раздел Просмотр проблем от объектов приложения);

■ затем из отчета переходит к решению (исправлению) проблемы, подробнее см. раздел Отчет Контроль ведения учета.

Также может дополнительно:

■ отобрать информацию в отчете по конкретной проблеме.

В том случае, если в приложении нет списка Текущие дела, предусмотрена возможность сообщать при каждом запуске о выявленных проблемах ведения учета с помощью всплывающего уведомления, из которого можно перейти к просмотру проблем. Перейти к работе с отчетом также можно из списка проверок с помощью кнопки Отчеты. Выберите из выпадающего списка команду Результаты проверки учета.

Переход к просмотру проблем из списка Текущие дела

В списке Текущие дела проблемы, выявленные в результате проверки, выводятся в виде ссылки и выделяются цветом в зависимости от важности, при этом проставляется количество найденных проблем (проблемы выделяются в отдельные группы, например, Некорректные документы или Проблемы ведения учета). Для просмотра результатов проверки перейдите по ссылке.

В панели Текущие дела на начальной странице выводится персонализированный список проблем. В подсчет количества и список не включаются документы (справочники и другие объекты приложения), за которые явно назначен ответственным другой пользователь.

Просмотр проблем от объектов приложения

Если обнаруженная во время проверки проблема связана с объектом приложения, проблемный объект помечается значком . В окне списка предусмотрена дополнительная колонка со значком  – переход к отчету по двойному нажатию на соответствующей ячейке указанной колонки.

В сообщении о наличии проблем ведения учета в карточке проблемного документа (объекта) выводится дата и время последней проверки. Если в документе выявлена только одна проблема, то сразу выводится ее описание. После сохранения документа оперативно выполняется перепроверка для подтверждения устранения проблемы. Для повышения удобства в списках и карточке объекта картинка индикатора проблемы теперь соответствует самой критичной из найденных проблем.

С помощью ссылки есть проблемы из окна объекта можно перейти к просмотру отчета Контроль ведения учета (подробнее см. раздел Отчет Контроль ведения учета) и подробного описания проблемы.

Просмотр отчета для администратора

Администратор может открыть отчет Контроль ведения учета по ссылке в панели Отчеты администратора раздела Администрирование – Обслуживание – Отчеты и обработки.

Отчет Контроль ведения учета

Отчет Контроль ведения учета предназначен для просмотра и устранения выявленных проблем с документами, регистрами и любыми другими данными в приложении:

■ можно перейти к просмотру и исправлению проблемных объектов;

■ могут быть предусмотрены ссылки для перехода к автоматическому проведению исправлений.

■ предусмотрена возможность Игнорировать выбранную проблему с помощью кнопки . Это не исправляет проблему, данная возможность позволяет на время отложить проблему и вернуться к ней позже, при этом уменьшает объем отчета.

В отчете Контроль ведения учета выводится персонализированный список проблем. В подсчет количества и список не включаются документы (списки и другие объекты приложения), за которые назначен ответственным другой пользователь.

В отчете по умолчанию выводятся:

■ колонка Вид проверки – содержит сведения о проверке и перечень проблемных объектов;

■ итоговая.

Сведения о проверке выделены цветом. В этой части выводятся:

■ наименование проблемы и ее важность (подробнее см. раздел Правила проверки учета);

■ возможные причины;

■ рекомендации по исправлению;

■ решение – в некоторых проверках может быть предусмотрена ссылка, по которой можно перейти к автоматическому исправлению проблемы. Подробнее см. раздел Возможности проверок ведения учета.

Затем следует перечень обнаруженных в ходе этой проверки проблемных объектов приложения, который состоит из колонок:

■ данные о проблемном объекте (например, наименование, номер и дата документа);

■ обнаруженная проблема;

■ дата проведения проверки.

В отчете Контроль ведения учета предусмотрены быстрые отборы по периоду, проверкам и ответственному.

Если указать пользователя в поле Ответственный (флажок отбора включится автоматически) проблемы будут выданы только по указанному ответственному. Выявленные проблемы в отчете группируются по ответственным, при этом в специальных колонках по каждому ответственному выводится, сколько проблемных объектов обнаружено. С одним объектом может быть связано несколько проблем, тогда по нему будет несколько строк.

В отчете наглядно видно, в каких объектах приложения не было заполнено поле Ответственный, количество таких объектов выводится в колонку Нет ответственного.

Дважды щелкнув по наименованию объекта в отчете, можно перейти к просмотру объекта, исправить обнаруженные в ходе проверки проблемы, например, в случае с документом Демо: Поступление товаров на скриншоте – заполнить поле Комментарий. Подробнее см. раздел документации Варианты отчетов.

Для того чтобы увидеть проигнорированные проблемы, следует открыть Настройки – расширенный вид, найти отбор по полю Игнорировать проблему, отключить его с помощью флажка (будут показаны все проблемы) или выбрать Значение Да (будут показаны только проигнорированные). Подробнее см. раздел документации Варианты отчетов.

Проверка контактной информации

В приложении проводятся проверки контактной информации с возможностью исправления проблем:

■ Выявление некорректных настроек видов контактной информации. В карточке или документе отсутствуют поля контактной информации, или возникает ситуация, блокирующая работу с ними. – Поиск «битых» видов КИ и исправление их на основании данных первоначального заполнения;

■ Выявление устаревших адресов контактной информации. Устаревание адресов и их переименование – например, переименована улица. Нужно изменить все адреса с этой улицей. Для проверки требуется загрузка истории изменений адресных сведений;

■ Проверка адресов на соответствие адресов ГАР – Массовая проверка адресов на соответствие их Государственному адресному реестру;

■ Корректировка адресов из-за изменений в ГАР – исправление адресов, содержащих устаревший тип здания Литер (тип строения «Литер» был переименован в «Литера»).

Провести проверки можно по расписанию или вручную. Подробнее см. разделы Правила проверки учета и Выполнение проверок вручную.

Также можно Проверить все адреса по ссылке сразу после загрузки адресного классификатора.

После выполнения проверок выводится отчет. Также можно перейти к нему по команде Отчеты из списка проверок. Подробнее см. раздел Отчет Контроль ведения учета.

Если были выявлены проблемы, исправить их можно с помощью кнопки Выполнить исправление. Приложение выводит сообщение. Для подтверждения нажмите кнопку Исправить адреса.

Предусмотрена возможность автоматической проверки и исправления адресов с помощью регламентного задания. Регламентное задание 1 раз в неделю проверяет и исправляет адреса, ставшие устаревшими. Для этого при настройке адреса необходимо включить флажок Автоматически исправлять устаревшие адреса. Подробнее см. раздел документации Контактная информация.
