# BSP Documentation

`BSP Documentation` — плагин Codex для разработки на 1С. Он объединяет MCP с версионной документацией БСП, компактную навигационную карту программного интерфейса и демо-конфигурацию EDT с примерами использования.

## Возможности

Для задачи разработки на 1С Codex может:

1. определить версию БСП целевого проекта;
2. найти подходящую подсистему и группу API;
3. найти и прочитать официальную документацию метода;
4. получить каталог соответствующей демо-конфигурации;
5. изучить реальные вызовы BSL, callbacks, клиент-серверный поток и код форм.

Официальная документация БСП является нормативным источником. Демо-конфигурация — практический пример реализации.

## Локальная установка

Требования: Codex с поддержкой plugins, Python 3.11 или новее и доступ к сети при первом старте MCP. При первом старте создаётся личное виртуальное окружение и в него устанавливается bundled Python MCP.

```powershell
git clone https://github.com/VVi3ard/BSP_Documentation.git
codex plugin marketplace add "<путь-к-клону>"
```

Включите **BSP Documentation** в Codex и начните новую задачу. Имя bundled MCP-сервера — `bsp_documentation`.

Для семантического `search_bsp` задайте `OPENROUTER_API_KEY` в окружении. Навигация и получение каталога демо ключа не требуют.

## Обычный сценарий

1. Используйте skill `bsp-development` для задачи BSL.
2. Вызовите `detect_bsp_version` для проекта.
3. Вызовите `discover_bsp_api_sections` с формулировкой задачи.
4. Вызовите `get_bsp_api_section_map` для выбранной подсистемы.
5. Вызовите `search_bsp` с `mode="development"`, `subsystem` и `api_group`.
6. Прочитайте выбранный метод через `get_bsp_section`.
7. Вызовите `get_bsp_demo_location`, затем найдите полное имя метода в полученном каталоге.
8. Прочитайте содержащую вызов процедуру и её прямые UI/callback-зависимости.

Подробности: [сценарий разработки](docs/development-workflow.md) и [архитектура](docs/architecture.md).
