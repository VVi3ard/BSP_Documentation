# Примеры работы и benchmark BSP Documentation

Пять задач сформулированы как прикладные требования без прямого указания подсистемы или метода БСП. Ответы проверены по программному интерфейсу БСП 3.1 и реализации в демо-конфигурации 3.1.11.115.

## 1. Загрузка большого файла с отображением прогресса

### Задача

Нужно обеспечить загрузку файла размером до 100 МБ, содержащего до 1 000 000 строк. Во время загрузки пользователь должен видеть, что обработка продолжается, а после завершения — получить информацию о результате.

### Ответ

Для загрузки такого объёма следует использовать механизм длительных операций БСП. Файл сначала передаётся на сервер и сохраняется во временном хранилище. Серверная процедура запускается через `ДлительныеОперации.ВыполнитьПроцедуру`, а клиент подключается к ней с помощью `ДлительныеОперацииКлиент.ОжидатьЗавершение`. `ВыполнитьПроцедуру` запускает фоновое задание только если это возможно; метод нельзя использовать там, где фоновый запуск должен быть гарантирован безусловно.

Во время обработки серверная процедура периодически вызывает `ДлительныеОперации.СообщитьПрогресс(Процент, Текст)`. Для стандартной формы ожидания устанавливается `ПараметрыОжидания.ВыводитьПрогрессВыполнения = Истина`. После завершения обработчик проверяет статусы `Выполнено`, `Ошибка` и `Отменено`; при ошибке пользователю передаётся `ИнформацияОбОшибке`.

БСП не решает автоматически проблему миллиона строк: файл необходимо читать и обрабатывать порциями, не загружая целиком в память. Прогресс нельзя использовать для передачи промежуточного результата. Документация рекомендует сообщать его не более 100 раз; обновления чаще одного раза в три секунды объединяются.

В демо эта схема используется при загрузке адресного классификатора: файлы размещаются во временном каталоге, обработка выполняется в фоне, а форма получает прогресс и результат отдельными оповещениями.

### Комментарий к результату

**Оценка: 9/10.** Первое совпадение вело в специализированную «Загрузку данных из файла», но ранжирование правильно выбрало длительные операции. Ответ явно отделяет возможности БСП от проектирования потокового чтения.

## 2. Присоединённые файлы контрагента и копирование карточки

### Задача

В карточке контрагента должна быть возможность прикладывать сканы договоров и другие документы. Прикреплённые файлы должны быть доступны всем пользователям, имеющим доступ к контрагенту. При создании нового контрагента копированием необходимо переносить его файлы.

### Ответ

Справочник `Контрагенты` следует подключить к подсистеме «Работа с файлами» как владельца присоединённых файлов. В форме вызывается `РаботаСФайлами.ПриСозданииНаСервере`, и БСП добавляет элементы управления файлами.

Для переноса вложений при интерактивном копировании нужно получить `РаботаСФайлами.НастройкиРаботыСФайламиВФорме()`, установить `КопироватьПрисоединенныеФайлы = Истина` и передать структуру третьим параметром в `ПриСозданииНаСервере`. Само интерактивное копирование завершается вызовом `РаботаСФайлами.ПриЗаписиНаСервере` из одноимённого обработчика формы. Для программного сценария существует `СкопироватьПрисоединенныеФайлы(Источник, Получатель)`; оба объекта должны быть одного типа.

Доступ определяется не только этими методами. Необходимо настроить владельца, справочник присоединённых файлов, роли и ограничения доступа. Нельзя считать наследование прав от контрагента обеспеченным одним API формы.

В демо полный сценарий копирования показан в `_ДемоНоменклатура` и `_ДемоПроекты`.

### Комментарий к результату

**Оценка: 8/10.** Слова о доступе сначала увели discovery в «Управление доступом», а «Работа с файлами» не попала в top-5. После смыслового уточнения найден правильный механизм. Ответ не выдаёт настройку формы за полное решение разграничения доступа.

## 3. Проверка активных пользователей перед изменением настроек

### Задача

Перед изменением общих настроек системы необходимо проверять, работают ли в базе другие пользователи. Если активные пользователи есть, изменение настроек должно быть отменено, а пользователю показан список открытых сеансов.

### Ответ

На сервере следует вызвать `СоединенияИБ.ИнформацияОСоединениях()`. Метод возвращает признаки `НаличиеАктивныхСоединений`, `НаличиеCOMСоединений`, `НаличиеСоединенияКонфигуратором` и `ЕстьАктивныеПользователи`.

Если обнаружены активные пользователи или другие соединения, изменение отменяется. На клиенте через `СтандартныеПодсистемыКлиент.ОткрытьСписокАктивныхПользователей()` открывается штатный список активных пользователей. Это не обязательно буквальный перечень всех технических сеансов и соединений; для такого перечня потребуется отдельный сценарий администрирования кластера.

Между проверкой и изменением может появиться новый сеанс. Если это недопустимо, одной проверки недостаточно: нужно запретить новые соединения через `СоединенияИБ.УстановитьБлокировкуСоединений`, повторно проверить или завершить уже существующие сеансы, выполнить изменение и гарантированно снять блокировку. Сама установка блокировки не завершает активные сеансы.

В демо тот же сценарий используется при установке обновлений: форма получает информацию о соединениях, показывает предупреждение и открывает стандартный список пользователей.

### Комментарий к результату

**Оценка: 9/10.** Найдены простой API проверки и готовая форма списка. Ответ дополнительно выявляет гонку между проверкой и изменением и не представляет предварительную проверку как строгую гарантию монопольности.

## 4. Дополнительные характеристики без обновления конфигурации

### Задача

Пользователям должна быть предоставлена возможность самостоятельно добавлять дополнительные характеристики контрагентов и номенклатуры. Новые характеристики должны отображаться в карточках объектов без выпуска новой версии конфигурации.

### Ответ

Для задачи предназначена подсистема «Свойства» — дополнительные реквизиты и сведения. В форме вызывается `УправлениеСвойствами.ПриСозданииНаСервере`; место размещения можно указать через `ИмяЭлементаДляРазмещения`. При чтении используется `ПриЧтенииНаСервере`, а перед записью — `ПередЗаписьюНаСервере`, чтобы перенести значения формы в объект.

Если набор характеристик зависит от вида номенклатуры, подключается соответствующий набор свойств и элементы формы обновляются после изменения вида. Переопределяемый интерфейс нужен только для нестандартного выбора или нескольких наборов.

До использования API формы объекты должны быть подключены к подсистеме в метаданных, а пользователям назначены права на настройку дополнительных реквизитов.

В демо стандартная последовательность представлена в `_ДемоНоменклатура` и `_ДемоКонтрагенты`.

### Комментарий к результату

**Оценка: 8/10.** Правильная подсистема оказалась четвёртой в discovery, но карта и поиск внутри неё сработали точно. Ответ корректно разделяет стандартный сценарий формы, наборы по видам и первоначальное подключение метаданных.

## 5. Обновление связанных открытых форм

### Задача

После изменения ответственного в документе актуальные сведения должны автоматически отображаться во всех открытых формах, связанных с этим документом. Пользователь не должен закрывать или обновлять формы вручную.

### Ответ

После успешной записи на клиенте следует вызвать `ОбщегоНазначенияКлиент.ОповеститьОбИзмененииОбъекта(СсылкаДокумента, ДополнительныеПараметры)`. БСП оповестит открытые формы и динамические списки об изменении ссылки.

Формы, непосредственно отображающие документ, смогут отреагировать стандартно. Если зависимость косвенная, в `ОбработкаОповещения` формы нужно проверить источник или маркер изменения ответственного и перечитать только необходимые данные.

Если изменено несколько объектов или записей регистров, используется `ОповеститьОбИзмененииОбъектов` с конкретным массивом источников. Оповещение всего типа без необходимости может вызвать лишнее обновление большого числа форм и списков.

Механизм работает в текущем клиентском приложении. Он не обновляет формы других пользователей и не заменяет межсеансовое серверное оповещение. В демо вызов расположен в `ПослеЗаписи` формы учётной записи электронной почты.

### Комментарий к результату

**Оценка: 8/10.** Навигация по исходной формулировке промахнулась, но глобальный поиск сразу нашёл группу «Формы» и правильный API. Ответ адекватен, если под открытыми формами понимаются формы текущего клиента; ограничение явно зафиксировано.
