# Экспорт HTML из ИТС через `exporter.py`

Документ описывает, как повторно выгрузить документацию ИТС в локальное HTML-дерево с помощью модуля [exporter.py](</D:/Documents/Настройка ИИ/bsp-docs-mcp/src/bsp_docs_mcp/exporter.py>).

Скрипт не использует LLM и не строит индекс. Его задача:

- взять уже сохраненный HTML;
- очистить страницы от служебного мусора;
- сохранить структуру разделов в файловой системе;
- переписать внутренние ссылки на локальные HTML-файлы.

## Что умеет модуль

В модуле есть два сценария экспорта.

`export_chapter_tree(source_html, output_dir)`

- Используется для одного большого HTML-файла, где несколько глав находятся в одном документе.
- Доступен через CLI-команду `export-html`.
- Разрезает документ по `h1` и пишет каждую главу в отдельный каталог.

`export_crawl_manifest(manifest_path, output_dir)`

- Используется для полной выгрузки ИТС, когда страницы уже скачаны по отдельности.
- Берет `manifest.json` и каталог с сырыми HTML-файлами.
- Восстанавливает иерархию по блокам `.index a[href]` из исходных страниц.
- Это основной режим для BSP 3.1.11 и аналогичных выгрузок с ИТС.
- Через CLI пока не опубликован, вызывается из Python.

## Ожидаемая структура входных данных

Для полной выгрузки ИТС нужен каталог такого вида:

```text
.tmp\bsp3111-crawl\
  manifest.json
  pages\
    0001.html
    0002.html
    ...
```

Этот каталог теперь формируется скриптом [crawl_its.py](/C:/Users/volos/.codex/mcp/bsp-docs-mcp/crawl_its.py). Подробности — в [docs/crawler.md](/C:/Users/volos/.codex/mcp/bsp-docs-mcp/docs/crawler.md).

`manifest.json` должен содержать словарь `pages`, где для каждой страницы есть минимум:

- `status: "ok"`
- `title`
- `file`
- при наличии `parent` используется как запасной родитель, если страница не попала в `.index`

Пути в `file` задаются относительно каталога, где лежит `manifest.json`.

## Что чистится при экспорте

При обработке HTML модуль делает следующее:

- удаляет `script`;
- удаляет форму из секции `Фильтр подсистем`, чтобы она не засоряла результат;
- материализует нумерацию в таблицах, где в первой колонке был пустой `<ol class="n"><li></li></ol>`;
- переписывает ссылки между страницами в относительные локальные пути;
- оставляет внешние ссылки абсолютными;
- добавляет простой HTML-каркас, `meta charset="utf-8"` и базовые стили;
- пишет файлы в UTF-8.

Сырые скачанные файлы модуль не удаляет и не должен использоваться как инструмент очистки исходного crawl-каталога.

## Как запустить простой экспорт из одного HTML

Этот режим полезен для старого формата, где документация уже собрана в один файл.

Из корня репозитория:

```powershell
.\.venv\Scripts\python.exe -m bsp_docs_mcp export-html `
  --html ".\data\sources\3.1.11.155\Документация.html" `
  --output ".\data\sources\3.1.11.155-exported"
```

Результат:

- в каталоге назначения появятся папки по заголовкам `h1`;
- внутри каждой папки будет `index.html`.

## Как запустить полную выгрузку ИТС из `manifest.json`

Это режим, который использовался для BSP `3.1.11`.

Из корня репозитория:

```powershell
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe -c @'
from pathlib import Path
from bsp_docs_mcp.exporter import export_crawl_manifest

manifest = Path(r".tmp\bsp3111-crawl\manifest.json")
output = Path(r"data\sources\3.1.11")
result = export_crawl_manifest(manifest, output)
print(f"Exported {result['pages']} pages into {output}")
'@
```

Если нужна другая версия, меняются только:

- путь к `manifest.json`;
- каталог назначения `data\sources\<версия>`.

## Как формируется иерархия каталогов

Логика такая:

1. Корневые разделы берутся по известным заголовкам глав и приложений.
2. Для каждой страницы ищутся дочерние ссылки в `.index a[href]`.
3. Страница с дочерними узлами становится каталогом с `index.html`.
4. Листовая страница сохраняется как отдельный `.html` файл внутри родительского каталога.
5. Если страница не нашлась через `.index`, но в `manifest.json` есть `parent`, она прикрепляется к этому родителю.
6. Если и это невозможно, страница попадает в `Дополнительные материалы`.

Для BSP 3.1.11 это дает структуру вида:

```text
data\sources\3.1.11\
  Глава 4. Программный интерфейс\
    Адресный классификатор\
      Интерфейс\
        index.html
        АдресныйКлассификаторЗагружен.html
```

## Ограничения и практические замечания

- Модуль рассчитан на шаблонную структуру страниц ИТС BSP. Если верстка ИТС изменится, сначала проверьте `.index` и правила нормализации ссылок.
- Полный экспорт из `manifest.json` сейчас не вынесен в CLI. Для повторных запусков используется Python-вызов функции.
- Пути ограничиваются по длине, а при конфликте имен добавляется короткий хеш. Это сделано для Windows.
- Нормализация ссылок завязана на URL вида `/db/bsp3111doc/content/src/...` и `/db/content/bsp3111doc/src/...`.
- Файлы читаются как UTF-8 / UTF-8-SIG. Если в исходном crawl снова появятся `Р` / `С` вместо кириллицы, сначала проверьте кодировку сохраненных HTML.

## Минимальная проверка после экспорта

После очередной выгрузки имеет смысл проверить:

```powershell
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe -m pytest -q tests\test_exporter.py
```

И вручную:

- открыть `data\sources\<версия>\index.html`;
- убедиться, что корневые главы на месте;
- проверить одну-две страницы из главы 4;
- убедиться, что в HTML нет текста `Фильтр подсистем`;
- проверить, что в таблицах колонка `№` содержит последовательные числа.

## Когда править сам `exporter.py`

Модуль нужно менять, если:

- ИТС изменил HTML-шаблон;
- изменились корневые разделы документации;
- появились новые URL-префиксы source-страниц;
- нарушилась иерархия каталогов;
- перестали корректно переписываться внутренние ссылки.

Перед изменениями ориентируйтесь на тесты в [test_exporter.py](</D:/Documents/Настройка ИИ/bsp-docs-mcp/tests/test_exporter.py>).
