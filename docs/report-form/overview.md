# Общая форма отчета БСП: как устроена и где в нее встраиваться

Исследование для БСП 3.1.11 (АСПУ использует 3.1.11.155, демо — 3.1.11.115; API совпадает).
Назначение документа — полная картина для разработчика и сильной модели. Прямые инструкции для
типовых задач — в [recipes.md](recipes.md).

## 1. Главная идея

Все отчеты на СКД открываются в одной общей форме `ОбщаяФорма.ФормаОтчета` (в АСПУ задана в свойствах
конфигурации как `defaultReportForm`). Форму менять нельзя: она общая и библиотечная. Поведение конкретного
отчета меняют в трех местах:

1. **Модуль объекта отчета** — экспортные процедуры-обработчики, которые форма и механизм формирования
   вызывают, если отчет «подписался» на событие в `ОпределитьНастройкиФормы`. Плюс два платформенных
   события объекта: `ПриКомпоновкеРезультата` и `ОбработкаПроверкиЗаполнения`.
2. **Общий модуль `ОтчетыПереопределяемый`** (сервер) — те же серверные события, но для всех отчетов сразу.
3. **Общий модуль `ОтчетыКлиентПереопределяемый`** (клиент) — клиентские события формы: расшифровка,
   выбор в табличном документе, команды, после формирования. **Отдельного клиентского модуля у отчета нет**:
   клиентская логика всех отчетов проходит через этот общий модуль, внутри нужно ветвиться по имени отчета
   (`ФормаОтчета.НастройкиОтчета.ПолноеИмя`).

## 2. Подключение отчета к интеграции с формой

Без этого шага ни одно событие из модуля объекта (кроме платформенных) вызвано не будет.

### 2.1. Флаг `ОпределитьНастройкиФормы`

Форма получает настройки отчета через `ВариантыОтчетов.НастройкиФормыОтчета` → `НастройкиОтчета`
(`CommonModules/ВариантыОтчетов/Module.bsl:6087`). Для отчета конфигурации процедура
`ОпределитьНастройкиФормы` модуля объекта вызывается **только если отчет есть в кэше
`ОтчетыСНастройками`**, иначе возвращаются настройки по умолчанию **[код]**:

```bsl
ОтчетыСНастройками = ВариантыОтчетовПовтИсп.Параметры().ОтчетыСНастройками;
Если ОтчетыСНастройками.Найти(ОтчетСсылка) = Неопределено
	И (ОтчетОбъект = Неопределено Или Метаданные.Отчеты.Содержит(ОтчетОбъект.Метаданные())) Тогда
	Возврат НастройкиОтчета; // по умолчанию, ОпределитьНастройкиФормы не вызывается
КонецЕсли;
```

Кэш заполняется из описаний отчетов, у которых `ОпределитьНастройкиФормы = Истина`
(`ВариантыОтчетов/Module.bsl:3925`, `СформироватьТаблицуФункциональныхОпций`) **[код]**. Флаг ставится
при регистрации отчета, обычно так (демо, документация глава 3) **[код][док]**:

```bsl
// ВариантыОтчетовПереопределяемый.НастроитьВариантыОтчетов
ВариантыОтчетов.НастроитьОтчетВМодулеМенеджера(Настройки, Метаданные.Отчеты.ИмяОтчета);

// Модуль менеджера отчета
Процедура НастроитьВариантыОтчета(Настройки, НастройкиОтчета) Экспорт
	НастройкиОтчета.ОпределитьНастройкиФормы = Истина;
КонецПроцедуры
```

Альтернативы: `ВариантыОтчетов.ОписаниеОтчета(Настройки, Метаданные.Отчеты.X).ОпределитьНастройкиФормы = Истина`
прямо в переопределяемом модуле; для отчетов из подсистемы `ПодключаемыеОтчетыИОбработки` —
`ПриОпределенииНастроек(НастройкиПрограммногоИнтерфейса)` в модуле менеджера (`ВариантыОтчетов/Module.bsl:2294`).
Внешние (дополнительные) отчеты этой проверки не проходят — у них флаг задается в `СведенияОВнешнейОбработке`.

**Отчет из расширения.** Документация: настройки отчетов расширений задаются через подсистему
`ПодключаемыеОтчетыИОбработки` — отчет включают в ее состав, а в модуле менеджера объявляют
`ПриОпределенииНастроек` с `ОпределитьНастройкиФормы = Истина` **[док]**. Второй путь — `&После` на
`ВариантыОтчетовПереопределяемый.НастроитьВариантыОтчетов` с `ВариантыОтчетов.ОписаниеОтчета(...)`
(статьи 2746819, 2656467). Кэш отчетов расширений хранится отдельно (`ПараметрРаботыРасширения`, привязан к
`ПараметрыСеанса.ВерсияРасширений`, `ВариантыОтчетовПовтИсп/Module.bsl:345`) **[код]**: после изменения
расширения нужен перезапуск сеанса.

**Ловушки регистрации:**

- `НастроитьВариантыОтчета` в модуле менеджера — **два параметра** `(Настройки, НастройкиОтчета)`. Вызов
  идет из `ВариантыОтчетов.НастроитьОтчетВМодулеМенеджера` в `Попытка`; при ошибке (в том числе неверной
  сигнатуре) — только запись в журнал «Недопустимое значение параметра КлючВарианта в процедуре
  ВариантыОтчетов.НастроитьОтчетВМодулеМенеджера», настройки не применяются (`ВариантыОтчетов/Module.bsl:155`)
  **[код]**. В ERP/УТ есть прикладные отчеты с одним параметром — их вызывает свой модуль конфигурации,
  копировать их шаблон нельзя (статья 2746819).
- Отчет в кэше, а процедуры `ОпределитьНастройкиФормы` нет или она падает — исключение «Отчет … подключен к
  подсистеме "Варианты отчетов", но при получении настроек возникла следующая ошибка (возможно процедура
  ОпределитьНастройкиФормы не указана разработчиком отчета или не обновлен кэш вариантов отчетов)»
  (`ВариантыОтчетов/Module.bsl:6110`) **[код]**. Такой текст означает: регистрация прошла, ошибка в модуле объекта.
- У **внешнего** отчета та же ошибка подавляется молча: подставляются настройки по умолчанию, в журнал
  ничего не пишется **[код]**. Симптом — события не вызываются без сообщений. Там же: платформа кэширует
  внешние отчеты, при отладке помогает смена имени файла отчета (статья 2112355, комментарии).
- Во внешних отчетах безопаснее `Настройки.События.Вставить("ИмяСобытия", Истина)`: если ключ удалят в
  новой версии БСП, прямое присваивание упадет (статья 2112355, комментарии).

**Кэш.** Список живет в параметрах работы программы (`ВариантыОтчетовПовтИсп.Параметры`, строка 333).
После включения флага он пересчитается при обновлении ИБ. Документация (глава 3, «Обновление вспомогательных
данных во время разработки») предлагает при разработке: обработку `ОбновлениеВспомогательныхДанных.epf` из
дистрибутива БСП, параметр запуска `ЗапуститьОбновлениеИнформационнойБазы` или увеличение номера версии
конфигурации **[док]**. Симптом забытого обновления: процедура `ОпределитьНастройкиФормы` написана, но не
вызывается, события отчета «молчат».

**Состояние в АСПУ.** `ВариантыОтчетовПереопределяемый.НастроитьВариантыОтчетов` пустая
(`CommonModules/ВариантыОтчетовПереопределяемый/Module.bsl`). Прикладные отчеты АСПУ интеграцию с формой
не используют; `ОпределитьНастройкиФормы` есть только у отчетов БСП. Первый отчет, которому понадобятся
события, потребует и регистрации в этом модуле.

### 2.2. `ОпределитьНастройкиФормы` и подписка на события

```bsl
Процедура ОпределитьНастройкиФормы(Форма, КлючВарианта, Настройки) Экспорт
	Настройки.События.ПриСозданииНаСервере = Истина;
	Настройки.События.ПередЗагрузкойНастроекВКомпоновщик = Истина;
	// ...
КонецПроцедуры
```

- Параметр `Форма` здесь **всегда `Неопределено`**: процедура вызывается из `НастройкиОтчета` с
  `ОтчетОбъект.ОпределитьНастройкиФормы(Неопределено, КлючВарианта, НастройкиОтчета)` **[код]**. Трогать форму
  в ней нельзя.
- Вызывается и в форме, и в фоновом задании формирования (через `ПодключитьОтчетИЗагрузитьНастройки`), и в
  рассылке — флаги событий действуют везде.
- Полный состав `Настройки` — `ОтчетыКлиентСервер.НастройкиОтчетаПоУмолчанию()`: `ФормироватьСразу`,
  `ВыводитьСуммуВыделенныхЯчеек`, `РазрешеноИзменятьСтруктуру`, `РазрешеноИзменятьВарианты`,
  `РазрешеноВыбиратьИНастраиватьВариантыБезСохранения`, `ПараметрыРасположенияЭлементовУправления`,
  `ЗагрузитьНастройкиПриИзмененииПараметров`, `ПоляПоиска`, `ВариантПредставленияПериода`, `ВариантПериода`,
  `ОтключитьСтандартноеКонтекстноеМеню`, `СкрытьКомандыРассылки`, `Печать`, `События` **[док]**; в коде 3.1.11
  есть еще `РазрешеноЗагружатьСхему`, `РазрешеноРедактироватьСхему`, `РазрешеноВосстанавливатьСтандартнуюСхему`
  и событие `ПриОпределенииСвойствЭлементовФормыНастроек` (`ОтчетыКлиентСервер/Module.bsl:232–290`) **[код]**.
- `РазрешеноВыбиратьВарианты` в эту структуру не входит: форма вычисляет его сама по правам пользователя
  (`ФормаОтчета/Module.bsl:4399–4412`) **[код]**.

## 3. Жизненный цикл: где что вызывается

### 3.1. Открытие формы (сервер формы)

`ФормаОтчета.ПриСозданииНаСервере` (`CommonForms/ФормаОтчета/Module.bsl:33`):

1. Получает `ОтчетОбъект = РеквизитФормыВЗначение("Отчет")`, настройки отчета (`НастройкиОтчета`).
2. Заполняет списки `ПостоянныеРеквизиты` и `ПостоянныеКоманды` тем, что есть на этот момент. В 3.1.11
   `ПостоянныеКоманды` в `ФормаОтчета` только пополняется и читается в `Подключаемый_Команда` как таблица
   «команда → обработчик `Модуль.Процедура`»; цикла удаления «непостоянных» команд в этой форме нет
   (использования — стр. 92, 1261, 4774) **[код]**. Поэтому `ОтчетыСервер.ВывестиКоманду` нужна ради
   диспетчеризации обработчика, а не ради «защиты от удаления», как сказано в ее описании (статья 2746819).
3. В конце: `ОтчетыПереопределяемый.ПриСозданииНаСервере` (стр. 146), затем, если подписан,
   `ОтчетОбъект.ПриСозданииНаСервере(ЭтотОбъект, Отказ, СтандартнаяОбработка)` (стр. 148) **[код]**.

Далее платформа загружает вариант: `ПередЗагрузкойВариантаНаСервере` (стр. 287) →
`ПриЗагрузкеВариантаНаСервере` (стр. 335) → пользовательские настройки (стр. 386, 398) → перестроение панели
быстрых настроек.

### 3.2. Перестроение панели быстрых настроек (сервер формы)

`ОбновитьЭлементыФормыНастроекНаСервере` (стр. 4430) → `ЗагрузитьНастройкиВКомпоновщик` (стр. 4459) →
`ОтчетыСервер.ОбновитьЭлементыФормыНастроек` (`ОтчетыСервер/Module.bsl:500`). Порядок событий **[код]**:

1. `ПередЗаполнениемПанелиБыстрыхНастроек(Форма, ПараметрыЗагрузки)`;
2. `ПередЗагрузкойНастроекВКомпоновщик(ЭтотОбъект-форма, КлючСхемы, КлючВарианта, НовыеНастройкиКД, НовыеПользовательскиеНастройкиКД)` — можно менять загружаемые настройки;
3. загрузка в `Отчет.КомпоновщикНастроек`;
4. `ПослеЗагрузкиНастроекВКомпоновщик(Новый Структура)`;
5. **удаление всех дочерних элементов** группы `КомпоновщикНастроекПользовательскиеНастройки` и группы
   `Дополнительно` (`ПодготовитьФормуКПерегруппировкеЭлементов`, `ОтчетыСервер/Module.bsl:1593`), создание их
   заново из пользовательских настроек;
6. `ПослеЗаполненияПанелиБыстрыхНастроек(Форма, ПараметрыОбновления)`.

Перестроение происходит при открытии, смене варианта, «Настройки по умолчанию», после расширенной настройки,
при изменении параметров из `ЗагрузитьНастройкиПриИзмененииПараметров`, после формирования, если вариант
был модифицирован. Свои элементы, положенные внутрь панели быстрых настроек, живут до следующего
перестроения.

Уточнения к шагам **[код]**:

- Шаг 2 в форме выполняется, только если есть **новые** настройки: `ДоступныеНастройки.Настройки <> Неопределено`
  (стр. 4493). Новые настройки берутся из `ПараметрыЗагрузки` или из XML, который `ПередЗагрузкойВариантаНаСервере`
  сохраняет при загрузке варианта (стр. 320–332, `ОтчетыСервер.ДоступныеНастройки`, стр. 553). При простом
  изменении значения в быстрой настройке событие в форме **не** вызывается; в фоне при формировании — вызывается
  всегда. Отсюда жалобы «не отрабатывает» (статья 2112355, комментарии).
- Перед шагом 5 строится таблица свойств элементов (`ОтчетыСервер.СвойстваЭлементовФормыНастроек`, стр. 362);
  если отчет подписан на `ПриОпределенииСвойствЭлементовФормыНастроек(ТипФормы, СвойстваЭлементов, ПользовательскиеНастройки)`,
  в нем можно задать группу, ширину, растягивание и положение заголовка каждого поля **до** построения
  (стр. 441). Образец — `УниверсальныйОтчет` (группа «ФиксированныеПараметры» по горизонтали). При подписке
  БСП отключает свое автоматическое распределение полей по колонкам (стр. 1778).

### 3.3. Формирование (клиент → сервер формы → фоновое задание)

Кнопка «Сформировать» → клиентская `СформироватьОтчет` (стр. 1443) → серверная
`РезультатФормированияОтчета` (стр. 1617):

1. `ПроверитьЗаполнение()` формы (стр. 1624). Платформа вызывает `ОбработкаПроверкиЗаполненияНаСервере`
   формы и **`ОбработкаПроверкиЗаполнения` модуля объекта отчета** (основной реквизит `Отчет`). Если
   `Отказ` — формирование не запускается, сообщения видны пользователю. Так проверяют параметры отчеты БСП
   `ПроверкаЦелостностиТома`, `АнализЖурналаРегистрации` **[код]**.
2. Если подписан `ПередФормированиемОтчета` (стр. 1641) — обработчик может вернуть `ТекстПредупреждения`;
   клиент покажет вопрос «Продолжить / Отмена» (с опцией «больше не спрашивать») **[код]**. Это мягкое
   предупреждение, не запрет.
3. `ПараметрыФормированияОтчета` (стр. 1671) собирает **только** настройки компоновщика формы
   (`Настройки`, `ФиксированныеНастройки`, `ПользовательскиеНастройки`), ключ варианта, схему. **Реквизиты
   формы в фон не передаются.**
4. `ДлительныеОперации.ВыполнитьВФоне("ВариантыОтчетов.СформироватьОтчетВФоне", ...)`.

В фоне — `ВариантыОтчетов.СформироватьОтчет` (`ВариантыОтчетов/Module.bsl:1685`):

1. `ПодключитьОтчетИЗагрузитьНастройки` (стр. 1057): создает **новый** объект отчета, вызывает
   `ОпределитьНастройкиФормы`, `ПередЗагрузкойНастроекВКомпоновщик(Контекст=структура, ...)` (стр. 1214),
   загружает настройки, `ПослеЗагрузкиНастроекВКомпоновщик` (стр. 1230) **[код]**;
2. при `ПроверятьЗаполнение = Истина` — `ОтчетОбъект.ПроверитьЗаполнение()` (стр. 1730). Из формы передается
   `Ложь` (форма проверила сама), из рассылки и снимков — `Истина`;
3. `ОтчетОбъект.СкомпоноватьРезультат(ТабличныйДокумент, Расшифровка)` (стр. 1782) → платформенное событие
   **`ПриКомпоновкеРезультата(ДокументРезультат, ДанныеРасшифровки, СтандартнаяОбработка)`**;
4. исключение → текст ошибки уходит в форму и показывается в области отчета.

Обратно на сервере формы — `ЗагрузитьРезультатФормированияОтчета` (стр. 1732): табличный документ в
`ОтчетТабличныйДокумент`, данные расшифровки во временное хранилище `ОтчетДанныеРасшифровки`.

На клиенте — `ПослеФормирования` формы (стр. 1559) → `ОтчетыКлиентПереопределяемый.ПослеФормирования(ФормаОтчета, ОтчетСформирован)` (стр. 1603) → `ОбработчикПослеФормированияНаКлиенте`, если его задали через
`ОтчетыКлиент.СформироватьОтчет(ФормаОтчета, Обработчик)`.

Рассылка (`РассылкаОтчетов/Module.bsl:2038`) и снимки отчетов (`РегистрыСведений.СнимкиОтчетов`) вызывают
тот же `ВариантыОтчетов.СформироватьОтчет` без формы **[код]**. Всё, что сделано в фоне (`ПриКомпоновкеРезультата`,
`ОбработкаПроверкиЗаполнения`, события загрузки настроек), работает и там; всё, что сделано на клиенте или
в событиях формы, — нет.

## 5. Ловушки

### 5.1. Модуль объекта в событиях формы — временная копия

Форма вызывает обработчики на `ОтчетОбъект = РеквизитФормыВЗначение("Отчет")` и **не записывает объект
обратно** (`ЗначениеВРеквизитФормы` нет) **[код]**: стр. 41, 319, 371, 404, 1640, 4469, 4515. Следствия:

- менять надо **параметры обработчика** (`Форма.Отчет.КомпоновщикНастроек`, `НовыеНастройкиКД`,
  `НовыеПользовательскиеНастройкиКД`), а не `ЭтотОбъект.КомпоновщикНастроек`;
- `ЭтотОбъект.КомпоновщикНастроек` в событиях формы годится для **чтения** текущего состояния;
- исключения, которые форма сама считывает обратно: после `ПослеЗагрузкиНастроекВКомпоновщик` форма передает
  копию в `ОтчетыСервер.УстановитьДоступныеЗначения` (там берутся `ДоступныеЗначения` параметров) и читает
  `ДополнительныеСвойства.ВариантНаименование`;
- `ОтчетыСервер.ПодключитьСхему(ЭтотОбъект, Контекст, Схема, КлючСхемы)`, вызванная из события формы, сама
  записывает объект обратно в форму: `ЗначениеВДанныеФормы(Отчет, Контекст.Отчет)` (`ОтчетыСервер/Module.bsl:90`)
  и ставит `НастройкиОтчета.СхемаМодифицирована = Истина`, поэтому подмененная схема уходит и в фон **[код]**.

Статьи, где значения меняют через `ЭтотОбъект.КомпоновщикНастроек` в `ПередЗаполнениемПанелиБыстрыхНастроек`
(1647373, БСП 3.1.5), в 3.1.11 по коду работать не должны: там загружаются настройки из `ПараметрыЗагрузки`,
а не из копии объекта **[не проверено запуском]**.

В фоне всё наоборот: `ПередЗагрузкойНастроекВКомпоновщик`, `ПослеЗагрузкиНастроекВКомпоновщик` и
`ПриКомпоновкеРезультата` работают на **том самом** объекте, который компонует результат.

### 5.2. Реквизиты формы не доходят до формирования

В фон уходит только компоновщик. Значение, которое должно влиять на результат, должно жить в настройках
компоновки: параметр СКД в пользовательских настройках или дополнительное свойство
`ПользовательскиеНастройки.ДополнительныеСвойства`. Реквизит формы, добавленный программно, при
формировании не виден, в вариант не сохраняется, в рассылку не попадает.

Передать в фон произвольные данные (например, таблицу, которую пользователь правил на форме) можно через
`Отчет.КомпоновщикНастроек.ПользовательскиеНастройки.ДополнительныеСвойства` — БСП сама кладет туда
`ВариантМодифицирован` перед запуском фона и читает в фоне (`ФормаОтчета/Module.bsl:1674`,
`ВариантыОтчетов/Module.bsl`, «Регистрация результата») **[код]**. Значения должны сериализоваться.
Адрес временного хранилища, помещенный без идентификатора формы, в фоне может оказаться пустым (статья
1740930, комментарии) — помещать с `УникальныйИдентификатор` формы.

### 5.2а. Двойник в пользовательских настройках

Если параметр или отбор выведен в пользовательские настройки (есть `ИдентификаторПользовательскойНастройки`),
его значение берется из `ПользовательскиеНастройки`, а правка в `Настройки` будет перекрыта. Значение по
умолчанию или программная установка — через элемент пользовательских настроек:

```bsl
Параметр = НовыеНастройкиКД.ПараметрыДанных.НайтиЗначениеПараметра(Новый ПараметрКомпоновкиДанных("Склад"));
Если Параметр <> Неопределено И НовыеПользовательскиеНастройкиКД <> Неопределено Тогда
	Двойник = НовыеПользовательскиеНастройкиКД.Элементы.Найти(Параметр.ИдентификаторПользовательскойНастройки);
	Если Двойник <> Неопределено Тогда
		Двойник.Значение = ОсновнойСклад;
		Двойник.Использование = Истина;
	КонецЕсли;
КонецЕсли;
```

Место — `ПередЗагрузкойНастроекВКомпоновщик` (статья 2112355 и комментарии автора; тот же прием в демо
`ПраваРолей.ВключитьПараметр`). Для отбора — то же с `Отбор.Элементы` и `ПравоеЗначение`. Функции поиска
двойника в БСП нет; `КомпоновкаДанныхКлиентСервер.*` из статей — модули ERP/УТ, см. раздел 10.

Отбор, переданный параметром формы `Отбор`, ставится в режиме «Недоступный»
(`ОтчетыСервер.УстановитьФиксированныеОтборы`) — пользователь его не изменит. Если значение нужно только
по умолчанию, с возможностью правки, — ставить его через двойник, а не через `Отбор` (статья 2056824, комментарии).

### 5.3. Динамические элементы и обработчики событий

- Всё внутри `КомпоновщикНастроекПользовательскиеНастройки` и `Дополнительно` удаляется при каждом
  перестроении (п. 3.2). Свои элементы в панели быстрых настроек создают в `ПослеЗаполненияПанелиБыстрыхНастроек`
  при каждом вызове.
- Элементы в других группах (например, отдельная группа внутри `ПанельБыстрыхНастроек` рядом с
  `КомпоновщикНастроекПользовательскиеНастройки`) перестроение переживают **[код, по составу удаляемых
  узлов]**.
- Обработчик события элемента (`УстановитьДействие("ПриИзменении", ...)`) может ссылаться только на
  процедуру **модуля формы**. У общей формы нет процедуры для чужих полей: `Подключаемый_ЭлементНастройки_ПриИзменении`
  (стр. 541) ищет элемент пользовательских настроек по имени поля и на чужом поле упадет. Поэтому у
  программно добавленного поля ввода своего `ПриИзменении` быть не может.
- Для команд это решено: `ОтчетыСервер.ВывестиКоманду` (`ОтчетыСервер/Module.bsl:146`) ставит
  `Действие = "Подключаемый_Команда"` и регистрирует команду; при нажатии вызывается либо
  `ОтчетыКлиентПереопределяемый.ОбработчикКоманды`, либо процедура `"ИмяКлиентскогоМодуля.ИмяПроцедуры"`,
  если так было задано `Действие` до вызова `ВывестиКоманду` (стр. 1253) **[код]**.

**Вывод:** элемент управления, влияющий на отчет, правильно делать **параметром СКД в быстрых
пользовательских настройках** — форму для него БСП построит сама (булев параметр → флажок, `НайтиЗначенияКакФлажки`,
`ОтчетыСервер/Module.bsl:1987`; параметр с доступными значениями → поле со списком выбора), значение сохранится
в варианте и дойдет до фона и рассылки.

### 5.4. Контекст `ПередЗагрузкойНастроекВКомпоновщик`

Первый параметр `Контекст` — форма (вызов из формы) **или структура** (вызов из фона,
`ВариантыОтчетов/Module.bsl:1214`). Код не должен предполагать, что это форма. Оба аргумента настроек могут
быть `Неопределено`.

### 5.5. Прочее

- `ОпределитьНастройкиФормы` без регистрации флага не вызывается (п. 2.1) — самая частая причина «ничего не
  работает».
- `ОтчетыКлиентПереопределяемый` общий для всех отчетов: всегда ветвиться по
  `ФормаОтчета.НастройкиОтчета.ПолноеИмя` и сразу выходить для чужих отчетов.
- В `ПриКомпоновкеРезультата` использовать `ЭтотОбъект.СхемаКомпоновкиДанных`, а не `ПолучитьМакет(...)`:
  пользователь мог изменить схему, БСП подставляет ее в объект (`ПодключитьОтчетИЗагрузитьНастройки`).
- При своей компоновке передавать `ДанныеРасшифровки` в компоновщик макета и процессор, иначе пропадут
  расшифровка и контекстное меню БСП.
- Флаг «отчет пустой» для рассылки («не отправлять пустой»): БСП смотрит
  `ПользовательскиеНастройки.ДополнительныеСвойства.ОтчетПустой`, иначе считает сама (`ВариантыОтчетов/Module.bsl`,
  конец `СформироватьОтчет`). Демо при своей компоновке ставит его через `ОтчетыСервер.ОтчетПустой(ЭтотОбъект, ПроцессорКД)`.
- `КомпоновщикНастроек.ПолучитьНастройки()` падает, если фиксированные настройки пересекаются с
  пользовательскими по параметрам или отборам — типично для контекстных отчетов (статья 2746819)
  **[не проверено]**.
- Проверка «наш ли отчет» в общих модулях — по `Форма.НастройкиОтчета.ПолноеИмя`. Сравнение
  `ТипЗнч(Форма.Отчет) = Тип("ОтчетОбъект.X")` всегда ложно: основной реквизит в форме — `ДанныеФормыСтруктура`
  (статья 2746819). `РеквизитФормыВЗначение("Отчет")` работает, но создает объект на каждой форме.
- Изменения `КомпоновщикНастроек` в фоне уходят обратно в форму, только если в
  `ПользовательскиеНастройки.ДополнительныеСвойства` выставлено `ВариантМодифицирован` /
  `ПользовательскиеНастройкиМодифицированы` (`СформироватьОтчет`, блок «Регистрация результата») **[код]**.
  По умолчанию правки в фоне действуют только на этот прогон — обычно это и нужно.

## 6. Разбор задач

### 6.1. Свой элемент на форме

Варианты по убыванию предпочтительности:

1. **Параметр СКД + быстрая пользовательская настройка.** Никакого кода формы. Булево → флажок; ссылочный тип
   или тип с `ДоступнымиЗначениями` → поле выбора. Список значений — в схеме или программно в
   `ПослеЗагрузкиНастроекВКомпоновщик` через `Настройки.ПараметрыДанных.ДоступныеПараметры.НайтиПараметр(...).ДоступныеЗначения`
   (демо `ПраваРолей.НастроитьПараметрУровеньДоступа`) **[код]**. Параметр можно не использовать в запросе —
   он нужен только как носитель значения.
   - **Ограничение формы выбора без кода** — в схеме СКД: колонка «Параметры редактирования» у параметра
     или поля набора → «Связи параметров выбора» (отбор по значению другого параметра/отбора, например
     характеристики по номенклатуре) и «Параметры выбора» (фиксированный отбор, например `Отбор.ЭтоГруппа = Ложь`)
     (статья 2364022). Иерархия и поиск по коду при этом сохраняются — в отличие от списка
     `ДоступныеЗначения`, который превращает выбор в плоский список.
   - **`ПриОпределенииПараметровВыбора`** (устаревшее, но рабочее): после обработчика БСП читает только
     `СвойстваНастройки.ЗначенияДляВыбора` и `ЗапросЗначенийВыбора` (результат первой колонки добавляется в
     список, список сортируется по представлению) и записывает их в `ДоступныеЗначения` поля
     (`ОтчетыСервер.УстановитьДоступныеЗначенияНастроек`, стр. 3790–3830) **[код]**. Флаги
     `ОграничиватьВыборУказаннымиЗначениями`, `БыстрыйВыбор` в этой ветке не читаются; `УПОРЯДОЧИТЬ ПО` в
     запросе не действует. `ЗапросЗначенийВыбора` — объект `Запрос`, задавать `.Текст`, а не присваивать строку
     (ошибка в статье 2364022). Сначала вызывается общий `ОтчетыПереопределяемый`, потом обработчик отчета.
     Вызов — на каждую настройку при каждом перестроении панели.
   - **Отбор-флажок по булеву полю без «Да/Нет»**: заполнить колонку «Представление» у элемента отбора в
     настройках варианта — поле значения не выводится (платформа; по комментариям, не работает при
     разработке на 8.5) (статья 2625318). Альтернатива — скрыть поле значения в
     `ПослеЗаполненияПанелиБыстрыхНастроек`.
   - **Раскладка полей шапки** — `ПриОпределенииСвойствЭлементовФормыНастроек` (п. 3.2): группа, ширина,
     положение заголовка до построения панели, без ручного перемещения элементов.
2. **Команда** (кнопка) — `ПриСозданииНаСервере` + `ОтчетыСервер.ВывестиКоманду` + обработчик в
   `ОтчетыКлиентПереопределяемый.ОбработчикКоманды` (демо `РезультатыПроверкиУчета`, `ОтчетыПереопределяемый` демо) **[код]**.
3. **Декорация, надпись, группа** в панели — в `ПослеЗаполненияПанелиБыстрыхНастроек`, пересоздавать на
   каждом вызове; свойства уже построенных элементов (ширина, заголовок, видимость) меняют там же.
4. **Произвольное поле ввода с реквизитом формы** — технически возможно (`ИзменитьРеквизиты` +
   `Элементы.Добавить` в `ПриСозданииНаСервере`, в группе, которую не перестраивают), но без своего
   `ПриИзменении`, без сохранения в варианте и без передачи в фон. Перенести значение в компоновщик можно в
   `ПередФормированиемОтчета` (получает форму, сервер) — **[не проверено]**, не рекомендуется.
   Статья 2206654 решает это правкой модуля самой `ФормаОтчета` (универсальные `Подключаемый_ДобавленыйЭлемент_*`
   с `Выполнить(...)`) — это изменение библиотечной формы, в АСПУ неприемлемо.

### 6.2. Изменить настройки перед формированием (флажок «В разрезе признака удержания»)

СКД не умеет «включить поле в группировку по значению параметра». Два способа:

**А. `ПриКомпоновкеРезультата` со своей компоновкой** (демо `ДвиженияДокумента`, `РезультатыПроверкиУчета`,
`_ДемоДинамикаИзмененийФайлов`) **[код]**:

```bsl
СтандартнаяОбработка = Ложь;
Настройки = КомпоновщикНастроек.ПолучитьНастройки(); // вариант + пользовательские, копия
// прочитать параметр, поправить Настройки.Структура / Выбор
// КомпоновщикМакета → ПроцессорКомпоновки → ПроцессорВывода в ДокументРезультат
```

Плюсы: одно место, работает в форме, рассылке и снимках, правка действует только на этот прогон,
вариант пользователя не меняется. Минус: ~10 строк стандартной компоновки.

**Б. `ПередЗагрузкойНастроекВКомпоновщик`** (демо `РезультатыПроверкиУчета.СкрытьГруппировкуПоОтветственным`:
булев параметр `ВыводитьОтветственного` включает поле группировки и состояние группировки колонок) **[код]**.
Читает значение из `НовыеПользовательскиеНастройкиКД` по `ИдентификаторПользовательскойНастройки` параметра и
меняет `НовыеНастройкиКД`. Работает и в форме (структура в настройках сразу отражает флажок), и в фоне.
Чтобы форма перестраивалась сразу при переключении флажка, параметр добавляют в
`Настройки.ЗагрузитьНастройкиПриИзмененииПараметров` в `ОпределитьНастройкиФормы` **[код, стр. 557]**.
Минус: правка попадает в настройки варианта, их видит и может сохранить пользователь; сложнее код.

Для простых случаев — способ А.

**Про АСПУ.** В `ОтчетОбОстаткахВРазрезеСтратегийИРезервов` режим разбивки сейчас сделан двумя детальными
группировками `СРазбивкой` / `БезРазбивки` с флажками использования в быстрых настройках (D-0023 спецификации
ASP-209959). Один флажок вместо двух группировок — это способ А или Б над одной группировкой. Построитель
СКД сам удалит `ПризнакУдержания` из запроса, если поле не выбрано (см. архитектуру отчета).

### 6.3. Запрет формирования по условию (период 1 день при выводе лицевого счета)

Точка — **`ОбработкаПроверкиЗаполнения(Отказ, ПроверяемыеРеквизиты)` модуля объекта** (платформенное
событие, не экспортное) **[код]**:

- в форме вызывается из `ПроверитьЗаполнение()` до запуска фона (стр. 1624) и перед переформированием
  после изменения настроек (стр. 4437); сообщение + отмена — ровно запрошенное поведение;
- в рассылке и снимках вызывается из `ВариантыОтчетов.СформироватьОтчет` (стр. 1730), текст сообщений
  попадает в ошибку рассылки;
- внутри: `Настройки = КомпоновщикНастроек.ПолучитьНастройки()` — итоговые настройки с учетом
  пользовательских (так делают демо-отчеты);
- ошибка: `ОбщегоНазначения.СообщитьПользователю(Текст,,,, Отказ)`.

Альтернативы: `ПередФормированиемОтчета` — только вопрос с «Продолжить», не запрет;
`ВызватьИсключение` в `ПриКомпоновкеРезультата` — работает, но ошибка появится после запуска фона и
показывается в области отчета как ошибка формирования.

Проверка «поле выбрано для вывода» — обход `Настройки.Выбор` и `Настройки.Структура` (группировки, таблицы,
диаграммы) с учетом `Использование`. «Установлен отбор по полю» — обход `Настройки.Отбор` (и отборов
группировок) с `Использование = Истина`. Готовые функции — в рецептах.

**Про АСПУ.** В отчете о резервах лицевой счет не выводится (требования: «Отчет не выводит лицевые счета»),
а отбор сделан отдельным полем `ОтборЛицевойСчет` (D-0025). Сценарий применим к отчетам, где счет —
поле вывода; в проверке отбора надо указывать то поле, по которому реально отбирают.

### 6.4. Обработка табличного документа после вывода

| Место | Контекст | Рассылка, снимки | Когда выбирать |
|---|---|---|---|
| `ПриКомпоновкеРезультата` после `ПроцессорВывода.Вывести` | фон, сервер | да | почти всегда |
| `ОтчетыКлиентПереопределяемый.ПослеФормирования` → `ФормаОтчета.ОтчетТабличныйДокумент` | клиент | нет | только визуальное, только в форме |

Серверный вариант — демо `РезультатыПроверкиУчета.ДоопределитьГотовыйМакет` (правит шапку, итоги,
проставляет гиперссылки), `_ДемоДинамикаИзмененийФайлов` (дописывает гиперссылку
`ОтчетыСервер.ВывестиГиперссылку`) **[код]**. Объект — `ДокументРезультат` (`ТабличныйДокумент`): области,
`ВысотаТаблицы`/`ШиринаТаблицы`, `Область(...)`, `НайтиТекст`, `Вывести`, `ВставитьОбласть`.

**[не проверено]** Вставка строк выше таблицы результата может сбить соответствие областей и данных
расшифровки/заголовков, по которым работает контекстное меню БСП (`СвойстваРезультата.Заголовки`).
Безопаснее менять значения и оформление ячеек и дописывать в конец.

### 6.5. Перехват расшифровки и другой отчет

Образец БСП — `УправлениеДоступомСлужебныйКлиент.ПриОбработкеРасшифровкиОтчета` (отчет `АнализПравДоступа`
открывает `Отчет.ПраваРолей` с отбором из расшифровки) **[код, демо]**:

1. клиент, `ОтчетыКлиентПереопределяемый.ОбработкаРасшифровки(ФормаОтчета, Элемент, Расшифровка, СтандартнаяОбработка)`;
   `Расшифровка` — индекс `ИдентификаторРасшифровкиКомпоновкиДанных`;
2. фильтр по `ФормаОтчета.НастройкиОтчета.ПолноеИмя`, `СтандартнаяОбработка = Ложь`;
3. серверный вызов с `ФормаОтчета.ОтчетДанныеРасшифровки` (адрес) и индексом:
   `ДанныеРасшифровки.Элементы[Расшифровка]` → `ПолучитьПоля()` (поле ячейки) и `ПолучитьРодителей()`
   (значения группировок выше); в `ДанныеРасшифровки.Настройки` — настройки, по которым сформирован отчет
   (период и прочие параметры);
4. `ОткрытьФорму("Отчет.Другой.Форма", Параметры, ФормаОтчета)`, где `Параметры`:
   `КлючВарианта`, `СформироватьПриОткрытии = Истина`, `Отбор` (структура), `КлючНазначенияИспользования`.
   Несколько действий — меню `ФормаОтчета.ПоказатьВыборИзМеню(...)`.

Как `Отбор` применяется в открываемом отчете — `ОтчетыСервер.УстановитьФиксированныеОтборы`
(`ОтчетыСервер/Module.bsl:954`) **[код]**: ключ, совпадающий с именем **параметра данных**, устанавливает
параметр (`Использование = Истина`, режим «Недоступный»); иначе создается элемент отбора «Равно»
(`СписокЗначений` / `Массив` → «В списке»; значение-структура `{ВидСравнения, ПравоеЗначение}` задает вид
сравнения). Применяется при загрузке варианта, если открыт начальный вариант (`ВариантыОтчетов.ДопустимоУстановитьКонтекст`).
Ключ структуры не может содержать точку — только поля верхнего уровня.

**Про «в то же окно».** Стандартная расшифровка БСП тоже открывает **новую форму того же отчета**:
`ВариантыОтчетовСлужебныйКлиент.ОткрытьФормуОтчета` (стр. 3253) делает
`ОткрытьФорму(НастройкиОтчета.ПолноеИмя + ".Форма", Параметры, Форма, Форма.УникальныйИдентификатор)` с
параметром `Расшифровка` **[код]**. Окно при этом не передается. Открыть **другой** отчет «внутри» текущей
формы нельзя: форма привязана к объекту своего отчета (реквизит `Отчет`, схема, варианты). Приближения:

- передать `ФормаОтчета.Окно` пятым параметром `ОткрытьФорму` (Окно) — форма откроется в том же окне
  приложения **[не проверено: поведение зависит от режима интерфейса]**;
- если нужен **тот же** отчет с другими настройками — поменять `ФормаОтчета.Отчет.КомпоновщикНастроек` на
  клиенте и вызвать `ОтчетыКлиент.СформироватьОтчет(ФормаОтчета)` (публичный API, `ОтчетыКлиент/Module.bsl:20`);
- подменить `ОтчетТабличныйДокумент` результатом чужого отчета — ломает расшифровку, контекстное меню,
  сохранение и переформирование. Не делать.

**Другая схема в стандартной форме расшифровки** (статья 2656467, УТ 11.5). Ближе всего к типовому поведению:
открывается штатная форма расшифровки того же отчета, но формируется по другому макету СКД.

1. В схеме исходного отчета у поля — макет поля, в параметр `Расшифровка` которого добавлены служебные
   строковые поля (что открыть, какое поле нажато) и нужные значения.
2. `ОбработкаРасшифровки`: собрать значения из данных расшифровки; если это «наша» ячейка —
   `СтандартнаяОбработка = Ложь` и
   `ОткрытьФорму("Отчет.X.Форма", Новый Структура("Расшифровка, СформироватьПриОткрытии", Новый ОписаниеОбработкиРасшифровкиКомпоновкиДанных(ФормаОтчета.ОтчетДанныеРасшифровки, Расшифровка, НастройкиСДопСвойствами), Истина), ФормаОтчета)`,
   где у `НастройкиСДопСвойствами` (новые `НастройкиКомпоновкиДанных`) в `ДополнительныеСвойства` лежат данные ячейки.
3. В модуле объекта отчета `X`, `ПередЗагрузкойНастроекВКомпоновщик`: если `Контекст` — форма и
   `Контекст.Параметры.Расшифровка.ПрименяемыеНастройки.ДополнительныеСвойства` содержит данные ячейки —
   `ОтчетыСервер.ПодключитьСхему(ЭтотОбъект, Контекст, ДругаяСхема, КлючСхемы)`; затем заполнить параметры
   новой схемы.

По коду 3.1.11 **[код]**: форма в режиме расшифровки загружает `ПрименяемыеНастройки` как фиксированные
(стр. 335 и далее), `ПодключитьСхему` из формы пишет объект обратно и помечает схему модифицированной — фон
получит новую схему. Не раскрыто в статье **[не проверено]**: какие настройки варианта достаются новой схеме
(варианты старой ей не соответствуют — вероятно, брать `ДругаяСхема.НастройкиПоУмолчанию` в `НовыеНастройкиКД`)
и где именно переносятся параметры. `Попытка ... Исключение КонецПопытки` с пустым обработчиком из статьи —
не переносить.

## 7. Дополнительно полезное

- **`ЗагрузитьНастройкиПриИзмененииПараметров`** — массив `ПараметрКомпоновкиДанных`; изменение такого
  параметра в быстрых настройках перестраивает форму (и вызывает `ПередЗагрузкойНастроекВКомпоновщик`).
- **`ОтчетыСервер.ПодключитьСхему`** в `ПередЗагрузкойНастроекВКомпоновщик` — подменить схему целиком
  (общий макет, схема по параметру).
- **`ПередЗагрузкойВариантаНаСервере`** — значения по умолчанию в варианте при открытии, скрытие отборов
  (`РежимОтображения`), добавление `ИдентификаторПользовательскойНастройки`, чтобы вывести настройку в быстрые.
- **`Настройки.ПараметрыРасположенияЭлементовУправления`** — ширина, растягивание полей быстрых настроек.
- **`ОтчетыКлиентПереопределяемый.ПриНачалеВыбораЗначений`** — своя форма подбора значений отбора.
- **`ОтчетыСервер.ВывестиГиперссылку(Ячейка, Адрес, Представление)`** — гиперссылка в результате;
  `e1cib/...` и `http(s)://` форма открывает сама, остальное — в `ОбработкаВыбораТабличногоДокумента`.
- **Контекстный отчет** из формы объекта: `ОткрытьФорму("Отчет.X.Форма", Новый Структура("Отбор, СформироватьПриОткрытии, КлючВарианта", ...))`
  — тот же механизм `Отбор`, что и в расшифровке.
- **Настройки печати** по умолчанию — `Настройки.Печать` в `ОпределитьНастройкиФормы`.
- **`ПередФормированиемОтчета`** — предупредить о долгом формировании с опцией «больше не спрашивать»
  (`ИмяПараметраХраненияОтказаОтПредупреждения` — имя булева параметра в пользовательских настройках).
- **Отборы при открытии из своей команды** — в `ПриСозданииНаСервере` дописать `Форма.ФормаПараметры.Отбор`
  (по имени команды, `Форма.Параметры`); применит `ПриЗагрузкеВариантаНаСервере` через
  `УстановитьФиксированныеОтборы` (статья 2056824) **[код]**.
- **`КлючНазначенияИспользования`** (параметр формы) — отдельный набор сохраненных пользовательских настроек
  для каждого контекста запуска; форма берет его из `Параметры.КлючНазначенияИспользования` или строит из
  контекста варианта (`ФормаОтчета/Module.bsl:4176`) **[код]**.
- **Изменение схемы СКД программно** (добавить набор, связь, вычисляемое поле, ресурс) — в
  `ПередЗагрузкойНастроекВКомпоновщик` с защитой по `КлючСхемы` и `ОтчетыСервер.ПодключитьСхему` (статья 2370783);
  в комментариях к 2112355 для вычисляемых полей и ресурсов советуют `ПередЗагрузкойВариантаНаСервере`.
  Предупреждение авторов: пользовательские варианты с добавленными полями сохраняются плохо; схему менять до
  `ПриЗагрузкеВариантаНаСервере`. Изменение схемы прямо в `ПриКомпоновкеРезультата` (статья 2405937, `СхемаЗапроса`
  + `КомпоновщикНастроек.Инициализировать`) работает, но добавленные поля пользователь не видит в настройках.
- **Внешние данные в компоновку** — в своей компоновке `ПроцессорКомпоновки.Инициализировать(Макет, ВнешниеНаборы, ДанныеРасшифровки, , , МенеджерВременныхТаблиц)`:
  таблица, помещенная запросом в МВТ, доступна набору-запросу по имени (статьи 2405937, 1740930).
- **Результат отчета без формы** (для выгрузки, печати, вставки в другую форму): `Отчеты.X.Создать()`,
  `КомпоновщикНастроек.ЗагрузитьНастройки(вариант)` + `ЗагрузитьПользовательскиеНастройки(...)`,
  отборы — `ОбщегоНазначенияКлиентСервер.УстановитьЭлементОтбора`, затем `СкомпоноватьРезультат(ТабДок)`
  или своя компоновка в `ДеревоЗначений` генератором `ГенераторМакетаКомпоновкиДанныхДляКоллекцииЗначений`
  (статьи 2746819, 2056824-комментарии). `ВариантыОтчетов.СформироватьОтчет` в 3.1.11 — служебный интерфейс
  (область `СлужебныйПрограммныйИнтерфейс`), не опираться.
- **Своя форма у отчета** ломает интеграцию: общие формы подключаются комплектом (основная, настроек,
  варианта); при своей основной форме нужна своя форма настроек или `ВспомогательнаяФормаНастроекОтчета`;
  нетиповые отчеты — `ФорматНастроекСКД = Ложь` (свойство описания отчета) **[док]**. Копия или
  заимствование `ФормаОтчета` ломается при обновлениях (статьи 2112355, 1740930 и комментарии).

## 8. Особенности АСПУ

- Общая форма подключена полностью: `defaultReportForm = CommonForm.ФормаОтчета`, хранилище вариантов —
  `ХранилищеВариантовОтчетов` (`Configuration.mdo`).
- `ОтчетыПереопределяемый`, `ОтчетыКлиентПереопределяемый`, `ВариантыОтчетовПереопределяемый` — пустые
  шаблоны.
- Есть проектные модули `ОтчетыАванкорСервер` / `ОтчетыАванкорКлиент` / `ОтчетыАванкорКлиентСервер` /
  `ОтчетыАванкорВызовСервера`, перенесенные из другого продукта. **Не подключены**: из прикладного кода
  используется только `ОтчетыАванкорВызовСервера.УстановитьПользовательскиеПараметры` (`ПроверкиАСПУКлиент`).
  Полезное в них:
  - `ОтчетыАванкорСервер.ЗначениеГруппировкиРасшифровки(ЭлементРасшифровки, Тип)` — ищет значение нужного
    типа в поле расшифровки и вверх по родителям; `ОтчетыАванкорКлиент.ЗначениеГруппировкиРасшифровки(ФормаОтчета, Расшифровка, Тип)` —
    клиентская обертка;
  - `ОтчетыАванкорКлиентСервер.ЭтоОтчетСИменем`, `ЗначениеПараметра`, `ЭлементОтбора`;
  - `ОтчетыАванкорКлиент.ОбработкаРасшифровки` — конвенция «клиентская логика отчета в его форме
    `ФормаРасшифровки` с экспортным методом `ОбработкаРасшифровки`»; вызывается через `ПолучитьФорму` и глотает
    исключения.
  Подключать ли их к `ОтчетыКлиентПереопределяемый` — решение команды.
- Функций `КомпоновкаДанныхКлиентСервер.ПолучитьПараметр` / `УстановитьПараметр` /
  `ДобавитьПараметрыВПользовательскиеНастройки`, `КомпоновкаДанныхСервер.*` из статей про ERP/УТ в АСПУ нет —
  их нет и в демо БСП, это модули типовых конфигураций. Одноименные модули `КомпоновкаДанных`,
  `КомпоновкаДанныхКлиентСервер` в АСПУ — проектные, с другим содержимым. Экспортный состав
  `ОтчетыСервер`, `ОтчетыКлиент`, `ОтчетыКлиентСервер`, `ВариантыОтчетов`, `ВариантыОтчетовКлиент`,
  `ОбщегоНазначенияКлиентСервер` в АСПУ совпадает с демо БСП. Замены: платформенные
  `ПараметрыДанных.НайтиЗначениеПараметра` / `УстановитьЗначениеПараметра`, БСП
  `ОбщегоНазначенияКлиентСервер.УстановитьЭлементОтбора` / `НайтиЭлементыИГруппыОтбора` / `ИзменитьЭлементыОтбора`.
- Параметр `КонецПериода` в `ОтчетОбОстаткахВРазрезеСтратегийИРезервов` — выражение
  `КонецПериода(&ПериодОтчета.ДатаОкончания, "День")`. При очищенном пользователем периоде это конец дня
  01.01.0001 — отчет молча пуст (ловушка из статьи 2746819). Для этого отчета период обязателен, но стоит
  проверить поведение при пустом периоде.
- Любая доработка отчета в АСПУ начинается со спецификации (`spec-writing`), правки BSL — по правилам проекта.

## 9. Что проверить запуском

1. Вызов `ОбработкаПроверкиЗаполнения` модуля объекта из `ПроверитьЗаполнение()` общей формы — подтвержден
   демо-отчетами, но стоит увидеть сообщение в АСПУ.
2. После включения `ОпределитьНастройкиФормы` — что кэш обновился и события вызываются.
3. Флажок из булева параметра: значение, которое видит фон при снятом `Использование` параметра в варианте
   (рекомендуется включить `Использование` в варианте и читать `Значение`).
4. Открытие отчета из расшифровки с `ФормаОтчета.Окно`.
5. Постобработка табличного документа со вставкой строк — не ломает ли контекстное меню БСП.
6. Расшифровка с подменой схемы (п. 6.5): какие настройки получает новая схема.
7. `ПриОпределенииПараметровВыбора` с `ЗапросЗначенийВыбора`: ограничивает ли форма выбор списком
   (флаг `ОграничиватьВыборУказаннымиЗначениями` в 3.1.11 не читается).
