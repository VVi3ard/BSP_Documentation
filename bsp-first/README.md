# bsp-first: навык и хук «БСП прежде своего кода»

Комплект файлов, который нужно перенести к себе. Задача: чтобы LLM брала готовые методы БСП,
а не писала свои. Навык дает карту «задача → метод БСП». Хук, описанный в спецификации,
подсказывает метод в момент, когда модель пишет велосипед, даже если она навык не открывала.

Основа - статьи «Обзор полезных методов БСП 3.1.4», части
[1](https://infostart.ru/1c/articles/1398340/) и [2](https://infostart.ru/1c/articles/1411756/):
около 400 методов, отсортированных по числу вызовов в УТ, РТ, БП, ЗУП и ERP.
Все методы сверены с БСП 3.1.11.115 (`bsp-demo`).

## Состав

```
bsp-first/
├── README.md                     этот файл
├── sources/                      статьи, очищенные скриптом, текст и код без изменений
├── skill/bsp-first/              НАВЫК - копировать целиком
│   ├── SKILL.md                  карта «задача → метод», около 100 вызовов, все сверены с 3.1.11
│   ├── references/
│   │   ├── catalog.md            около 400 методов, одна строка на метод, для grep
│   │   └── <раздел>.md           49 разделов: текст статей + строка сверки `> 3.1.11:` у каждого метода
│   └── data/
│       ├── bsp-api-index.json    программный интерфейс БСП 3.1.11: 3172 метода, одна запись на строку
│       └── article-methods.json  методы из статей: модуль, параметры, контекст, статус сверки
├── hook/                         ХУК - только описание и данные
│   ├── HOOK-SPEC.md              спецификация для реализации, с замерами на АСПУ
│   └── data/
│       ├── antipatterns.json     25 правил «велосипед → метод БСП/платформы»
│       ├── bsp-deprecated.json   245 устаревших методов БСП с заменой
│       ├── bsp-internal.json     служебный API БСП, не вызывать из прикладного кода
│       └── bsp-objects.txt       объекты БСП, в которых хук молчит (черновик, см. ниже)
└── scripts/                      пересборка всего выше, Python 3.11+
```

## Куда положить

- Навык: `skill/bsp-first` -> `ASPU/.agents/skills/bsp-first` (или в плагин
  `BSP_Documentation`, если навык нужен и в других проектах). Навык дополняет `bsp-development`:
  тот ищет по документации через MCP, когда модель уже знает, что искать; этот дает
  «оглавление», чтобы модель узнала о существовании метода.
- Хук: реализовать по `hook/HOOK-SPEC.md`, данные из `hook/data` положить рядом с ним.
- В `CLAUDE.md`, сценарий «Правка BSL», добавить шаг: перед новой процедурой или функцией
  общего назначения свериться с навыком `bsp-first`.

## Пересборка

Лучше пересобрать индекс из исходников **целевой** конфигурации: тогда он точно совпадет
с версией БСП проекта (3.1.11.155 в АСПУ) и будет содержать только подсистемы, внедренные в
проект. Сейчас он собран по демо 3.1.11.115: в нем есть подсистемы, которых в АСПУ нет.

```powershell
pip install beautifulsoup4 lxml

# 1. Статьи (нужно только при обновлении статей)
python scripts/extract_articles.py sources 1398340 1411756
#    и переименовать в bsp-3.1.4-methods-part1.md / part2.md

# 2. Индекс API: полный (для сверки) и компактный (для навыка)
python scripts/build_bsp_api_index.py <src> api-full.json --full
python scripts/build_bsp_api_index.py <src> skill/bsp-first/data/bsp-api-index.json

# 3. Методы из статей + сверка с версией
python scripts/extract_article_methods.py api-full.json skill/bsp-first/data/article-methods.json sources/bsp-3.1.4-methods-part1.md sources/bsp-3.1.4-methods-part2.md

# 4. references навыка
python scripts/build_references.py skill/bsp-first/data/article-methods.json skill/bsp-first/references sources/bsp-3.1.4-methods-part1.md sources/bsp-3.1.4-methods-part2.md

# 5. Данные хука; третий аргумент - src чистой поставки БСП для bsp-objects.txt
python scripts/antipatterns_source.py hook/data/antipatterns.json
python scripts/build_hook_data.py api-full.json hook/data <src поставки БСП>

# 6. Проверка правил и замер шума на прикладном коде
python scripts/check_antipatterns.py hook/data/antipatterns.json skill/bsp-first/data/bsp-api-index.json <src прикладного кода>
python scripts/similar_names_probe.py skill/bsp-first/data/bsp-api-index.json skill/bsp-first/data/article-methods.json <src прикладного кода> 0.67 --popular
```

`<src>` - каталог `src` выгрузки EDT (с подкаталогом `CommonModules`).

## Что проверено

- Извлечение статей детерминированное, без LLM. Повторный прогон `extract_articles.py`
  дает те же файлы, что в `sources/`.
- 407 методов из статей сверены с 3.1.11: 401 актуален, модуль каждого подтвержден примерами
  из статьи. 5 устарели или исключены из программного интерфейса (замена указана в разделах):
  три метода хранилищ настроек из `ОбщегоНазначенияВызовСервера` теперь вызываются из
  `ОбщегоНазначения` / `ОбщегоНазначенияКлиент`, `ДанныеQRКода` переехал в `ГенерацияШтрихкода`.
  1 метод (`ОтправитьPOSTЗапрос`) не из БСП, а из библиотеки обмена с банками.
- Все 96 вызовов в карте `SKILL.md` и все методы в `suggest` правил хука есть в программном
  интерфейсе 3.1.11 и не устарели (проверка скриптом).
- Правила хука проверены на примерах `bad`/`good` и замерены на 458 прикладных модулях АСПУ
  (таблица в `HOOK-SPEC.md`, раздел 10).

## Ограничения

- Числа вызовов - из статей 2021 года (типовые на БСП 3.1.4). Как мера популярности годятся,
  как точная статистика - нет.
- Примеры кода в `references/` взяты из статей как есть: в них встречаются модули конкретных
  типовых (`ОбщегоНазначенияРТВызовСервера` и т.п.). Сигнатуру брать из строки сверки
  и индекса, пример - как иллюстрацию.
- `bsp-objects.txt` собран по демо-конфигурации: в нем есть объекты-примеры демо без префикса
  `_Демо`. Пересобрать по чистой поставке БСП.
- Проверка D хука (похожие имена) - грубый стемминг «первые 5 букв». Около 4% имен
  существующего кода получают подсказку, часть ложных. Уверенность medium, формулировка «проверь».
