# Установка BSP Documentation MCP для новичка

## Цель

Сделать установку MCP-сервера понятной пользователю Windows и агенту Codex без предположения, что они знакомы с Git, Python, виртуальными окружениями или MCP.

## Поддерживаемая среда

- Windows 10 или Windows 11.
- Codex.
- Python 3.12.
- Учетная запись OpenRouter и API key.
- Установка сервера в `%USERPROFILE%\.codex\mcp\bsp-docs-mcp`.

Другие операционные системы и MCP-клиенты в инструкции не рассматриваются.

## Основной сценарий

README начинается с краткого объяснения назначения сервера и раздела «Быстрая установка». Пользователь скачивает проект с GitHub, открывает PowerShell и запускает `install.ps1`. Скрипт:

1. Проверяет наличие Python 3.12.
2. Копирует файлы сервера в глобальный каталог Codex.
3. Создает `.venv` внутри каталога сервера.
4. Устанавливает рабочие зависимости без зависимостей для разработки.
5. Выводит дальнейшие команды для API key и `config.toml`.

Скрипт не запрашивает, не сохраняет и не выводит API key.

## Ручной сценарий

После быстрой установки README содержит полный резервный сценарий:

1. Скачать ZIP с GitHub или клонировать репозиторий.
2. Открыть PowerShell.
3. Перейти в явно указанный каталог с распакованными файлами.
4. Скопировать сервер в `%USERPROFILE%\.codex\mcp\bsp-docs-mcp`.
5. Перейти в каталог установленного сервера.
6. Создать `.venv` и установить рабочий пакет.
7. Создать пользовательскую переменную `OPENROUTER_API_KEY`.
8. Добавить готовый переносимый блок в `%USERPROFILE%\.codex\config.toml`.
9. Полностью перезапустить Codex и проверить доступность MCP.

Перед каждым блоком команд указывается, где его запускать и что должно произойти.

## Проверка и ошибки

README объясняет, как проверить:

- что Python 3.12 установлен;
- что создан исполняемый файл `.venv\Scripts\python.exe`;
- что переменная `OPENROUTER_API_KEY` доступна новому процессу;
- что конфигурация Codex ссылается на каталог текущего пользователя;
- что готовый индекс найден сервером.

Для распространенных ошибок приводятся короткие причины и конкретные исправления.

## Индекс и модель

README явно указывает:

- готовый индекс БСП 3.1 уже находится в репозитории;
- для обычной установки строить индекс не требуется;
- для поискового запроса используется та же embedding-модель, которой построен индекс;
- смена embedding-модели требует полной переиндексации;
- построение индекса расходует существенно больше токенов, чем отдельный поиск.

## Критерии готовности

- Пользователь может выполнить установку, последовательно копируя команды из README.
- Для каждой команды известен рабочий каталог.
- Реальный API key не записывается в репозиторий или `config.toml`.
- Конфигурация не содержит конкретного имени пользователя Windows.
- Основной сценарий не требует установки зависимостей разработчика.
- Автоматический и ручной сценарии приводят к одинаковой структуре установки.
