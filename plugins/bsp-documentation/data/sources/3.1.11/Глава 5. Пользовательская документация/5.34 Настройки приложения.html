5.34 Настройки приложения

Для эффективной работы приложения ее необходимо правильно настроить. Настройку приложения обычно осуществляют администраторы, у которых включена роль Администратор системы или Полные права.

К настройке параметров приложения можно перейти с помощью команд раздела Администрирование.

Кроме того, внешний вид и поведение приложения также может быть настроено на каждом рабочем месте самим пользователем или с помощью администратора приложения. Персональные настройки приложения открываются по команде Демо: Мои настройки и доступны всем пользователям, у которых установлена роль Демо: Мои настройки. Подробнее см. раздел Персональные настройки.

Обслуживание

В данном разделе администратору предоставляются возможности по поддержанию приложения в работоспособном состоянии: контроль работы приложения, резервное копирование и восстановление, обновление версии, оптимизация быстродействия.

■ Журнал регистрации – с помощью этой ссылки администратор может выяснить, какие события происходили в приложении в определенный момент времени или какие действия и кем выполнялись в приложении. Подробнее см. раздел Журнал регистрации.

■ Активные пользователи – переход к списку пользователей, которые в настоящий момент времени работают в приложении. Подробнее см. раздел документации Завершение работы пользователей.

■ Блокировка работы пользователей – для администратора в приложении предусмотрена возможность завершать работу пользователей и блокировать вход в приложение на определенный период времени. Это бывает необходимо для проведения каких-либо профилактических работ в приложении. Подробнее см. раздел документации Завершение работы пользователей.

■ Удаление помеченных объектов – переход к окончательному удалению тех объектов в приложении, которым была присвоена пометка на удаление. Можно также настроить расписание автоматического удаления помеченных объектов. Подробнее см. раздел документации Удаление помеченных объектов.

Для удобства использования остальные команды сгруппированы в подразделы.

Журнал регистрации

С помощью журнала регистрации администратор приложения может выяснить, какие события происходили в приложении в определенный момент времени или какие действия выполнял тот или иной пользователь. Приложение фиксирует в журнале основные действия, выполняемые по модификации данных, выполнению регламентных операций, подключению и отключению от приложения и т. д.

Для работы с журналом регистрации должна быть установлена роль Полные права. Для перехода в журнал регистрации нужно выбрать ссылку раздела Администрирование – Обслуживание.

При работе со списком Журнал регистрации события выводятся только за сегодняшний день, что ускоряет первое открытие списка, а также позволяет снизить нагрузку на сервера 1С:Предприятие. В дальнейшем этот фильтр можно перенастроить.

При работе с приложением могут возникать события следующих видов, каждый из которых отображается в журнале регистрации специальным значком:

■  Ошибка;

■  Предупреждение;

■  Информация;

■  Примечание.

Каждое событие фиксируется в отдельной строке журнала. В колонке Дата, время помимо даты и времени проставляется значок, отображающий вид события. Для просмотра детальной информации о событии можно воспользоваться двойным щелчком мыши по нужному событию, также можно выделить событие, затем нажать на кнопку Открыть.

Если событие связано с конкретным объектом, то с помощью кнопки  Открыть данные для просмотра можно перейти к просмотру объекта. Открыть данные для просмотра можно также двойным щелчком по содержимому колонки Данные, Комментарий.

В журнале регистрации показаны не все события, а то количество, которое задано в поле Показывать (по умолчанию равно 200). Выберите нужное значение с помощью кнопки .

В поле Критичность можно выбрать для показа события одного вида, например, ошибки.

С помощью кнопки Выгрузить в файл можно сохранить журнал регистрации на компьютер. Укажите путь для сохранения журнала, нажмите кнопку Сохранить. Журнал сохраняется в виде файла XML, просмотреть его можно, например, в приложении MS Excel.

С помощью кнопки Интервал можно управлять периодом показа событий журнала. Также к установке интервалов дат можно перейти с помощью двойного щелчка по содержимому колонки Дата, время. Период можно написать вручную или выбрать из календаря.

С помощью кнопок Установить отбор, Установить отбор по значению в текущей колонке и  Отключить отбор можно управлять отбором событий журнала. Также можно воспользоваться ссылкой, которая принимает значение Не установлен или показывает значение установленного отбора. В журнале производится установка фильтров отбора по периоду, пользователю, событию, наименованию компьютера, номеру соединения, степени важности событий, комментарию.

Можно произвести отбор журнала с помощью флажков по полям:

■ Важность (по умолчанию выбраны все виды событий);

■ Статус транзакции (по умолчанию выбраны все статусы).

Для отбора по остальным полям, например, События, нажмите кнопку  Выбрать, затем выберите из списка с помощью флажков. В событиях со сложными структурами данных наглядно видно их содержимое как в карточке события, так и в самом журнале.

В некоторых полях, например, Идентификатор, необходимо написать вручную значение для поиска.

Информация о событиях представлена в колонках Метаданные, Данные и Представление данных.

В поле Метаданные содержится список метаданных, представленных в приложении. Нужно установить флажки для тех метаданных, по которым требуется произвести отбор, например, по всем согласиям на обработку персональных данных.

В поле Данные выбирается объект приложения, например, какой-то конкретный документ, по которому требуется отобрать все события. Также можно настраивать отбор сразу по нескольким значениям, например, отбор событий по нескольким интересующим ссылкам.

В группе полей Прочее можно выбрать с помощью флажков для отбора Рабочие серверы, Основные IP-порты, Вспомогательные IP-порты, также можно провести отбор по полю Комментарий.

Рабочие серверы ‑ выбираются центральные серверы кластеров (для клиент-серверного варианта работы). Основные IP порты ‑ выбираются IP-порты менеджеров кластера (для клиент-серверного варианта работы). Вспомогательные IP порты ‑ выбираются вспомогательные порты менеджеров кластера (для клиент-серверного варианта работы).

Настройки отбора журнала регистрации можно сохранить. Для этого воспользуйтесь командой Еще – Сохранить настройки в файл. Укажите путь на компьютере. Настройки сохраняются в формате XML. После этого можно будет применить раннее сохраненные настройки. Нажмите на кнопку Загрузить настройки из файла.

Подробнее о работе с журналом регистрации см. в книге «1С:Предприятие 8.3. Руководство администратора».

Особенности работы с журналом регистрации в приложении в Интернете

При работе с приложением через Интернет события в списке Журнал регистрации выводятся только за сегодняшний день, что существенно ускоряет первое открытие списка. Этот фильтр можно перенастроить в дальнейшем.

Отчеты и обработки

В данном подразделе администратору предоставляются возможности по получению отчетов о работе приложения, а также внешних дополнительных отчетов и обработок по администрированию приложения.

С помощью ссылки Отчеты администратора можно перейти к панели отчетов для администрирования приложения. Подробнее см. раздел документации Варианты отчетов.

В панели представлены следующие отчеты:

■ Активность пользователя, Анализ активности пользователей, Контроль журнала регистрации и Продолжительность работы регламентных заданий, Сведения о пользователях и внешних пользователях, Пользователи по подразделениям и т.д. – анализ работы пользователей и приложения на основании сведений из журнала регистрации. Подробнее см. раздел документации Контроль работы пользователей;

■ Анализ прав доступа – показывает текущие настройки прав доступа пользователей к таблицам приложения. Подробнее см. раздел документации Управление доступом;

■ Внешние ресурсы, используемые приложением и дополнительными модулями – интернет-ресурсы, внешние компоненты, COM-классы и т. д. – параметры окружения, которые помогут администратору выполнить настройку компьютера и провести аудит безопасности, подробнее см. раздел документации Профили безопасности.

■ Даты запрета загрузки данных по информационным базам, Даты запрета загрузки данных по разделам и объектам, Даты запрета изменения данных по пользователям, Даты запрета изменения данных по разделам и объектам – отчеты по датам запрета загрузки или изменения данных для разделов с объектами, сгруппированные по пользователям, см. также раздел Даты запрета изменения. Подробнее см. раздел документации Даты запрета изменения;

■ Контроль ведения учета – предназначен для просмотра и устранения выявленных проблем с документами, регистрами и любыми другими данными в приложении. Из отчета можно перейти к просмотру и исправлению проблемных объектов, также в отчете могут быть предусмотрены ссылки для перехода к автоматическому проведению исправлений. В приложении можно настроить правила ведения учета, см. раздел Корректировка данных. Подробнее см. раздел документации Контроль ведения учета.

■ Объем ненужных файлов по владельцам (Первые 10) – отчет позволяет получить информацию об объеме данных, занятых ненужными файлами, см. также раздел Настройки работы с файлами. Подробнее см. раздел документации Работа с файлами;

■ Оценка производительности по ключевым операциям – предоставляет информацию о производительности приложения. Оценка производительности (период в колонках) – предоставляет информацию об оценке производительности в разрезе периодов. Периоды представлены в колонках. Также можно произвести Сравнение оценки производительности за выбранные периоды. Для того чтобы получить отчеты, необходимо произвести настройки, см. раздел Оценка производительности. Подробнее см. раздел документации Оценка производительности;

■ Сведения о пользователях и внешних пользователях – подробные сведения о пользователях приложения (может включать настройки для входа), см. также раздел Настройки пользователей и прав. Подробнее см. раздел документации Пользователи;

■ Прогресс отложенного обновления – отчет позволяет наглядно увидеть, как проходит отложенное обновление информационной базы, см. также раздел Обновление приложения. Подробнее см. раздел документации Обновление версии ИБ;

■ Универсальный отчет – отчет позволяет получить данные по выбранным объектам приложения. Подробнее см. раздел документации Варианты отчетов.

С помощью ссылок Дополнительные отчеты по администрированию и Дополнительные обработки по администрированию можно перейти к вызову дополнительных отчетов и дополнительных обработок, подключенных к разделу Администрирование. Подробнее см. раздел документации Дополнительные отчеты и обработки.

Регламентные операции

В подразделе доступны ссылки по управлению регламентными операциями:

■ Регламентные и фоновые задания – переход к списку регламентных и фоновых заданий. Ряд действий в приложении может выполняться автоматически в фоне, по определенному расписанию. Такие действия называются регламентными заданиями. Подробнее см. раздел документации Регламентные задания;

■ Разблокировать работу с внешними ресурсами – с помощью кнопки можно снять блокировку регламентных заданий по работе с внешними ресурсами. Блокировка автоматически устанавливается, если изменилось местоположение ИБ в связи с копированием или восстановлением из резервной копии (в таких случаях кнопка становится доступной). В этом случае в заголовке приложения автоматически добавляется префикс [КОПИЯ]. После снятия блокировки кнопка становится недоступной. Подробнее см. раздел документации Регламентные задания;

■ Управление итогами и агрегатами – переход к администрированию итогов регистров накопления и бухгалтерии, агрегатов оборотных регистров накопления. Подробнее см. раздел документации Управление итогами и агрегатами.

С целью уменьшения риска потери данных администратору приложения необходимо регулярно выполнять резервное копирование. Частота создания резервных копий зависит от интенсивности ввода новых данных в приложение. Подробнее см. раздел документации Резервное копирование приложения.

В подразделе доступны ссылки:

■ Создание резервной копии – переход к выполнению резервного копирования;

■ Восстановление из резервной копии – переход к восстановлению приложения из резервной копии;

■ Настройка резервного копирования – переход к настройке резервного копирования.

Корректировка данных

В приложении предусмотрены различные возможности поддерживать списки в порядке: изменять данные, отобранные по определенным признакам; устранять повторяющиеся элементы автоматически, при этом приложение также исправляет ссылки на удаленные элементы. Для этого предусмотрены ссылки:

■ Групповое изменение реквизитов – администратору для группового изменения доступны реквизиты всех списков приложения, в том числе табличные части и служебные реквизиты. Подробнее см. раздел документации Групповое изменение объектов;

■ Поиск и удаление дублей – приложение позволяет найти похожие объекты (по умолчанию – с похожим наименованием, условия поиска можно изменить). Для каждой группы похожих объектов приложение предлагает оставить один объект (главный), а все остальные удалить как дубли. Дубли помечаются на удаление, а их ссылки во всех местах использования заменяются ссылкой главного. После успешной замены дубли удаляются окончательно. Подробнее см. раздел документации Поиск и удаление дублей.

■ Правила проверки учета – правила проверки корректности данных. В приложении предусмотрена возможность контролировать корректность данных приложения по произвольным прикладным правилам (ссылочная целостность, циклические ссылки и т. д.). После проверки выявленные проблемы выводятся в списке Текущие дела, администратор может просмотреть отчет Контроль ведения учета, см. раздел Отчеты и обработки. Подробнее см. раздел документации Контроль ведения учета.

Обновление приложения

В подразделе производится установка обновлений приложения или исправлений (патчей), также можно просмотреть информацию о предыдущих обновлениях.

Предусмотрены ссылки:

■ Установка обновлений и исправлений (патчей) – переход к установке обновлений приложения или исправлений (патчей). Подробнее см. раздел документации Обновление приложения;

■ Установленные исправления (патчи) – переход к просмотру списка установленных в приложении исправлений (патчей). Подробнее см. раздел документации Обновление приложения;

■ Описание изменений приложения – переход к просмотру списка нововведений. Также можно просмотреть рекомендации по обновлению к текущей версии приложения. Подробнее см. в разделе документации Обновление версии ИБ;

■ Результаты обновления и дополнительная обработка данных – с помощью этой ссылки можно увидеть сведения о ходе обновления версии приложения, а также запустить отложенное выполнение дополнительных процедур обработки данных. Отложенное обновление позволяет обновление основной части данных произвести в фоне во время работы приложения. Подробнее см. в разделе документации Обновление версии ИБ;

■ В клиент-серверной базе с помощью переключателя Приоритет обработки данных можно установить, что во время отложенной обработки данных важнее: Работа пользователей (замедлится обработка данных) или Обработка данных (ускорить обновление, при этом произойдет существенное замедление работы пользователей). Подробнее см. раздел документации Обновление ИБ.

■ Детализировать ход обновления в журнале регистрации – включите флажок, для того чтобы приложение отражала подробную информацию о процессе обновления в журнале регистрации. Подробнее см. в разделе документации Обновление версии ИБ.

■ Очистка устаревших данных – очистка данных вручную, когда при реструктуризации произошла ошибка «Записи регистра стали неуникальными». По ссылке открывается форма, которая сразу запускает длительную операцию поиска устаревших данных и выводит таблицу с устаревшими данными, которые можно удалить. Подробнее см. в разделе документации Обновление версии ИБ.

Оценка производительности

В приложении предусмотрены встроенные средства для сбора и анализа данных о производительности ее работы по APDEX, которая является международным стандартом оценки производительности информационных систем. Для последующего формирования отчета Оценка производительности по ключевым операциям (см. раздел Отчеты и обработки) в подразделе можно настроить параметры:

Режим использования профилей безопасности

Использование профилей безопасности предоставляется только при наличии версии КОРП клиентских и серверных лицензий для платформы 1С:Предприятие 8.

С помощью переключателя можно выбрать режим использования профилей безопасности для приложения:

■ Профили безопасности не используются для данной информационной базы – приложение не информирует администратора о необходимости добавления внешних ресурсов в профили безопасности. Если настроить использование профилей безопасности в кластере серверов и не изменять данную настройку, попытки обращения к внешним ресурсам, не разрешенным в кластере серверов, будут приводить к проблемам в работе приложения. Если в профиле безопасности выключен флажок Полный доступ к внешним отчетам и обработкам, запуск приложения будет невозможен;

■ Профили безопасности для данной информационной базы настраиваются администратором в консоли кластера – приложение не информирует администратора о необходимости добавления внешних ресурсов в профили безопасности. Администратор настраивает разрешения в профилях безопасности с помощью консоли кластера. При этом он может ознакомиться с перечнем разрешений, которые требуется разрешить в профиле безопасности с помощью отчета, открываемого при переходе по ссылке Требуемые разрешения на данной панели;

■ Предлагать автоматически настраивать разрешения в профилях безопасности при необходимости (непосредственно из приложения) – при переключении в этот режим будет создан новый профиль безопасности (и назначен для приложения), в котором разрешены все внешние ресурсы, требуемые для корректной работы приложения. Управление разрешениями в профилях безопасности выполняется самим приложением. Управление профилями выполняется из самой приложения. Если при редактировании каких-либо настроек приложения возникает необходимость предоставления доступа к новому внешнему ресурсу, администратору отображается диалог с перечнем разрешений. Если администратор согласен, он вводит параметры аутентификации в кластере и нажимает Далее. Разрешения в профилях безопасности предоставляются автоматически.

В зависимости от выбранного режима становятся доступными те или иные возможности:

■ Требуемые разрешения – перейдите по ссылке, для того чтобы вывести отчет о внешних ресурсах, которые должны быть разрешены в профилях безопасности для корректной работы приложения. Ссылка недоступна в случае, если настройка Режим использования профилей безопасности установлена в значение Профили безопасности не используются для данной информационной базы;

■ В поле Профиль безопасности информационной базы введите имя профиля безопасности (в кластере серверов 1С:Предприятия), установленного для ИБ. Поле недоступно для редактирования, если настройка Режим использования профилей безопасности установлена в значение Предлагать автоматически настраивать разрешения в профилях безопасности при необходимости (непосредственно из приложения);

■ Если в профиле безопасности выключен флажок Полный доступ к внешним отчетам и обработкам, требуется включить для него флажок Может использоваться как профиль безопасного режима и указать имя этого профиля безопасности в поле Профиль безопасности информационной базы на данной панели (иначе запуск приложения будет невозможен);

■ Если настройка Режим использования профилей безопасности установлена в значение Профили безопасности для данной информационной базы настраиваются администратором в консоли кластера и в профиле безопасности выключен флажок Полный доступ к внешним отчетам и обработкам, то для профиля безопасности следует включить флажок Может использоваться как профиль безопасного режима и указать имя этого профиля безопасности в поле Профиль безопасности информационной базы (иначе запуск приложения будет невозможен).

Электронная подпись и шифрование

Электронная подпись – реквизит любого электронного документа, с помощью которого можно удостовериться в неизменности электронного документа с момента его подписи.

Перед тем как начать работу с электронной подписью и шифрованием, нужно создать электронный ключ и получить к нему сертификат. Сертификаты бывают юридически значимые (квалифицированные) или обычные. Для создания юридически значимых электронных подписей требуется получить квалифицированный сертификат. Для этого потребуется создать электронный ключ с помощью юридически значимой приложения электронной подписи и шифрования, которая поддерживает ГОСТ Р 34.10-2012, например, КриптоПро CSP. Такое приложение (криптопровайдер) нужно приобрести и установить на компьютеры вместе с приложением 1С:Предприятие. После этого нужно заключить договор с удостоверяющим центром, который имеет право на выпуск квалифицированных сертификатов. Для того чтобы создавать обычные электронные подписи (например, для внутренних задач предприятия), можно использовать любое приложение электронной подписи и шифрования, например, Microsoft Enhanced CSP, которая входит в состав ОС Windows. У каждой приложения свои настройки. В случае организации совместной работы в распределенной информационной базе список используемых приложений и их настройки могут быть изменены только в главном узле. Подробнее см. раздел документации Электронная подпись.

Электронная подпись DSS позволяет подписывать документы из любой точки, не устанавливая на свой компьютер приложений криптографии. Приложения криптографии и сертификаты электронной подписи в данном случае обеспечивает сервис DSS. Нужно лишь зарегистрироваться в подобном сервисе. В приложении осуществляется поддержка разработанного фирмой КриптоПро сервиса криптографии «КриптоПро DSS», который был сертифицирован ФСБ. Подробнее см. раздел документации Электронная подпись сервиса DSS.

В подразделе предусмотрены команды для работы с электронной подписью:

■ Электронная подпись – включите флажок, для того чтобы использовать возможность проверки отсутствия изменений файла с момента его подписи;

■ Шифрование – включите флажок, для того чтобы использовать возможность шифрования файлов для надежного ограничения доступа.

После включения одного из флажков становятся доступными:

■ Сертификаты и приложения электронной подписи и шифрования – переход к настройке сертификатов и приложений, используемых для создания электронных подписей, их проверки, а также для шифрования и расшифровки данных в приложении. Для подписания документов необходимо иметь ключ электронной подписи с действительным сертификатом. Можно создать ключ электронной подписи через 1С:Предприятие, а затем получить на него сертификат в удостоверяющем центре 1С. Для этого в списке Настройки электронной подписи и шифрования нужно добавить Заявление на выпуск нового квалифицированного сертификата. Удостовериться в неизменности электронного документа можно путем проверки электронной подписи. После проверки соответствия электронной подписи и документа проверяется действительность сертификата того ключа, которым была сделана электронная подпись. Если сертификат является квалифицированным, тогда подпись будет иметь юридическую силу, которая указана в заявлении на выпуск сертификата.

■ Проверять подписи и сертификаты на сервере – позволяет не устанавливать приложение криптографии на компьютер пользователя для проверки подписей и сертификатов, в этом случае необходимо установить приложение криптографии только на компьютере, где работает сервер 1С:Предприятия или веб-сервер.

■ Подписывать и шифровать на сервере – позволяет не устанавливать приложение криптографии на компьютер пользователя для подписания, шифрования и расшифровки. В этом случае необходимо установить приложение криптографии и сертификат с закрытым ключом только на компьютере, где работает сервер 1С:Предприятия или веб-сервер.

■ Серверы DSS – обеспечивают работу с криптографией на сервисе DSS;

■ Учетные записи DSS – переход к настройкам авторизации на сервере DSS.

Можно выбрать тип электронной подписи для документов:

■ Подпись с меткой доверенного времени (CAdES-T) – действует после окончания срока действия сертификата подписанта;

■ Архивная подпись (CAdES-A) – содержит полный набор доказательств подлинности, в том числе цепочку сертификатов, и автоматически продлевается.

■ Адреса серверов меток времени – для создания подписей с метками доверенного времени укажите адреса серверов меток времени.

Производительность

В клиент-серверном варианте работы приложения можно ускорить некоторые длительные операции, настроив их выполнение в несколько потоков: например, загрузку адресного классификатора. В клиент-серверном варианте работы приложения при использовании кластера серверов для корректной работы отдельных функций приложения в разделе Администрирование – Общие настройки – Производительность необходимо ввести общий сетевой путь к Каталогу временных файлов. Группы доступа

В подразделе сгруппированы команды управления доступом пользователей:

■ Группы доступа – переход к списку Группы доступа. Группа доступа определяет совокупность действий с данными приложения, которые могут выполнять участники этой группы. Подробнее см. раздел документации Управление доступом;

■ Профили групп доступа – переход к списку Профили групп доступа. Профили групп доступа, как правило, объединяют в себе несколько ролей. При включении пользователя в группу доступа ему назначаются все роли, заданные в профиле группы доступа. Например, предопределенная группа доступа Администраторы связана с профилем Администратор, в состав которого входит роль Полные Права. Эта роль предоставляет неограниченный доступ ко всем данным и назначается всем администраторам приложения, перечисленным в группе доступа Администраторы. Подробнее см. раздел документации Управление доступом.

С помощью выпадающего меню можно выбрать Вариант работы:

■ Производительный – рекомендуется для клиент-серверного приложения, где он значительно эффективнее стандартного варианта. Если выбрать производительный вариант для файловой базы, в которой работает один пользователь или несколько пользователей, но неинтенсивно, то увеличится скорость просмотра списков и формирования отчетов;

■ Стандартный – может потребоваться для файлового приложения, когда производительный вариант ограничивает интенсивность работы нескольких пользователей (параллельное добавление или изменение документов и других данных).

Если выбран производительный вариант работы, становится доступной следующая возможность:

■ Обновление доступа на уровне записей – для отслеживания хода обновления прав доступа. Также для нештатных случаев позволяет обновить доступ отдельных объектов и запланировать обновление доступа к требуемым спискам. Подробнее см. раздел Обновление доступа на уровне записей.

Включите флажок Ограничивать доступ на уровне записей, для того чтобы максимально гибко настраивать права доступа пользователей к спискам, документам и другим данным приложения. Подробнее см. раздел документации Управление доступом. В этом случае становятся доступными следующие возможности:

■ Демо: Группы доступа партнеров – создание групп партнеров для разграничения доступа к спискам, документам и другим данным.

■ Демо: Ограничивать доступ по номенклатуре – включите флажок, для того чтобы разрешить настройку доступа к данным по группам номенклатуры. После этого становится доступной ссылка:

Центр мониторинга

Отчеты об использовании приложения, автоматически переданные разработчикам, помогут им определить, над чем следует поработать в первую очередь. Собранные сведения являются обезличенными и содержат только статистические показатели. Подготовка и отправка отчетов не замедлит работу приложения.

С помощью переключателя выберите:

■ Разрешить автоматическую отправку сведений об использовании приложения в фирму «1С» (выбрано по умолчанию, рекомендуется);

■ Разрешить отправку сведений стороннему разработчику – в этом случае необходимо заполнить Адрес сервиса, например, https://pult1C.ru/pult/v1/packet/;

Каталог временных файлов кластера серверов 1С:Предприятие

Путь к единому сетевому каталогу для общих временных файлов серверов 1С:Предприятие, работающих в одном кластере:

Под управлением ОС Windows – укажите путь к единому каталогу временных файлов всех серверов кластера, который будет использоваться для серверов, работающих под управлением ОС Windows.

Под управлением ОС Linux – укажите путь к единому каталогу временных файлов всех серверов кластера, который будет использоваться для серверов, работающих под управлением ОС Linux.

Каталоги временных файлов можно не заполнять, когда в кластере 1С:Предприятия работает только один сервер или приложение работает в файловом варианте.

Если все сервера кластера работают под управлением операционных систем одного семейства (Windows/Linux), то второе поле заполнять не обязательно.

Каталог должен быть доступен на чтение и запись для всех серверов кластера. В том числе – для всех пользователей операционных систем, от имени которых запускаются сервера 1С:Предприятия.

UNC путь к каталогу должен быть одинаковым для всех серверов одного семейства – для этого каталог необходимо подключать к серверам под одним именем.

В поле Каталог временных файлов Linux можно указать только локальный путь, например, /home/path.

Для того чтобы использовать UNC путь, нужно сделать на него ссылку. Для этого под правами администратора (root) сделайте следующее:

mkdir folder

--- вместо folder напишите имя каталога. Например, в каталоге /home делаем mkdir shared – эта команда создаст каталог shared с полным путем /home/shared.

mount -t cifs //server/share folder -o //domain/user, password=pwd

– где //server/share – UNC путь к другому компьютеру, folder – путь каталога на Linux компьютере, например \home\shared, //domain/user – имя домена/пользователя, если нужно, pwd – пароль пользователя (если нужно).

Если имя и пароль не нужны, команда выглядит так:

mount -t cifs //server/share folder

После этого в пути к каталогу указываем folder, например /home/shared.

Можно выбрать нужный объект приложения из списка, выбрать период, указать другие настройки и сформировать отчет. Подробнее см. раздел документации Варианты отчетов;

■ Состояния оригиналов первичных документов – переход к настройке состояний, которые будут использоваться при отслеживании оригиналов первичных документов.

Можно просмотреть параметры для входа в приложение, сменить пароль (если это разрешено администратором), ввести контактную информацию, просмотреть состав прав доступа (группу доступа и профиль доступа) и вывести отчет по своим правам доступа. Запуск и завершение работы

С помощью флажков можно определить, как будет происходить Запуск и завершение работы:

■ Демо: Предлагать перейти на сайт при запуске – в этом случае после открытия приложения будет выведено сообщение с предложением перейти на сайт приложения для ознакомления с ее документацией. При этом работа приложения блокируется. По умолчанию флажок выключен;

■ Запрашивать подтверждение при завершении приложения – включите флажок, для того чтобы при выходе из приложения требовалось подтверждение (рекомендуется). По умолчанию флажок включен. Запрос подтверждения завершения работы предусмотрен для предотвращения случайного закрытия главного окна приложения при закрытии рабочих окон приложения. Подробнее см. раздел документации Базовая функциональность.

■ Показывать предупреждение об установленных обновлениях приложения – включите флажок, для того чтобы приложение информировала, какие обновления установлены.

Работа в веб-клиенте

При работе в веб-клиенте становится доступным раздел, в котором сгруппированы настройки для этого варианта работы:

■ Напоминать об установке расширения для веб-клиента 1С:Предприятие – если флажок включен, то приложение выводит сообщение (по умолчанию флажок включен, если установка расширения еще не производилась). Не рекомендуется выключать флажок, т. к. без данного расширения работа в веб-клиенте невозможна;

■ Установить сейчас – для повышения удобства работы в веб-клиенте требуется установка и подключение расширения для веб-клиента. Нажмите кнопку, для того чтобы сразу установить это расширение. При работе с файлами через веб-клиент необходимо учитывать особенности, которые связаны с моделью безопасности веб-браузера. Например, по умолчанию такие операции, как получение файлов на клиентский компьютер или передача файлов на сервер, могут работать с ограничениями. Для того чтобы снять эти ограничения, можно установить себе на клиентский компьютер специальное расширение для работы с файлами, которое входит в состав дистрибутива платформы 1С:Предприятие 8.3, воспользовавшись данной кнопкой. После установки расширения флажок и кнопка установки становятся недоступными, выводится информация, что расширение установлено. Подробнее об особенностях работы с файлами через веб-клиент можно узнать из документации по технологической платформе, в книгах «1С:Предприятие 8.3. Руководство пользователя» и «1С:Предприятие 8.3. Руководство администратора». О применении этой настройки см. раздел документации Печать.

■ Настройки работы с почтой (при наличии прав доступа) – переход к персональным настройкам работы с почтой (включение подписи для новых сообщений, включение подписи при ответе или пересылке, настройки уведомлений для отправляемых сообщений, настройки ответов на запрашиваемые уведомления, включение содержания исходного письма при пересылке). Подробнее см. раздел документации Взаимодействия.

Работа с файлами

На вкладке производятся персональные настройки для работы с файлами (подробнее см. раздел документации Работа с файлами):

■ Действие при выборе файла – выберите действие приложения при выборе файла в списке;

■ Запрашивать, как открывать файл: на чтение или для редактирования – включите флажок, для того чтобы приложение предлагала выбрать способ открытия файла при его выборе;

■ Показывать подсказки при редактировании файлов (только веб-клиент) – включить подсказки при редактировании файлов при работе в веб-клиенте;

■ Показывать занятые файлы при завершении работы – включите флажок, для того чтобы при завершении работы приложение предлагала завершить редактирование файлов;

■ Показывать колонку «Размер» в списках файлов – если флажок включен, то в списках файлов в соответствующей колонке будет указан размер файла;

■ Показывать информацию, что файл не был изменен – если флажок включен, то при сохранении версий файла приложение будет сообщать, что в файл не было внесено изменений;

■ Сравнивать версии при помощи – выберите, с помощью какой приложения будут сравниваться версии текстовых файлов;

■ Настройки открытия файлов – в предлагаемой таблице выберите способ открытия для текстовых файлов с указанными расширениями (во встроенном редакторе приложения или стандартным приложением, например, текстовый файл можно открыть с помощью приложения Блокнот Microsoft Windows);

■ Настройка основного рабочего каталога – перейдите по ссылке, для того чтобы указать параметры основного рабочего каталога;

■ Настройка сканирования – переход к настройке параметров сканирования.
